What should I name my widget?

Read Name Your SDK Projects (/pages/viewpage.action?pageId=284697925) to find out your well-known identifier.

The purpose of this document is to demonstrate the Alkami guidelines for widget naming and file structures and layouts. Standardizing our widgets and packages will allow for better deployment, troubleshooting, and coherency. For purposes of this document we will demonstrate with the following widgets.

- One widget will be called SampleDemo for the organization Alkami Technology. The organization uses a well-known identifier Alkami.
- The second widget will be called ToyFair for the organization US Best Financial Institution. The organization uses a well-known identifier USBFI. To distinguish the organization's widget from other offerings, the widget's URL slug will be identified as USBFIToyFair.

Widget names and any derived names do not contain spaces, periods, underscores, or any other separating character. Numbers are permitted after the first letter.

Invalid: 2ndMyAccounts

Valid: MyAccounts2nd

<url slug> when referred to as the widget name is also going to be the root name of the area folder for URL path routing. This will directly influence how widgets are distributed and installed.

```
<well-known identifier>.Client.Widget.<url slug>
```

Examples:

- Alkami.Client.Widget.MyAccountsV2
- Alkami.Admin.Widget.WidgetManagement
- USBFI.Client.Widget.USBFIToyFair

These instructions assume the widget to be installed is a client Client widget package. For Admin area widgets, substitute .Admin. wherever .Client. is referenced. The word .Apps is not included in these examples. .Client.Widgets is the preferred naming strategy.

Do NOT include the word Mobile in the name of your widget. For example, USBFI.Client.Widget.MyMobileSpecialFeature will not work.

Do NOT leave Alkami as the well-known identifier. For example, Alkami.Client.Widget.MyNewWidget will not work. This will fail validation and the submission will be cancelled.

See Microsoft's Choose a unique package identifier and setting the version number (https://learn.microsoft.com/en-us/nuget/create-packages/creating-a-package#choose-a-unique-package-identifier-and-setting-the-version-number)

### Solution organization

Each widget should consist of a solution with several parts. The solution folder should be the base of a repository, that contains the following files:

- <well-known identifier>.Client.Widget.<url slug>.slnThe file name will match the primary assembly root namespace for the widget.ExamplesAlkami.Client.Widget.SampleDemo.slnUSBFI.Client.Widget.USBFIToyFair.slnInvalidAlkami.Apps.SampleDemo.slnUSBFIToyFair.slnThe solution itself will only have one build target of AnyCPU
- The repository folder will also have the following files and folders: (covered in more detail below).git folder.gitignoreREADME.mdAssemblyInfo.csAlkamists will use a sem.ver here in conjunction with their bamboo build job structure.<well-known identifier>.Client.Widget.<url slug>.nuspectools folderchocolateyInstall.ps1chocolateyUninstall.ps1<well-known identifier>.Client.Widget.<url slug> folderExamplesAlkami.Client.Widget.SampleDemoUSBFI.Client.Widget.USBFIToyFair<well-known identifier>.Client.Widget.<url slug>.Tests folderExamplesAlkami.Client.Widget.SampleDemo.TestsUSBFI.Client.Widget.USBFIToyFair.Tests
