Now that you've built out a beautiful, performant, and perfectly coded Vue application, let's talk about how to test it!

As referenced on the Vue project anatomy page, this is what the testing folder structure looks like:

Test Folder Structure

```

│ ├── globalSetup.js # Optional
│ ├── e2e
│ │ ├── modules # End-to-End Test Specs

│ │ │ ├── errorTests.js
│ │ │ └── ...
│ │ ├── plugins # Cypress Plugins
│ │ │ └── index.js # Contains the file and folder configuration referenced by "cypress.json"
```

#### The Breakdown

This is a brief description of the various folders in the folder diagram above. Each type of testing has its own documentation that goes into more detail and walks through various strategies of each.

##### Tests/
##### E2E/modules/

This folder contains the end-to-end test cases for each scenario defined in the specs folders below.

##### E2E/specs/

The location for all top-level scenarios, which set up the environment for their associated test cases and then execute them.

##### E2E/XXX/

Various folders for setting up and supporting Cypress, and the modules and scenarios.

##### Mocks/

This is the folder where all mock data lives to be used in component and utility specific test cases.

##### Unit/

The location of all test files. Jest is configured to look for a folder under "tests" named "unit" to find test files. Additionally, all test files must have ".spec." in the file name to be located for testing.

##### Unit/Components/

Vue component specific test cases. Each of these corresponds to a different component.

##### Unit/XXX/

Various folders to test all other function specific tests. Each of these files corresponds to a separate file in the your project that testing is desirable for.

##### Server/
##### Mocks/

This folder contains all end-to-end all mock responses, useful for mocking service responses when testing with Cypress and "live" components.

##### Mocks/Entities/

This folder contains shared entity definitions that may be used in multiple responses, or across scenarios.
