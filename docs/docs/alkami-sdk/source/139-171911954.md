## Development Phase - FI

These procedures are completed by the Vendor.

- Creating Your Chocolatey package from the Alkami SDK Download
- Installing the Local Build Into choco.dev and Test the Functionality
- Submitting the SDK Package

### Creating Your Chocolatey package from the Alkami SDK Download

The SDK download contains a NuGet Chocolatey package. Create your Chocolatey package and maintain the configuration on this package. Your development will be within your Chocolatey package and after testing successfully, you will upload your package to the Alkami NuGet feed to the private repo assigned to your FI or Company. Only your authorization will permit upload to your assigned feed server.

### Installing the Local Build Into choco.dev and Test the Functionality
- In Visual Studio, open your project and run the install_widget.sql script from the Tools menu in the template for the widget from the SDK downloaded.
- Make all needed changes to the widget. (If needed, see My First Client Widget for additional details on this process.)
- In ProGet, in the Dev feed (myfi.choco.dev), click Add Package (to upload build to choco.dev).
- In the Add Package window, click Upload from Disk and then click Choose File in the Upload from Disk window.
- Navigate to the directory where the build was completed in Visual Studio, select the Nuget package that was generated by the local build, and then click Upload.
- Open the Dev feed and ensure the file reflects the current update.Note: You will see the current Project URL, Last Update date, Package Source, Release Notes, and Tags assigned.
- Copy the Project URL.
### Submitting the SDK Package

After creating local You will then create your SDK Submission Type. This starts an automated process for review and deployment. After testing in the Staging environment, the package will be promoted in Jira to Production.

### Creating Your Choco Package from Nuspec File
- (Standard widget format) Nuspec file contains the metadata of the file to package. Content (Area folder) Lib (Assemblies - like .net assemblies) Src (Source of application) Tools (Chocolatey Install/Uninstall scripts)
- A generic template will be created by the Alkami Visual Studio Project Template. Update metadata with your package/company information.Create unique ID format YourFI.Widget/Microservice.YourName(helloworld).Apply semantic versioning to your version number. Note: Packages are immutable – 1.0.2 cannot be used again. It would be 1.0.3.For any breaking change in the code, apply an increase of 1st octet of version numberFor less impacting changes update the 2nd octet Standard version numbers (for bug fixes) are assigned to 3rd octet Update the Authors, Owners, projecturl, and iconurl for your company.
- Once development and testing of widgets/service is complete, click Add Package to add your package to your private Choco feed to upload.
- Once you have submitted your package copy the URL of your submitted package to point to this specific version.Note: You will need to share this this URL with your CSM for your Jira delivery request ticket.

## Development Phase - FI

These procedures are completed by the FI requesting the widget or service.

### Submit Jira Delivery Request Ticket for Installation

Alkami Gold Partners are vendors that have one of the following two arrangements for providing their solutions in the Alkami platform.

An existing agreement and authorization with Alkami (https://confluence.alkami.com/display/SDKC/Gold+Partner+Solution+Deployment#GoldPartnerSolutionDeployment-resold) for deploying their content and services in the Alkami environment and are resold by Alkami.

An existing agreement with a Financial Institution (FI) (https://confluence.alkami.com/display/SDKC/Gold+Partner+Solution+Deployment#GoldPartnerSolutionDeployment-notResold) that is currently on the Alkami platform and will require legal authorization and access to upload their packages to their client FI's environment.

In either case, the vendor is providing a coding, configuration, or authentication service that will save the FI time and resources.

Once these items are submitted, the Software Development Kit (SDK) Product Owner (PO) will create the Release Management ticket (RM) to route the solution to the FI staging environment

After Staging verification, and Prod deployment approval have been received from the FI, the SDK PO will work with RM to deploy the changes to Production.

Gold Partners that are resold by Alkami open a Delivery Request Jira Ticket, as follows.
Note: Options selected in Project and Issue Type fields may cause other fields to appear or disappear.

- Identify if one or multiple FIs will use the submitted component.If you are submitting a component that can or will be used by multiple FI's and is coded using your namespace and identifier, open the src/Manifest in the Alkami SDK and remove (or comment out) the entire <bankIdentifiers> element from the manifest. The following text will be deleted: | <bankIdentifiers> <bankIdentifier name="">00000000-0000-0000-0000-000000000000</bankIdentifier></bankIdentifiers> | If you are submitting a widget for a specific FI and it is coded using the FI's namespace, ensure the FI's BankIdentifier node is filled in with the correct FI name and the identifier.
- Launch Jira and click the Create button.
- Select Delivery as the Project type from the Project dropdown menu.
- Select the appropriate issue from the Issue Type dropdown menu. This will typically be Feature Request for Vendor submitted widgets.Bug: Report defects (only used prior to the transition to support)Change: Request new featuresFeature Request: Request additional functionalityQuestion: Post questions to Alkami personnel
- Enter a detailed, concise description of the issue or request in the Summary field.Note: Do not enter sensitive information in the Summary field, as it will appear in email communications.
- Enter a detailed description of the issue or request in the Description field. (See Required Information for additional details.)
- Select the appropriate priority level (according to the contract guidelines) from the Priority dropdown menu.Pro Tip: Selecting an incorrect priority level may result in a processing delay as the priority level is reviewed and re-prioritized.Critical (SEV1): Must be resolved immediately due to failure of an essential function (For example, site outage, major security issue impacting most users).High (SEV2): Bugs preventing usage of a feature by most users (For example, Bill Pay not working).Medium (SEV3): Any of the above issues impacting one to a few users (use for all UAT/Pilot issues).Low: Change Requests, bugs not noticeable to most users.Lowest: Do not use.
- Screenshots (including URLs), logs, or other files helpful in the resolution of the issue should be uploaded via the Attachment section.
- Select the appropriate platform (if applicable)from the Components dropdown menu.
- Click the Create button to submit the JIRA ticket.

After Staging verification, and Prod deployment approval from the FI, the SDK Product Owner (PO) will work with RM to deploy the changes to Production.

### Monitor the Jira Delivery Request
- Record as much detail regarding the issue prior to submitting a JIRA ticket. Failure to do so will result in a request for further information, causing a delay in the resolution of the issue.
- The following list is an example of the type of information needed:Severity of the issue/request and its business impactExpected functionalityBuild version affectedSteps taken to duplicate the issue (bulleted list)User information for those impacted by the issue (username, FI ID)Screenshots (Including error messages and URLs of affected pages)Environment (Staging or Production)Type of device(s) impacted by the issue (desktop/mobile/tablet, OS, Browser w/ version, model number of device)Third party applications, vendors or services involvedOther applicable detailsDetailed description of the issue/requestFor new feature requests or enhancements, please also include the following:Business requirementsUse casesRequested delivery date
- Monitor the Jira statuses and transitions through the process. The party identified to receive Jira updates will receive notifications as the request progresses through these statuses and transitions. If any of the paths fail, there will also be notifications sent with relevant details.Note: Avoid opening connections and not closing them. Wrap all connections in a using statement to ensure it is close. Ensure your Database schema doesn't conflict with the Alkami schema. Don't allow any cross-site scripting as this poses an exploit threat. Avoid SQL injection issues. These are often identified in Static Code Analysis and cause submission rejections.
- Push completed package to private Alkami feed (myfi.choco.dev).
- After successful code review and Fortify scan, the package is promoted to private staging feed (myfi.choco.stage). Then, after you (the FI/vendor) complete your Stage testing and approve moving to Production, the package is promoted to private production feed (myfi.choco.prod).
