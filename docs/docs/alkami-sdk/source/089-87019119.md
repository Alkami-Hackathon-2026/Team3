The development environment comes equipped with a Static User context that will always pass authentication for our test users. We use the Brady family members as test users and each member of the family is authenticated as a Static User.

Typically, we want to go through the authentication process successfully, but it's possible to trigger a failed authentication by entering a predefined value as an answer to one of the challenge questions. Instead of answering "1" and "2" (any non-empty value is accepted), the developer can answer with "InvalidCredentials," "PasswordExpired," or any of the predefined authentication status results.

## Available Overrides

Case Sensitivity

The answers will be parsed into an Enum type and will require the casing to match

| AuthenticationStatusCode |
| Blocked |
| AccountDisabled |
| AccountLocked |
| InvalidCredentials |
| NotAuthorized |
| PasswordExpired |
| PasswordMustChange |
| ResourceNotProtected |
| Error |
| ChallengeUser |
| UserNotRegistered |
## Triggering a Failed Authentication

Enter one of the above status codes as an answer to either question.

- If the first answer satisfies a fail condition, the second answer will not be evaluated.
- If the first answer does not satisfy a fail condition, the second answer will be evaluated.
- If neither answer satisfies a fail condition, then authentication will continue as a success.
### Example Answer

This will trigger an "InvalidCredentials" authentication failure.

### Example Authentication Failure

The user will be prompted of the failure and asked to re-enter the answers.
