This guide will walk you through how to get Albus setup in your project and compiling your assets. If you are still new to Albus, it is recommended to read the anatomy (/spaces/SDKC/pages/303531403/Anatomy) section first to get an understanding of terminology and how things work or watch the Albus Training Video (/spaces/SDKC/pages/303531408/Albus+Training+Video) before diving into this part of the documentation.

If you already have an existing project that uses the antiquated gulpfile.js to compile your assets, head over to the existing project checklist (/spaces/SDKC/pages/303531410/Existing+Project+Checklist) and follow those steps before continuing. That checklist will make sure you have everything cleaned up in your project before starting here.

Additionally, if you would prefer a hands off approach, we have created a script that will automate the project setup and conversion from a project that leverages the gulpfile.js today. To get started, please make sure you have committed any changes and cleaned your branch and run this command in the root of your repository.

Albus conversion script

```
$ npm install @alkami/albus-convert-widget --no-save --@alkami:registry=https://packagerepo.orb.alkamitech.com/npm/npm.dev/
$ npx albus-convert-widget <your_project_folder>
```

Where <your_project_folder> is the name of the project folder in your solution. Review the output of that script and see if Albus is now building correctly. If you see any errors, check out the common conversion errors (/spaces/SDKC/pages/303531409/Common+Conversion+Errors) guide.

#### Check for node and npm

First things first, Albus relies on node and npm to function. Check to make sure both are installed and at the correct versions by running these commands in your terminal. The major version should be equal to or higher than the ones listed below.

Node & Npm check

```
$ node -v // => 14.x.x
$ npm -v // => 6.x.x
```

If those are not installed or are at older versions, please install / upgrade them. We recommend using the Alkami.DeveloperKit.Node (https://packagerepo.orb.alkamitech.com/feeds/choco.dev/Alkami.DeveloperKit.Employee.Node/1.1.0) chocolately package for Windows machines and the homebrew formula (https://formulae.brew.sh/formula/node@10) for MacOS.

#### Create a Package.json file

Before we can install Albus and other accompanying packages, there needs to be a package.json file at the root of your repository. If one doesn't exist already, run this command (at the root of your repository) to create that file.

```
npm init private
```

Once that is completed, the file contents should look like this:

package.json

```
{
"private": true,
"version": "0.0.0",
"dependencies": {},
"devDependencies": {},
"scripts": {}
}
```

#### Install Albus

Once the package.json file has been created, we can install the albus-cli package which is the starting base of the Albus ecosystem:

```
$ npm install @alkami/albus-cli --@alkami:registry=https://packagerepo.orb.alkamitech.com/npm/npm.dev/ --save-dev
```

To break this command down, we are installing the Alkami scoped package albus-cli from our private registry and saving it to the project as a development dependency. If you would like to know more about package installation or dependencies in general please check out the npm documentation (https://docs.npmjs.com/about-npm/).

#### Determine the preset(s) you need

Albus functionality is bundled together in the form of presets. For now you can think of presets as collections of functionality tailored to a specific use case e.g., building a Vue application. You can install one or more presets depending on the need of your project. If you would like to know more about presets, please see the preset list (/spaces/SDKC/pages/303531412/Presets) for an in depth look at what is available.

##### Legacy Preset

If you are converting a widget that currently uses a gulpfile.js file, this is the preset needed. Essentially, this replicates all of the current functionality in the gulpfile using Albus instead.

Install this preset using the following command:

Legacy preset install

```
$ npm install @alkami/albus-preset-legacy --@alkami:registry=https://packagerepo.orb.alkamitech.com/npm/npm.dev/ --save-dev
```

##### SASS Preset

This preset is for compile SCSS files on their own or in alongside another preset (e.g., Webpack).

Install this preset using the following command:

SASS preset install

```
$ npm install @alkami/albus-preset-sass --@alkami:registry=https://packagerepo.orb.alkamitech.com/npm/npm.dev/ --save-dev
```

##### Vue Preset

This preset is for building a front-end experience using Vue and wraps a webpack flow that compiles .vue files into JavaScript and CSS modules.

Install this preset using the following command:

Vue preset install

```
$ npm install @alkami/albus-preset-vue --@alkami:registry=https://packagerepo.orb.alkamitech.com/npm/npm.dev/ --save-dev
```

##### Webpack Preset

This preset allows you to leverage a modern JavaScript bundling pipeline using webpack without having to convert to using Vue as a framework.

Install this preset using the following command:

Webpack preset install

```
$ npm install @alkami/albus-preset-webpack --@alkami:registry=https://packagerepo.orb.alkamitech.com/npm/npm.dev/ --save-dev
```

#### Initialize an Albus Project

Now that Albus and the necessary presets have been installed, it's time to get the the preset(s) setup and configured. Each preset comes with a tailored init command that scaffolds the necessary files and creates a base configuration that works out of the box (for most projects). Simply run the following command in the solution directory:

Legacy preset install

```
$ npx albus catalyst -C your_project_folder
```

More information...

If the catalyst command can't infer all the information it needs, it will ask you a few questions for your Albus configuration. Just follow the interactive prompts to continue with the scaffolding process.

Based on the presets you have installed in your solution, several additional files will be created in your project to facilitate certain plugin tasks. You will need to commit these files to your repository.

If you would like to see what the catalyst command does, check out the manual instructions (/spaces/SDKC/pages/303531411/Manual+Project+Setup).

#### Configure Albus

Although all presets are initialized with sane defaults, you may need to configure Albus further to get exactly what you want. To get a deep dive on what configuration options are available, check out the following documentation:

- Albus Configuration - get to know your Albus config file
- Preset List - learn about the available presets and their specific configuration
#### Test it out

Now that everything has been installed, initialized, and configured, it's time to test it out! Run this command to execute the build job and see if Albus is working as expected:

Albus transmute

```
$ npx albus transmute -C project_folder # => Builds front end assets.
```

Protip

The -C option is available on all Albus commands to reference a folder. Use this option if you prefer to stay in your solution directory (e.g., npx albus panoption -C your_project_folder), otherwise you will need to cd into that project folder.

If there are any errors that are outputted to the console, see common conversion errors (/spaces/SDKC/pages/303531409/Common+Conversion+Errors).

#### Albus & Visual Studio (optional)

After getting Albus setup in your project, if you want it to run whenever you build in Visual Studio, you will need to update your project's csproj to attach to an event. Open the solution's csproj file and look for the <PreBuildEvent> or in Visual Studio navigate to Project > Properties > Build Events > PreBuild and prepend with the following script:

Visual Studio Prebuild Event

```
powershell.exe -noninteractive -command "npx --userconfig '$(SolutionDir).npmrc' --package @alkami/albus-vs-run@~1 albus-vs-run" '$(SolutionDir)' '$(ProjectDir)'
if %errorlevel% NEQ 0 exit %errorlevel%
```
