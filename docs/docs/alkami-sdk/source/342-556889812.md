Not all Standard SSO's require certificates but if they do, the types of certificates needed for Standard SSO's can vary depending on the individual SSO, but it will always be a signing certificate, encryption certificate, or a combination of these. Certificates come in many different file types, but are usually pfx, crt, or cer. Each certificate (signing or encryption) has both a public and private key

#### Types of Certificates:

Signing Certificates - Alkami generates the signing certificate if one is required for the integration. The private key (.PFX) is what gets installed at Alkami for the signing certificate.

- Signing certificate generation example: INFOSEC-16114 - Getting issue details... STATUS
- Signing certificate private key (.PFX) installation example: OPS-47145 - Getting issue details... STATUS

Encryption Certificates - These certificates are generated by the vendor and shared with Alkami to install. These files usually have an extension name of .crt or .cer. These are not required for every sso and dependent on the vendor.

- Encryption certification installation example: OPS-46058 - Getting issue details... STATUS

#### Where do the Certificates need to be installed for Standard SSO:
- Signing certificate private keys (.PFX) - These will need to be installed in the personal store on the lane or pod where the FI is hosted.
- Encryption certificates (.CRT or .CER) - These will need to be installed in the trusted people store on the lane or pod where the FI is hosted.

#### Certificate best practices:

- Do not share signing or encryption certificates for multiple FI's in production, even for the same sso.
