If you are developing a widget that will need SiteText for the Spanish language, then the steps below will show you how to enable your SDK site for multi-lingual operation so you can develop and test your widget.

### Step-by-step guide

- Enable the Spanish language in your tenant database. Enabling Spanish language (es-US) ``` USE DeveloperDynamic -- put in the name of the tenant database you want to use GO UPDATE [Contact].[Locale] SET [IsAvailable] = 1 WHERE [Id] = 21514 -- Enable Spanish 'es-US' -- Note that 21514 is the United States version of Spanish which you can find by running select * from Contact.Locale ```
- If you also want to enable the "XX" language, do the following. (The XX language is a helpful want to see all of the SiteText spots on your views.) (Optional) Enable the "XX" language ``` -- Run this query to see if a record is already in the database select * from Contact.Locale where Id = 99999 -- If the record is not present then insert it by using this line insert into Contact.Locale values (99999, 'Test Culture', 'xx-xx', Getdate(), 'xx', null, 1) ```
- Add a Spanish language Display Name and Description for your Widget. (If you do not do this, then the widget's area name will be used which is probably in English, and probably not human friendly.) Adding Display Name and Description ``` Declare @WidgetName varchar(100) Declare @WidgetDisplayName varchar(100) Declare @WidgetDescription varchar(100) Declare @localToAdd int Set @LocalToAdd = 21514 -- 21514 is the value for United States Spanish -- Update the following three lines with your values Set @WidgetName = 'TrainingMyWidget2' Set @WidgetDisplayName = 'Spanish Disp Name' Set @WidgetDescription = 'Spanish Description will go right here.' if exists (Select * from core.Item where name = 'Widget.' + @WidgetName) Begin Declare @ItemId BigInt select @ItemId = id from core.Item where name = 'Widget.' + @WidgetName and SecondaryId = @LocalToAdd if (@ItemId is null) begin print 'Adding core.Item record' insert into core.Item (ItemType, ParentId, SecondaryId,Name,CreatedUtc,Version,Deleted,LastUpdate) select ItemType, ParentId, @LocalToAdd,Name,CreatedUtc,Version,0,GetDate() from core.Item where name = 'Widget.' + @WidgetName Set @ItemId = SCOPE_IDENTITY () end else print 'Found existing core.Item record' print 'ItemId is ' + cast(@itemId as varchar(10)) if not exists (Select * from core.ItemSetting where name = 'DisplayName' and ItemId=@ItemId ) begin print 'Adding core.ItemSetting record' insert into core.ItemSetting ( ItemId,Name,[Value],CreatedUtc,Version,LastUpdate) Values(@ItemId,'DisplayName',@WidgetDisplayName,GETUTCDATE(),'1.0.0.1',getdate()) end else begin print 'Updating core.ItemSetting record' update core.ItemSetting set [Value]=@WidgetDisplayName where name = 'DisplayName' and ItemId=@ItemId end if not exists (Select * from core.ItemSetting where name = 'Description' and ItemId=@ItemId ) begin print 'Adding core.ItemSetting record' insert into core.ItemSetting ( ItemId,Name,[Value],CreatedUtc,Version,LastUpdate) Values(@ItemId,'Description',@WidgetDescription,GETUTCDATE(),'1.0.0.1',getdate()) end else begin print 'Updating core.ItemSetting record' update core.ItemSetting set [Value]=@WidgetDescription where name = 'Description' and ItemId=@ItemId end end else begin print 'Widget with the name ' + @WidgetName + ' does not have a record in core.item' end ```
- Update your browser to enable the additional language. Do this by going into the browser settings and find the settings for Languages. Add the desired language, Spanish (United States)
- Reboot your SDK, or restart the complete Alkami platform by running "restart-sdkservices" in Powershell.
- Now your SDK pages should have buttons on the bottom of the pages for selecting the desired language. In this example, you can see the option for Spanish (ESPANOL), and for the "XX" language.

here's a closer look

Now you are ready to add the Spanish language SiteText file to your widget project. The SiteText file that came in the widget temple will have "en" right before the file extension. This indicates English. For Spanish (Espanol) use "es" in the filename. If you have enabled the "XX" language, add a file with "xx" too.

The English and Spanish SiteText files will automatically get packaged and deployed when you rebuild your widget project. However the "XX" file will not. We do not want you to include the xx file in the package you submit to Alkami for deployment. You will need to manually copy it to the widget's _SiteText folder under c:\orb\areas\WidgetName.

In the admin site, under Setup→ Integration Settings you will find the admin tool for SiteText. Now that you have the additional language(s) enabled you will see them listed in the dropdown control. Each language can have values entered into the database using this tool to override the default values form your xml files.
