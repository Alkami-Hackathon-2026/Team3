## Base Information
### Controllers

The controllers handle the incoming requests to the service. In this project, you will only implement other base controllers defined in the Alkami.Providers.TransferPayments.Contracts project. These controllers define all the attributes needed for each controller and endpoint, so you don't have to configure the route, validation, HTTP method, response codes, and so on. Just implement each controller function since Alkami predefined all the necessary controllers.

You can see the Real-Time Payments endpoint (RealTimePaymentsController.cs) is implemented.

You must implement the following controllers and endpoints :

- RealTimePaymentsController.SubmitThis endpoint is invoked when a user posts a payment. When returning the response for this endpoint the Identifier and Status must be included. The Identifier and Reference is used to trace the full path of the request. The status is used to update the transfer in Alkami's database and show the user. Alkami also expects the other values to be filled out since they are used to store, trace, and display data to the user.
- RoutingNumbersController.GetThis endpoint is invoked when Alkami checks to see what the routing number can be used for. The only value in the response object is a Boolean (IsEligibileForRealTimeTransfers) to indicate whether a routing number can be used for Real-Time Transfers or not.
- StatusController.GetThis endpoint is invoked when Alkami wants to determine if we can send a request to the Transfer Payment Provider. Usually, this function includes checks to other necessary services and databases and sets the responses SupportedPaymentTypes accordingly. If the service does not include a certain payment type then we do not show that option to the user in the UI.

Typically, when a request comes in it is useful to get the request context.

### Validators

These validate that a request has all the necessary parameters and that each parameter has a valid value. This isn't to check to ensure that the account identifier references an account but to confirm that the account identifier isn't the default value.

### Startup.cs

This file contains the majority of the logic needed to register all the default classes and set up many settings for the service. If you must register a new interface you can do so here or create or add to the IServiceCollectionExtensions.cs class.

## Controller Endpoints

Implement the following controllers and endpoints: RealTimePaymentsController.Submit, RoutingNumbersController.Get, StatusController.Get. Most of the time when a request comes in it is useful to get the request context.

### DebitCardPaymentsController.Submit

This endpoint is invoked when a user is posting a debit card payment. When returning the response for this endpoint the Identifier and Status are important parameters that must be included. The Identifier and Reference are used to trace the full path of the request. The Status is used to update the transfer in our database and show the user. Alkami also expects the other values to be filled out since they are used in storing, tracing, and displaying data to the user.

### DebitCardVerificationsController.Verify

This endpoint is invoked when Alkami checks to see whether a debit card is valid. When returning the response for this endpoint, Alkami expects the Status to be filled out, and if the Status is Approved, then the supported transfer types for the debit card should be returned.

### RealTimePaymentsController.Submit

This endpoint is invoked when a user posts a real-time payment. When returning the response for this endpoint the Identifier and Status are important parameters that must be included. The Identifier and Reference are used to trace the full path of the request. The Status is used to update the transfer in Alkami's database and show the user. Alkami also expects the other values to be filled out since they are used in storing, tracing, and displaying data to the user.

### RoutingNumbersController.Get

This endpoint is invoked when Alkami checks to see what the routing number can be used for. Currently, the only value in the response object is a Boolean to indicate whether a routing number can be used for Real-Time Transfers.

### StatusController.Get

This endpoint is invoked when Alkami tries to determine if we can send a request to the Transfer Payment Provider. Usually, this function includes checks to other necessary services and databases and sets the response's SupportedPaymentTypes accordingly. If the service doesn't include a certain payment type then we don't show that option to the user in the UI. Also, this endpoint should return the supported ProviderLoanPaymentTypes which are types of loan payments that can be made using the provider.

## General Request Flow

After a request has passed all authentication and validation, it gets to the actual controller logic. Then, generally, Alkami first gets the request context so we can get the current user's ID and possibly useful settings. Then, we pass the request and the request context to another function or class that handles the request, whether that's reaching out to other services, the database, or anything else that is needed by the request. Alkami left the code in the controllers to get the request context since that's an Alkami-specific method but left everything else up to the user to decide how it happens.

## Testing
### Swagger

To test your service:

- Run the project and it will start your service. Run Visual Studio as an administrator, otherwise, the project will fail to run. In the debugger console window, it outputs the URL of your API as the Host Determined.
- Copy and paste this URL into your web browser and add /swagger/index.html to the end to go to your project's swagger page.
- On the Swagger page, you can fully test each endpoint of your service.
### Authenticating

To authenticate your user to test an endpoint in Swagger you must use the Alkami tool, Sidekick.

- Open Sidekick.
- Go to the Services Request New WCF Request Auth tab and select your bank identifier and user.
- Click Get JWT and it will automatically copy the JWT to your clipboard.
- On the Swagger page, click Authenticate and paste the JWT into the text box. Your requests will be authenticated with that user. If you get a 401 error then you must reauthenticate your user.

## Send Requests to Alkami WCF Services

When sending a request to an Alkami Service we generally have the following main parts of the request: the filter, the mapper, and the sorter.

### Filters

The filter is used to filter values that are not needed. An example of this is including the SourceAccountIdentifier and DestinationAccountIdentifier in the list of AccountIdentifiers on the filter of the GetAccountRequest object. This can have performance issues if you include parameters that are not commonly searched.

### Mappers

The mapper tells the service whether to include certain pieces of data in the response. An example of this is setting the IncludeRoutingInfo to true on the mapper of the GetAccountRequest object. This can have performance issues if you return a lot of data.

### Sorters

The sorter sorts the data returning. An example of this is setting the OrderByFields on the GetAccountRequest to use the LastTransactionDate field. This can have performance issues if you sort on a non-indexed column.

#### Examples
Use Security Service

```
internal interface IGetCurrentUserCommand
{
Task<User> ExecuteAsync(IRequestContext requestContext, CancellationToken cancellationToken);
}

internal class GetCurrentUserCommand : IGetCurrentUserCommand
{
private readonly ISecurityService _securityService;
private readonly ILogger _logger;

public GetCurrentUserCommand(
ILogger<GetCurrentUserCommand> logger,
ISecurityService securityService)
{
_logger = logger ?? throw new ArgumentNullException(nameof(logger));
_securityService = securityService ?? throw new ArgumentNullException(nameof(securityService));
}

[Trace]
public async Task<User> ExecuteAsync(IRequestContext requestContext, CancellationToken cancellationToken)
{
var userId = requestContext.Identity.UserId.Value;
User result = null;

try
{
var request = new GetUserRequest()
{
Filter = new UserFilter()
{
Ids = new List<long> { requestContext.Identity.UserId.Value },
},
Mapping = new UserMapper
{
ShouldIncludeUserAccounts = true,
ShouldIncludeExternalUserAccounts = true,
},
};

var response = await _securityService.GetUserAsync(request);
result = response?.Users?.FirstOrDefault();

if (result == null)
{
_logger.LogError("Error retrieving User {userId}.", userId);
}
}
catch (Exception ex)
{
_logger.LogError(ex, "Error retrieving User {userId}", userId);
}

return result;
}
}
```

## Logging

Alkami uses Serilog and Microsoft's ILogger. Instead of creating an exact string to log, Alkami passes parameters to the log function and lets them default. The ToString() method handles the logging. This saves time if you want to log a lot of values for a trace message, but the current log level is set to debug. The logger can also be automatically injected into classes so you don't need to create one or pass it around.

#### Examples
Logging Example

```
_logger.LogTrace("Retrieving User {userId}.", userId);
```

## Validators

Validators validate if a request has all the necessary data and other quick checks. They are not meant to be used to check if an account identifier is actually for the account of the user, but more for checking if the account identifier is not an empty GUID. We have base request validators to make sure that any non-nullable field on a request is filled out with a non-default value but if you want to create your own validator for something specific you can add them to the validator folder under models and they will be automatically included in the startup. These are the base request validators that we have:

- DebitCardAddressValidator
- DebitCardPaymentSubmitRequestValidator
- DebitCardVerifyRequestValidator
- RealTimePaymentSubmitRequestValidator
#### Example
DebitCardVerifyRequestValidator.cs

```
namespace Alkami.Providers.TransferPayments.Contracts.Models.Validators
{
public class DebitCardVerifyRequestValidator : IValidator<DebitCardVerifyRequest>
{
public Errors Validate(DebitCardVerifyRequest model)
{
var errors = new Errors();

if (string.IsNullOrWhiteSpace(model.CardNumber))
{
errors.Add(nameof(model.CardNumber), "Must be non-null and non-empty");
}

if (string.IsNullOrWhiteSpace(model.CVV))
{
errors.Add(nameof(model.CVV), "Must be non-null and non-empty");
}

if (model.ExpiryDate == DateTime.MinValue)
{
errors.Add(nameof(model.ExpiryDate), "Must be provided");
}

if (string.IsNullOrWhiteSpace(model.FirstNameOnCard))
{
errors.Add(nameof(model.FirstNameOnCard), "Must be non-null and non-empty");
}

if (string.IsNullOrWhiteSpace(model.LastNameOnCard))
{
errors.Add(nameof(model.LastNameOnCard), "Must be non-null and non-empty");
}

if (model.Address == null)
{
errors.Add(nameof(model.Address), "Must be provided");
}

return errors;
}
}
}
```

The following is the script to run to insert your provider into the database.

Insert Provider into database

```
DECLARE @ServicePath NVARCHAR(100) = ''

---------------------------------------------------------------------------------
DECLARE @ProviderTypeID BIGINT = (SELECT TOP 1 ID FROM [core].[ProviderType] WHERE [Name] = 'transfer-payments')

---------------------------------------------------------------------------------
```
