## Submission Requirements

The following standards not being followed will likely result in the re-submission of your SDK submission

### Packages
- Proper naming conventionRefer to the SDK Submission Guidelines at Submit ProjectsFor example: assume the name of your organization is "US Best Financial Institution," your Widget would have a name like "USBFI.Client.Widget.LoanHealth" or a microservice would have a name like "USBFI.MS.LoanHealthService"
- Content directory for widget package must follow the Alkami standardThe proper path for a content folder is: content\Areas\App\
- Disallowed filesWeb.configsWithin a Widget package the only DLL files should be: the assembly for your widget, assemblies needed to communicate with your custom microservice, only Alkami*.dll files that have a version number within the filename, and any other assemblies that Alkami has specifically told you to include.
- Do not modify the Alkami ChocolateyInstall.ps1 and ChocolateyUninstall.ps1 files provided in the Alkami.SDK.Templates.
### Configuration
- Improperly configured NewRelic.AppName value in the app.config for a microservice (should match the MS name, and must not be "REPLACEME")
- AlkamiManifest.xml should be filled out in its entirety.
### Versioning/Packages
- Chocolatey package version of an SDK submission and the C# AssemblyInfo.cs must have matching version numbers
- It is required that at minimum, the patch value of the semantic version must be incremented for each submission
- Alkami.Common, Alkami.Client and other Alkami reference assemblies cannot be more than two minor versions behind submission deployment target
- For utilizing approved Javascript libraries, review the \lib folder and the \javascripts folder under C:\Orb\WebClient. If Alkami includes the library on the page, do not load that library again. All Third Party JavaScript packages not in the Alkami Platform must be included, disclosed or available in the package.json.
### Code
- PII leak in URL
- If an object implements IDisposable, using statement with that object is required
- Public Internet API calls through Widget code is NOT permitted
- Any service request needs to be wrapped in try / catch
- Any service request needs to handle validation of error results
- Not implementing logging for exceptions
- Using console.log in your custom Javascript is not permitted.
### Security/Compliance
- Fortify submission failure
- Insecure cryptographic algorithms
- Use of unapproved 3rd party libraries; license issues with 3rd party libraries
- Overriding Setting TLS Security management value
- Any crypto keys, API passwords, or other secret information must be removed from the submitted source code and any SQL scripts contained in the submitted package. These values need to be read from configuration settings and not contained in your source code.
### JIRA Submission Ticket
- The SDK Component Type must be correct

## Submission Suggestions

The following best practices WILL NOT result in REJECTION, but may result in poor performance/stability in SDK widgets & services.

### Code
- Mixing async/sync behavior
- For dependency injection, LightInject IOC should be the container used
- Hard coded configuration data
- Using Html.SiteText inside Html.Raw helper is strongly discouraged
- Using ViewBag, as this is shared across the entire web platform and can be in an unpredictable state
### Testing responsibility
- Your projects must be tested in your local SDK environment prior to submitting the project to Alkami for processing
- Be sure you test the actual code that you are packaging to upload to the feeds server
## Understanding code review comments

Most comments will be self explanatory regarding what actions (if any) you you must take. To help communicate clearly to you we will sometimes begin the a comment with the following key phrases:

| Phrase | What it means to you |
| Needs work | This comment describes the reason (or one of the reasons) why the submission is being declined. You will need to make changes to your project to address this item before submitting again. |
| Suggestion | Although this item is not sufficient reason for us to decline the submission, you should make changes the next time you rework your project. |
| Tip | What follows is a general comment that might not even be related to your project code. No action on your part is required. |
| Question | The reviewer is curious about something in your project. These questions will not prevent processing your submission, but you should reply to the question by placing a comment on the submission Jira ticket. |
### Some examples of these types of comments:
- Needs Work: your package is missing the widget's dll file.
- Suggestion: you should use the AugmentRequest extension method that is contained in WebToolkit rather that maintaining your own method.
- Tip: do a web search for "razor syntax" and you will find many examples that will help you in building your views.
- Question: are you going to need us to open up a firewall port and configure routing to reach your web service?
