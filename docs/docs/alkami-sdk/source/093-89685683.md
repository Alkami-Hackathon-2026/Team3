## Transfer Widget Deep Linking

To implement deep linking to the transfers widget. you will need to know if the customer is on mobile or not. MMC does not have an endpoint that will decide whether to redirect the user to a mobile version or desktop version. Deep linking is only supported on the "classic" tab of the transfer widget and the mobile version. It is not supported on the "quick" tab.

### Parameters

You can provide as many or as few parameters to the widget as you'd like, although it should be noted that if you don't provide certain parameters, you won't be able to use other parameters.

- "toAccount": The account you'd like to transfer money to. Also known as the destination account. This should be the GUID of the account identifier (core.Account.Identifier). The parameter value is not case-sensitive, however the parameter key (toAccount) is case-sensitive.
- "fromAccount": The account you'd like to transfer money from. Also known as the source account. This should be the GUID of the account identifier (core.Account.Identifier). The parameter value is not case-sensitive, however the parameter key (fromAccount) is case-sensitive.
- "frequency": This is the frequency of the transfer. Please note that not all transfers support frequency, or all of the frequencies. The parameter value is not case-sensitive, however the parameter key (frequency) is case-sensitive. Here's a list of all potential values:DailyWeeklyBiweeklySemimonthlyEvery4WeeksMonthlyEndOfMonthQuarterlyEvery6MonthsQuarterlyEvery6MonthsAnnuallyEveryOtherMonthWhenDue
- "ending": This is how long the transfer should last, or when the transfer ends. The parameter value is not case-sensitive, however the parameter key (ending) is case-sensitive. Here's a list of potential values:"Never": This will cause the transfer series to never end, by selecting the "Never" option.<number>: This will cause the transfer series to end after a particular number of occurrences. This must be an integer greater than 0.<date>: This will cause the transfer series to end before or on a particular date. The date must be formatted as "MM/DD/YYYY". It is recommended that the date numbers are zero-padded.
- "startDate": The date that the transfer series should start on. The parameter value is not case-sensitive, however the parameter key (startDate) is case-sensitive. The date must be formatted as "MM/DD/YYYY". It is recommended that the date numbers are zero-padded.
- "amount": The "custom amount" of the transfer. This should be a positive value greater than zero. Please do not add the "$" on. It may only have two decimal places at a maximum. The parameter value is not case-sensitive, however the parameter key (amount) is case-sensitive.

### Examples

In DeveloperDynamic on Desktop, to transfer money to her savings account for $450 starting on 01/03/2021, you could do the following:

https://developer.dev.alkamitech.com/TransferV2/Classic?toAccount=0498a1fb-d172-4515-9f31-4205736f42ad&amount=400&startDate=01/03/2021 (https://developer.dev.alkamitech.com/TransferV2/Classic?toAccount=0498a1fb-d172-4515-9f31-4205736f42ad&amount=400&startDate=01/03/2021)

In DeveloperDynamic on mobile, to transfer money from cindy's checking account to her savings account for $10.50 monthly starting on 04/01/2020 and end after 9 occurrences could be written as such:

https://developer.dev.alkamitech.com/Mobile/TransferV2?fromAccount=90e94793-9860-4305-828b-0f2ac62f032a&toAccount=0498a1fb-d172-4515-9f31-4205736f42ad&amount=10.5&frequency=monthly&ending=9&startDate=04/01/2020 (https://developer.dev.alkamitech.com/Mobile/TransferV2?fromAccount=90e94793-9860-4305-828b-0f2ac62f032a&toAccount=0498a1fb-d172-4515-9f31-4205736f42ad&amount=10.5&frequency=monthly&ending=9&startDate=04/01/2020)

### Notes
- Due to mobile being highly wizard based, it is recommended to provide all parameters to get the best experience. For example, you'll need to provide a "fromAccount" if you provide a "toAccount" due to the validation process with mobile.
- There is no guarantee that the transfer you pick out will give expected results. Some accounts might not be transferable to, even if the user can see them. Other accounts might not allow transferring money to certain accounts. Some options might be disable for certain transfers or FIs.
- Validation should be done on the caller's end prior to performing a transfer deep linking.
- Due to the complex nature of LPOs, they are not supported at this time.
- You can use this to put a start date or ending date in the past but the transfer will not be allowed.
