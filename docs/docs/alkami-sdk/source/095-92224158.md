When you are developing and debugging your SDK microservice, you simply hit <F5> in Visual Studio to launch the service with the debugger attached. There is no need to actually "install" it as a Windows service. However, sometimes you will actually want to install it as a Windows service for reasons like:

- To test the final choco package that you will submit to Alkami
- So you don't need to have a second copy of Visual Studio running with the microservice while you are working on a Widget.
- You want to deliver the microservice to another developer in your organization, or you want to install it on an internal QA server where you test your SDK projects.

### Step-by-step guide
#### Your first step is make sure your microservice is working and to create the installation choco package
- It will be difficult to debug your code when it is running from the Windows Services registry. Make sure it starts and runs in Visual Studio with the <F5> functionality.
- Create the Chocolatey package for your microservice as if you are going to submit it to Alkami. Refer to Package A Microservice Installer

#### How to install from your dev feed:
- Upload your package as shown here: Add a package to your development feed
- Browse to the package page in the feeds server.
- Simply copy the installation command (with all the parameters) and run this command on the computer where you wish to install the service.

#### How to install from a local directory:
- Copy the package to the computer where you want to install the service and put it in a conveient directory, such as c:\LocalPackageFeed
- Use Powershell (as admin) to install the package. The command will look similar to the command you can get from the feeds server, however you will specify the drive and directory where the package is located like this:
Installing a chocolatry package from a local directory

```
# (the following is a simple command that may wrapped onto multiple lines)

choco install USBFI.MS.Service.SomethingSpecial.Host --version 1.0.0 --source c:/LocalPackageFeed/USBFI.MS.Service.SomethingSpecial.Host.1.0.0.nupkg

```

Warning:

After you install your microservice Chocolatey package, the service will be registered in Windows and will be set to automatically start. If you then try to use <F5> to run the same service from within Visual Studio the program will fail to stay running because of a service the the same name is already running. You can either use the Windows services control panel to stop and disable the service instance that is registered there, or you can uninstall your microservice Chocolatey package using this command in Powershell (as administrator):

Uninstall your registered service

```
# assuming your package is named USBFI.MS.Service.SomethingSpecial.Host

choco uninstall USBFI.MS.Service.SomethingSpecial.Host

# tip: if you forget the name of your package, you can see a list of the locally installed packages with this command:
choco list -lo

```
