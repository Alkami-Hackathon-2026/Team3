#### Issue: Sometimes the Subscription Host service doesn't get installed completely

Use this command to install it again:

```
choco upgrade Alkami.Services.Subscriptions.Host -y
```

#### Issue: These components are critical to the login process

Reinstalling or upgrading these can solve most login issues that arise from a fresh install or upgrade.

```
choco upgrade Alkami.Apps.Authentication -y; choco upgrade Alkami.Apps.DashboardV2 -y; choco upgrade Alkami.Apps.MyAccountsV2 -y;
```

#### Issue: After I log in, I get an error with the view on the dashboard

If you have the newer DashboardV2, then depending on the order of the other things you have installed, sometimes you must install or reinstall the UserInterface microservice. Use this command to install it:

```
choco upgrade Alkami.MicroServices.UserInterface.Service.Host -y;
```

#### Issue: I'm getting an error related to displaying the Dashboard

Another problem that is related to upgrading old SDK VM images to 2018.07 or later is the proper setting for the Accounts module on the modular DashboardV2 Widget. If you get errors related to displaying the Dashboard, check the Settings in the Admin User Interface and make sure the Accounts module has a URL of MyAccountsV2/Module and not an Accounts view from within the Dashboard module.

If you are still experiencing issues, use the Powershell command choco list -lo to view a list of the packages in the local environment. Confirm that you have this list of packages installed at a minimum. Install any that are missing:

#### The Alkami templates are not showing up in Visual Studio

Most likely the template package is not able to install the VS extension (a vsix file) that contains the templates.

- Make sure your Visual Studio is setup to be able to use .NET Framework 4.8. This is a requirement and the extension will not install without it.
- Install the templates again. Exit Visual Studio then use this command in PowerShell: choco install Alkami.SDK.Templates -f
- If they still do not show up, then go to the C:\ProgramData\chocolatey\lib\Alkami.SDK.Templates\tools directory and double-click on the vsix file to launch the extension installation. You can view the installation in progress and if it fails you can look at the log file to determine why.NoteOne of the more obscure conditions is that in some cases (notably when using the Community Edition of Visual Studio 2017), a required file c:\Program Files(x86)\Microsoft Visual Studio\Installer\vswhere.exe might not exist. Rerunning the Visual Studio installer is enough to fix it. Launching the installer will perform an update to the installer code, and one of the things it does is install the missing vswhere.exe file. After that file exists, you should be able to install the Alkami template packages.
### Troubleshooting problems that keep Microservices from starting

Usually the problem is related to the Alkami.Services.Subscriptions.Host service not running. Unless the Subscriptions service is running properly, most of the other Alkami services, and your custom services, will either fail to start or fail to remain running.

- Go into the Services control panel and see if Alkami.Services.Subscriptions.Host is running. If it is not running then try to start it. You can also use PowerShell and try the command start-servicesonly which will attempt to start the subscriptions service, and then all of the other Alkami services.If the Subscriptions service will not start, or will not stay running, then you can try to reinstall the Subscriptions service. Use this command in Powershell running as Administrator: choco install Alkami.Services.Subscriptions.Host -f

If you still have problems or the problem returns, then you probably do not have the required ports reserved as instructed on the SDK.

### Issue

Browser is throwing a 500 error when you go to https://developer.dev.alkamitech.com (https://developer.dev.alkamitech.com) and the C:\Orblogs\Alkami.Client.WebClient.log file keeps repeating this error. You have checked that all the IIS Application Pools are running and verified http://localhost/STSConfiguration/ (http://localhost/STSConfiguration/) is reachable and not throwing any errors.

```
2020-06-17 09:42:49,875 |*| 17 |*| FATAL |*| Alkami.Client.WebClient.GlobalApplication |*| (null) |*| (null) |*| (null) |*| (null) |*| Unable to retrieve BankId. Returning null
System.ServiceModel.EndpointNotFoundException: There was no endpoint listening at net.tcp://stsconfiguration/STSConfiguration/STSConfiguration.svc that could accept the message. This is often caused by an incorrect address or SOAP action. See InnerException, if present, for more details.
```

#### Fix

This is typically due to Net TCP not listening on port 808. Kill any occupying process task and then restart the Net TCP Port Sharing Service, Net TCP Listener Adapter, and the Windows Process Activation Service.

```
netstat -oan | findstr ":808" | % { Get-Process -ID $_.Substring($_.Length-7).Trim() }
```

If your output is anything else but these process names, kill the process.

```
#Handles NPM(K) PM(K) WS(K) CPU(s) Id SI ProcessName
#------- ------ ----- ----- ------ -- -- -----------
# 563 27 36024 38260 0.39 25820 0 SMSvcHost
# 1892 98 1376840 628556 348.73 5068 0 tomcat8.exe.x64
# 563 27 36024 38260 0.39 25820 0 SMSvcHost
# 1892 98 1376840 628556 348.73 5068 0 tomcat8.exe.x64
# 2666 298 355456 367484 9.94 20088 0 w3wp
```

Note: The previous netstat command will also return processes using port 8080 (and anything else that begins with 808) so you might want to use the following to get a list of ones you don't need to worry about.

```
netstat -oan | findstr ":8080" | % { Get-Process -ID $_.Substring($_.Length-7).Trim() }
```

Use this command to kill the process or use Task Manager.

```
taskkill /f /pid 12345
```

Restart the Net TCP services.

```
restart-service @("WAS") -Force
```

### Issue

Services, especially Subscription Service, will throw errors about not connecting to Redis. This will stop all other services from working as well, since they can't connect to the Subscription service. This can be caused by missing or misconfigured redis and database connection strings. Both are listed here.

Fix

Each C:\Windows\Microsoft.NET\Framework64\v4.0.30319\Config\machine.config has a section that must be added that looks like this below. If it's missing, or if it does not match, then please update it to look like this.

```
<connectionStrings>
<add name="AlkamiMaster" connectionString="data source=localhost;Integrated Security=SSPI; Database=AlkamiMaster" providerName="System.Data.SqlClient" />
<add name="RedisSetting" connectionString="redis-18620.redis.corp.alkamitech.com:18620,keepAlive=60,password=gamehendge2020" />
</connectionStrings>
```

### Issue

I'm not able to manually change the service user name and password under the Properties>Logon page of my locally running microservices.

#### Fix

If the text boxes are not able to be edited, the service is in a managed state. Run this command to allow the service logon to be edited:

```
sc.exe managedaccount "My.Service.Name" False
```
