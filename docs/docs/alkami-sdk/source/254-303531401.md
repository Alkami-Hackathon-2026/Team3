This guide will provide a high level overview on how you can migrate your current project to Vue 3. For a detailed description on how to convert your Vue app you could read up on the Migration Build Documentation (https://v3-migration.vuejs.org/migration-build.html).

## Upgrade Tooling

The first step is to migrate from the Albus Vue Preset to the Albus Vue 3 Preset. This migration comes with many benefits other than just the migration.

```
npm uninstall @alkami/albus-module-cypress @alkami/albus-preset-vue
npx -y shx rm -rf node_modules package-lock.json
npm install @alkami/albus-cli@latest @alkami/albus@latest @alkami/albus-preset-vue3@latest @alkami/orb-layout-mock@latest --save-dev
```

## Update Configuration

In the albus.config.js the vue property will need to be updated to vue3.

In the tsconfig.json the extends property value will need to be updated to ../node_modules/@alkami/albus-preset-vue3/configs/tsconfig.json

In the vue-shim.d.ts you will need to replace it with the following content:

```
declare module '*.vue' {
import Vue from 'vue';
export default Vue;
}

// makes Vue Module reference the Migration Build Version
declare module 'vue' {
import { CompatVue } from '@vue/runtime-dom';
const Vue: CompatVue;
export default Vue;
export * from '@vue/runtime-dom';
const { configureCompat } = Vue;
export { configureCompat };
}
```

## First Build

Try building your widget using albus:

```
npx albus b -C Alkami.Widget.Client
```

At this point, your application may encounter some compile-time errors / warnings (e.g. use of filters). Fix them first. If all compiler warnings are gone, you can also set the compiler to Vue 3 mode or go straight to updating the dependencies as your widget should nearly be releasable.

## Configuring Vue 3 Mode

In the albus.config.js under the vue3 pluginConfiguration, the property vueCompatMode: '3'

In the app.ts add the following code:

```
import {configureCompat, createApp} from 'vue';
...

configureCompat({ MODE: 3 });
```

After fixing the errors, the app should be able to run if it is not subject to the limitations (https://v3-migration.vuejs.org/migration-build.html#known-limitations) mentioned in the migration build such as dependency issues.

You will likely see a LOT of warnings from both the command line and the browser console. Here are some general tips:

- You can filter for specific warnings in the browser console. It's a good idea to use the filter and focus on fixing one item at a time. You can also use negated filters like -GLOBAL_MOUNT.
- You can suppress specific deprecations via compat configuration.
- Some warnings may be caused by a dependency that you use (e.g. vue-router). You can check this from the warning's component trace or stack trace (expanded on click). Focus on fixing the warnings that originate from your own source code first.
- If you are using vue-router, note <transition> and <keep-alive> will not work with <router-view> until you update Vue Router.

Update <transition> class names. This is the only feature that does not have a runtime warning. You can do a project-wide search for .*-enter and .*-leave CSS

Update app entry to use new global mounting API. It may look like this afterwards:

```
import {configureCompat, createApp} from 'vue';
import App from './App.vue';

void (async () => {
configureCompat({ MODE: 3 });

const app = createApp(App);

if (process.env.NODE_ENV === 'development' && process.env.ALBUS_LOCAL_DEV === 'cypress') {
const { setup } = await import('./tests/e2e/setup')
await setup();
}

app.mount('#app');
})();

```

## Update Dependencies

If you are using any dependencies then those will need to be updated or replaced. This may not be an exhaustive list.

### Iris Vue

Currently not compatible with Vue 3. If you widget utilizes this library you will need to wait to upgrade.

### Vue Router

Vue Router used to be built into the vue preset. Since not all widgets are using is we have removed it in favor of the widget owning its dependencies. Install the package using the following:

```
npm install vue-router@4
```

Update your Router according to the Migrating from Vue 2 Guide (https://router.vuejs.org/guide/migration/index.html). It probably will look something like this code snippet afterwards:

```
import {createRouter, createWebHistory} from 'vue-router';

// ONLY the entry point or global views should be imported in this way.
import Dashboard from '../views/Dashboard.vue';

const isMobile = location.pathname.toLowerCase().startsWith('/mobile');

const routes = [
{
path: '/',
name: 'dashboard',
component: Dashboard,
},
{
path: '/task/:taskId',
name: 'task',
component: () => import('../views/Task.vue'),
},
{
path: '/:pathMatch(.*)*',
redirect: '/',
},
];

const router = createRouter({
routes,
history: createWebHistory((isMobile ? '/Mobile/' : '/') + 'Example/'),
});

export default router;
```

### Vuex

Pinia (https://pinia.vuejs.org/) is the new preferred store but Vuex (https://vuex.vuejs.org/) is still being maintained.

#### Just updating Vuex

To upgrade to Vue 3 you will need to update Vuex as it was removed from the preset in favor of the widget owning its dependencies.

```
npm install vuex@4
```

Update your Vuex according to the Migration Guide (https://vuex.vuejs.org/guide/migrating-to-4-0-from-3-x.html) or look at this Code Example (https://github.com/vuejs/vue-hackernews-2.0/commit/5bfd4c61ee50f358cd5daebaa584f2c3f91e0205)

#### Updating Vuex to Pinia

```
npm install pinia@latest
```

Update your Store according to this Migration Guide from the Pinia Documentation (https://pinia.vuejs.org/cookbook/migration-vuex.html)
