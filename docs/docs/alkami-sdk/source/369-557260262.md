## Overview

Client redirects allow SSOs hosted in iframes to navigate users to a different page within online banking in response to events sent from the SSO itself.

Note: this could in theory work for new windows on desktop and mobile web, but due to limitations on native that make it impossible, we do not officially support it.

##

## Configuration

The configuration for redirects lives entirely in the widget settings for the SSO. No changes or values are required in the JSON SSO configuration.

Note: The SSO must be using the "inline" display method

Widget Setting Name: ClientRedirects

Value: List of ClientRedirect objects. No limit on number of redirects

ClientRedirect Schema

```
{
"$schema": "http://json-schema.org/draft-07/schema#",
"title": "ClientRedirect",
"description": "Represents a client redirect configuration for SSO",
"type": "object",
"properties": {
"EventName": {
"type": "string",
"description": "The name of the event that triggers the redirect"
},
"Origin": {
"type": "string",
"description": "The origin URL for the redirect"
},
"WebDestination": {
"type": "string",
"description": "The destination URL path for web-based (desktop or mobile web) redirects"
},
"NativeDestination": {
"type": "string",
"enum": ["Accounts", "LastPage"],
"description": "The destination for native app redirects"
}
},
"required": ["EventName", "Origin", "WebDestination", "NativeDestination"],
"additionalProperties": false
}
```

### Description of values
- EventNameThis is the string that will be sent by the SSO in the message that identifies to desired redirect. Can be any string value and is case insensitive.
- OriginThe event origin host (no protocol or subpath) used the verify origin of message. If being sent from https://www.ssourl.com/sub/route, you would put "www.ssourl.com". Case insensitive.
- WebDestinationLocation in OLB to send user to if on desktop or mobile web. Subpath only. For example, use "/MyAccountsV2", not https://www.bankurl.com/MyAccountsV2. Will properly prepend "/Mobile" and leading slash if needed.
- NativeDestinationLocation in native app to send user to.Supported Values:Accounts - App homeLastPage - Closes sso and returns user to prior page
### Example Configuration
Example configuration

```
[
{
"EventName": "redirectToDashboard",
"Origin": "www.ssourl.com",
"WebDestination": "/DashboardV2",
"NativeDestination": "LastPage"
},
{
"EventName": "redirectToAccounts",
"Origin": "www.ssourl.com",
"WebDestination": "/MyAccountsV2",
"NativeDestination": "Accounts"
}
]
```

## Implementation by SSO vendor

Messages should be sent to the iframe parent using window.parent.postMessage (https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage (https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)). The data should be just the event name defined in the configuration and the target should be the entire url of the sso widget.
