### Description

The Alerts Microservice acts as a proxy to the Notifications Microservice. It's purpose is to take care of a lot of the common code that all alerts require, such as resolving contactIds to email/sms/push contacts and logging details of the alert that has been sent for reporting purposes.

### Account Types

The different types of alert category are used for reporting purposes. Most of the alert types require the same information to be provided, but a couple have some additional data that is useful for reports, such as an AccountId or a TransactionId.

AccountAlert - The alert relates to general information at the account level, and is not specific to a single transaction

BillPaymentAlert - The alert relates to the user's bill payment payees or scheduled payments to payees

BudgetAlert - The alert relates to a budget configured for an account

GeneralAlert - The alert relates generally to the institution as a whole, and does not necessarily specifically apply to the user who receives it

SecurityAlert - The alert relates to the user's security authentication credentials or authorization permissions

ThirdPartyAlert - The alert relates to a condition generated by a third-party alert provider, where the way to review or resolve the alert's issue cannot, or may not always, be handled in a base system user interface component or widget.

TransactionAlert - The alert relates to a specific transaction within a single account

UserAlert - The alert relates to the user as a whole, and not to any specific account or transaction

### Alert Properties
#### Payload

This is the object that will be used as the model for your alert. It should be the same type as the object that was used when the template was being registered.

#### TemplateName

This is the name of the template that you want to use to send the alert. The template needs to be registered with the Notifications Microservice prior to use by the Alerts Microservice.

#### OriginatorName

The name of the service/widget etc that is sending the alert.

#### DestinationUserId

The UserId of the user who should receive the alert. If need to provide either the DestinationUserId or the DestinationUserIdentifier, but not both.

#### DestinationUserIdentifier

Ther UserIdentifier of the user who should receive the alert. If need to provide either the DestinationUserId or the DestinationUserIdentifier, but not both.

#### ContactIds

The contactId(s) that the alert should be sent to.

#### FallbackToPrimaryEmail

If no contactIds are provided, or all of the contactIds are invalid, then send the notification to the user's primary email address. This is useful if you want to ensure that the alert is always sent to at least one of the user's contact methods.

#### TemplateTransformType

The transform render type to use. This allows the user to select which type of template to use in the event that a template for the provided templateName exists for both transform types (i.e. On-line Banking Access Alert Template for Razor AND XSLT).

#### AlertDate

The DateTime when the alert was generated in UTC time.

### AlertType Specific Properties

Some alert types have additional properties that are used for reporting purposes.

#### Additional AccountAlert Properties

AccountId - This is the accountId of the account that this alert relates to

#### Additional AccountAlert Properties

TransactionId - This is the transactionId of the transaction that this alert relates to
