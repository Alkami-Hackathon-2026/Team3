If you are building a Vue application, this preset will handle compiling and optimizing your application's JavaScript produced from your Vue template files. This preset does a number of things:

- Precompiles Vue templates using the single file component syntax
- Optimizes output by splitting code into shared chunks
- Pulls out the CSS embedded in components and puts it in a separate file
- Minifies the resulting file(s)
- (optional) Autoinjects script tags into a cshtml file based on the resulting chunks from the webpack process
### Installation

To install this preset along with Iris Vue, use the following commands:

```
npm install @alkami/albus-preset-vue --save-dev
npm install @alkami/iris-vue --save-dev // Install as a dev dependency and use for unit tests only. See setup instructions below for setting up the iris-vue cdn links in your project.
```

#### Additional Requirements

This preset has additional file requirements. Either run albus catalyst or manually create them (/spaces/SDKC/pages/303531407/Additional+Files).

If you are using TypeScript:

- tsconfig.json
- tslint.json

If you are using SCSS:

- postcss.config.js
- .browserslistrc

All of these files go into the solution's root.

#### Including Vue and Iris Vue Libraries

As part of the webpack configuration, Albus strips out the vue, vuex, and vue-router libraries. These will need to be included in your .cshtml view file depending on which libraries you need.

To load in Iris Vue, install the Alkami.WebAssets.Helpers (https://packagerepo.orb.alkamitech.com/feeds/nuget.dev/Alkami.WebAssets.Helpers) package locally.

Then, reference the Iris Vue css and javascript helper methods to load in Iris Vue via the CDN. For more information, refer to the Alkami.WebAssets.Helpers docs (https://confluence.alkami.com/display/UDT/Including+Iris+Vue+in+your+widget).

See the example below for loading in both Vue and Iris Vue into your project:

index.cshtml

```
// Required in WebClientAdmin
@using Alkami.Client.Framework.Utility
@using Alkami.Client.WebClient.Shared.Helpers

// Desktop
@section StyleSheetContentPlaceholder {
@* Load Iris Vue stylesheets *@
@Html.IrisVueLinksSnippet()
}

@section JavaScriptIncludeContentPlaceHolder {
@Html.ScriptWithCacheExpiration("~/lib/vue/vue.runtime.min.js")
@Html.ScriptWithCacheExpiration("~/lib/vuex/vuex.min.js")
@Html.ScriptWithCacheExpiration("~/lib/vue-router/vue-router.min.js")

@* Load Iris Vue component library *@
@Html.IrisVueScriptsSnippet()
}

// Mobile
@section StyleSheets {
@* Load Iris Vue stylesheets *@
// For mobile, pass the 'device: "mobile"' named argument/value to load in mobile specific shim file
@Html.IrisVueLinksSnippet(device: "mobile")
}

@section BodyScripts {
@Html.ScriptWithCacheExpiration("~/lib/vue/vue.runtime.min.js")
@Html.ScriptWithCacheExpiration("~/lib/vuex/vuex.min.js")
@Html.ScriptWithCacheExpiration("~/lib/vue-router/vue-router.min.js")

@* Load Iris Vue component library *@
@Html.IrisVueScriptsSnippet()
}
```

Additionally, Vue devtools only work with the unminified version of the library. If directly including the references like this, you will only be able to access the dev tools by turning off the ForceUseOfProductionAssetsInDebug config setting found in the web.config file of WebClient. If you would like an automatic way of enabling this based on an environment variable, please see the Advanced Configuration section below.

### Plugins

This preset only has one plugin that runs all of the compilation and tasks needed for compilation: webpack.

#### Webpack

The webpack plugin is the crux of this preset and handles everything from compiling TypeScript and SCSS, pre-compiling the .vue template files, splitting out code into optimized chunks, and the minification of all output artifacts.

Default configuration

```
'webpack': {
autoInject: null, // See autoinject configuration section below
config: {}, // Custom webpack config that overrides the default
deploy: null, // Where to deploy the resulting files to
entry: { // Register main application files (e.g., app.ts)
app: path.resolve('<projectNamespace>/Scripts/app.ts')
},
outputPath: { // Configure output directory of resulting files
js: path.resolve('<projectNamespace>/Scripts/'),
css: path.resolve('<projectNamespace>/Styles/'),
}
// Only used for leveraging JavaScript testing (see accompanying docs for more info)
testConfigPath: path.resolve(path.join(__dirname, '../../configs/jest.config.js')),
}
```

### Configuration

If there is only one file that is the root of your application (and you don't want to leverage the autoinject functionality), you can name it app.ts, place it in your <projectNamespace>/Scripts folder and everything will immediately begin compiling and outputting as expected.

With a setup like this, the only thing that needs to be in your albus.config.js file are the tokens that albus needs:

Basic Configuration

```
module.exports = {
tokens: {
projectNamespace: 'Alkami.Apps.WidgetName',
orbWidgetName: 'WidgetName'
}
}
```

#### Multiple Entry Points

Many times you will need to slightly configure Webpack, particularly if you have multiple entry points in your application (e.g. a mobile and desktop TypeScript file). For this type of setup, we can leverage the entry configuration option exposed in the preset to add additional files or just to specify a different name other than app.ts.

Start by creating a configuration object for the Vue preset and add an entry object like this:

Entrypoint Configuration

```
entry: {
desktop: './Scripts/main.ts',
mobile: './Scripts/Mobile/main.ts',
}
```

Let's break down what this configuration is doing. entry maps to the Webpack configuration (https://webpack.js.org/concepts/entry-points) of the same name. This tells webpack where to find the starting files that will import all additional dependencies.

In the entry object, the key is the "entry name" that will be used throughout the compilation process and "entry path" is how Webpack will find the files in your widget.

Full Multiple Entry Point Config

```
module.exports = {
tokens: {
projectNamespace: 'Alkami.Apps.Widget',
orbWidgetName: 'Widget'
},
presets: ['vue'],
presetConfiguration: {
'vue': {
plugins: ['webpack'],
pluginConfiguration: {
'webpack': {
entry: {
desktop: './Scripts/desktopScriptName.ts',
mobile: './Scripts/Mobile/mobileScriptName.ts',
},
},
},
},
},
};
```

Entry name

For clarity, your "entry name" and file names can be whatever you want. This is just a way for webpack to internally name the files that it is compiling. desktop and mobile are not required nor reserved.

#### Autoinject Functionality

In addition to compiling and bundling your Vue application, this preset also has the ability to split your code into logical chunks to optimize the performance and loading of the assets. While this is not required, it is highly recommended for a performant and efficient widget.

The way this works is that Webpack examines your entry files and identifies the vendor files (those that are imported from the node_modules folder) and common chunks (code that is shared across multiple entry points). After that examination, Webpack will compile those files and produce the necessary assets. The naming convention for the resulting files is:

<type>~<entry_name(s)>.min.js

A few example file names are:

- common~desktop.min.js,
- common~desktop~mobile.min.js
- vendors~desktop.min.js,
- vendors~desktop~mobile.min.js

By dynamically splitting out chunks we can always optimize our application and its loading at compile time, which means we always output the most performant and logical code chunks. This introduces a new challenge though, how do you add references to your view file if you don't know which files will be outputted at compile time?

To solve this issue, we leverage Webpack to inform us of what chunks were outputted and give it a cshtml template file to inject the scripts into. To do this, we need to add an autoInject key to the albus configuration which will automatically add the necessary plugins to the webpack config and let our injection plugin know where to inject the references.

To begin, let's look at the albus config first:

Autoinject Configuration

```
autoInject: [
{
chunks: ['desktop'],
htmlFilePath: '<projectNamespace>/Views/index.desktop.cshtml',
htmlTemplateFilePath: '<projectNamespace>/Views/index.desktop.template.cshtml',
},
],
```

autoInject is an array of "templates" that webpack will inject the resulting chunks into. There should be an object for each of the entries you have configured. There are three properties that need to be set:

- chunks - This filters out the resulting chunks and makes sure to only inject the files that are associated with an entry point. The value is a string and matches the name of an entry. Taking the example from above, desktop is one of our entries and will be injected into the index.desktop.template.cshtml file.
- htmlFilePath - This is the path and file name of where the template file will be outputted to with the references injected.
- htmlTemplateFilePath - This is the path of where webpack can locate the template that will have references injected into.

With our configuration complete for the inject functionality, we also have to add an "injection point" in our template files that lets webpack know where to put the script references. To do this, we need to add an html comment into those template files.

For widgets on the Alkami platform, make sure to put these inside of the script sections in your cshtml files.

Template CSHTML file

```
<!-- Desktop -->
@section StyleSheetContentPlaceholder{
<!-- css:inject:start -->
<!-- css:inject:end -->
}

@section JavaScriptIncludeContentPlaceHolder {
@Html.ScriptWithCacheExpiration("~/lib/vue/vue.runtime.min.js")

<!-- js:inject:start -->
<!-- js:inject:end -->
}

<!-- Mobile -->
@section StyleSheets {
<!-- css:inject:start -->
<!-- css:inject:end -->
}

@section BodyScripts {
@Html.ScriptWithCacheExpiration("~/lib/vue/vue.runtime.min.js")

<!-- js:inject:start -->
<!-- js:inject:end -->
}
```

Once that is done and you have run npx albus transmute check the resulting cshtml file and you should see something like this:

Generated CSHTML file

```
@section StyleSheetContentPlaceholder{
<!-- css:inject:start -->
@Html.CssWithCacheExpiration("/Areas/Widget/Styles/app.min.css")
<!-- css:inject:end -->
}

@section JavaScriptIncludeContentPlaceHolder {
@Html.IncludeSiteTextScript()

<!-- js:inject:start -->
@Html.ScriptWithCacheExpiration("/Areas/Widget/Scripts/vendors~desktop~mobile.min.js")
@Html.ScriptWithCacheExpiration("/Areas/Widget/Scripts/vendors~desktop.min.js")
@Html.ScriptWithCacheExpiration("/Areas/Widget/Scripts/desktop.min.js")
<!-- js:inject:end -->
}
```

Full Autoinject Configuration

```
module.exports = {
tokens: {
projectNamespace: 'Alkami.Apps.Widget',
orbWidgetName: 'Widget'
},
presets: ['vue'],
presetConfiguration: {
'vue': {
plugins: ['webpack'],
pluginConfiguration: {
'webpack': {
entry: {
desktop: './Scripts/main.ts',
mobile: './Scripts/Mobile/main.ts',
},
autoInject: [
{
chunks: ['desktop'],
htmlFilePath: './Views/index.desktop.cshtml',
htmlTemplateFilePath: './Views/index.desktop.template.cshtml',
},
{
chunks: ['mobile'],
htmlFilePath: './Views/index.mobile.cshtml',
htmlTemplateFilePath: './Views/index.mobile.template.cshtml',
},
],
},
},
},
},
};
```
