Most SDK projects will need to access one of more of the common services that are built into the Alkami platform. This page gives a list of the services or features we see used most often and examples or how you can use them too.

### Common Services And Features

How do I...

- Get a list of accounts for the current user
- Read settings in my Widget
- Read settings in my provider service
- Get the name or TaxId of the current user
- Get the address, email, or phone numbers for the current user
### Get a list of accounts for the current user

To do this you will make a call to the Security microservice. Add the following Nuget packages (and their dependancies) to your project and follow the example below:

Alkami.MicroServices.Security.Client

Alkami.MicroServices.Security.Contracts

example code

```

// Create a request object to send to the security service
GetUserRequest userRequest = new GetUserRequest();

// "augment" the request. You can manually populate the userid, etc.
// or if you are calling from a microservice then use CopyBaseFrom()
userRequest.CopyBaseFrom(request);

SecurityServiceClient SecurityService = new SecurityServiceClient();

// you must have a filter. If getting the accounts for a specific user
// your filter will just need the user's identifier
userRequest.Filter = new UserFilter() { UserIdentifiers = new List<Guid>() { request.UserIdentifier.Value } };

// you also must have a mapper. To have the accounts returned from the call,
// specify ShouldIncludeUserAccounts = true
userRequest.Mapping = new UserMapper() { ShouldIncludeUserAccounts = true };

// we only expect a single user with its accounts to be returned.
userRequest.MaxResults = 1;

// here'e the actual call to the security service
GetUserResponse userResponse = await SecurityService.GetUserAsync(userRequest);

var users = userResponse.Users;
Logger.DebugFormat("{0} user accounts returned in the payload.", userResponse.Users.Count);
List<UserAccount> accounts = users.FirstOrDefault().UserAccounts;

// If you want to filter the accounts based on relationship or other permissions, do this
List<long> accountIds = new List<long>();
foreach (var ua in accounts)
{
//0 = Unknown
//1 = Primary Owner - The user of the account is considered the primary owner of the account.
//2 = Joint Owner - The user of the account is considered the joint owner of the account.
//3 = Linked - This account has been granted access indirectly. The user is not a joint or a primary user, but has been granted some level of permission on this account.
//4 = Aggregated - This account has been granted access indirectly from a remote aggregation provider. The user may be a primary or joint owner, but the relationship in the remote host
//5 = Business account - This account has been granted access by virtue of the entity to which this user belongs.

if ((ua.Relationship <= 2 || ua.HasMasterRights) && !ua.Deleted && !ua.HideFromEndUser)
{
accountIds.Add(ua.AccountId);
}
}

// If you need more details on the accounts, then call the Accounts Microservice and pass in the account id values you filtered and added to accountIds above

```

### Read settings in a Widget

The MyMoney client Widget found in C:\AlkamiSDK\Samples\MyMoney\ClientWidget has an example of reading from WidgetSettings. It also shows how to write UserWidgetSettings if that functionality is needed in your project.

Read settings from within a microservice

A detailed example of a "Provider Based Service" can be found at My First Microservice (/spaces/SDKC/pages/67617391/My+First+Microservice) . Follow this pattern to create a microserivce that can read from configurable settings that are managed using the admin site and stored in the database.

### Get the name of the current user

From within a Widget, your controller (if properly inheriting from the Alkami BaseController) will contain an object named "CurrentUser." Among the properties on this object you will find the user's name. For Example

firstName = CurrentUser.FirstName;

lastName = CurrentUser.LastName;

ssn = CurrentUser.TaxId;

### Get the address, email, or phone numbers for the current user

From within a Widget you can use the use the CurrentUser object mentioned above to get contact information for the current user. This information is pulled from the core system and cached in the Alkami database tables. A single method can be used for three different contact types (address, email, phone) by specifying the proper generic type. Users can have multiple addresses (home, mailing, work), multiple phone numbers (home, work, mobile), if supported by your core system, therefore the returned value will be a list of user contact objects. Here are three example:

CurrentUser.GetUserContact<UserContactAddress>()

CurrentUser.GetUserContact<UserContactPhone>()

CurrentUser.GetUserContact<UserContactEmail>()

Refer to the sample Widget found at C:\AlkamiSDK\Samples\Widgets\Sample.Client.Widget.ChangeAddress
