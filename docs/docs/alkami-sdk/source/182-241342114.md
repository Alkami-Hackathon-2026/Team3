TITLE: Updating Your Local Navigation Builder Configurations
PARENT: How-to Articles
UPDATED: 2024-08-19

Currently Nav Builder is not available in the local SDK so in order to add widgets to the default configurations you will need to open each configuration and manually add the widget entries.

The configurations are minimized by default which will make editing a little unpleasant. In order to get around this install the JSTool plugin in Notepad++ and use the JS Format option to beautify the configuration.

The parent folder for the navigation configurations is "C:\Orb\WebClient\s3\navigations". Under this folder you will have one folder, two if you have a stage match. You can determine which configuration belongs to which site by referencing the folder name (GUID) against the BankInstanceIdentifier column in the AlkamiMaster.dbo.Tenant table.

Now that you know which configuration set that you need to modify there are a couple more levels of child folders to consider. The next level down is the FlavorId (Package) and by default it is for the Adults package in DeveloperDynamic. You will need to update this folder name to the package the test user(s) is assigned. If you want to create configuration sets for another package duplicate the folder "3107" and its contents and rename to the FlavorID(s) listed for your test user(s).

The final folder level is for locale. We have only included English (1033) but you can add additional locales as you wish by duplicating this folder and renaming it to the correct LocalId. This is where you will grab the configuration file for the specific display/device type for editing.

In this first example we have added the MyMoney widget to the "Accounts" section in the desktop.json configuration.

The menu item that is added to "Accounts" section contains 3 properties: DisplayName, WidgetName and URL.

- DisplayName is what will be displayed in the drop down menu
- WidgetName is name that coincides with the WebClient\Areas folder for the widget
- URL is the relative pathing to the widget

In this second example we created a new section named "USBFI" to contain all of the widgets that are being tested in the local SDK.

The section that was added after the "Tools" menu contains 4 properties: DisplayName, Description, Icon, SectionItems

- DisplayName is what will be displayed in the header
- Description is descriptive text displayed below the DisplayName in the pop down menu
- Icon isn't currently showing
- SectionItems contains the links to the widgets/components

You will follow this same pattern for editing each configuration. The configurations are different between the display/device types so individual SectionItems can be copy/pasted between but the entire json cannot. You can however copy configuration sets between flavors and locals to speed editing if they are the similar to make editing the configurations faster.
