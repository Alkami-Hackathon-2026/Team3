## Overview

There are a few issue types specific to the SDK that you can use to manage and track your Alkami SDK work. The below sections will discuss these types and when to use them. Each developer should have access to their Client Services or Delivery project within the Alkami JIRA system in order to create and edit the issue types below.

## Alkami's JIRA System

Alkami uses a distributed JIRA Server to maximize availability and scalability, but the browser interface is no different than the classic JIRA Server. If you are not familiar with JIRA, please visit the Atlassian site and go through their JIRA Software (https://www.atlassian.com/software/jira) pages. For more detailed information, there is a great tutorial at Guru99: JIRA Tutorial: A complete guide for beginners (https://www.guru99.com/jira-tutorial-a-complete-guide-for-beginners.html)

## SDK Issue Types
### SDK Submission

The submission issue type is used to submit a Chocolatey package to Alkami's SDK team. This package will be reviewed and a deployment time will be scheduled upon approval.

| Field | Value Description |
| Summary | The summary should contain at minimum the package name and version. Any additional information that is helpful to the reporter may be added when necessary |
| SDK Component Type | This is a select box that will define what type of project you are submitting. The most common type is "Widget" or "Microservice" but can also be a "Provider," "Snippet," or "Repository" |
| FI Contact and FI Contact Info | Financial Institution Contact and Financial Institution Contact Info are two fields that should be filled out a point of contact (usually the reporter of the issue, but can be someone else) and a way to contact that person in case of escalation or unexpected issues. The info can be a telephone or email. |
| Package URL | This is the URL of the hosted package the developer would like to deploy. More information on how to find this URL can be found on the Add a package to your development feed guide.Warning!If the URL is malformed, or incorrect in any way, the submission will be canceled by Alkami's automation and a new submission will be required. |
| Scheduled Release Time | This is a field populated by Alkami's automation and will be the point of reference for when the deployment will be processed. If this time does not work, or needs to be changed, please reach out to the SDK team by commenting on the submission. |
### SDK Support Incident

Any questions regarding SDK development, deployment, general information, or anything at all relating to the SDK and/or an issue with SDK, should be submitted to Alkami as an SDK Support Incident. The SDK team will be happy to help open any additional support tickets required to get the information asked for.

| Field | Value Description |
| Summary | Provide a brief statement about the nature of the issue. |
| Description | Provide a detailed explanation of the support issue that needs to be resolved. The more information the better! When applicable, screen shots and detailed steps of how to recreate the issue is extremely helpful. Logs and stack traces are also helpful when dealing with issues related to the SDK run time platform or individual components.Please limit all tickets to one issue. This will allow the SDK team to focus on that specific issue as well as maintain more specific historical data within the ticket.Warning!Support incidents lacking proper details, or vague context, will require the SDK team to ask for more information. Make sure the information provided in the description is as detailed and nuanced as possible so that the SDK team can begin to resolve the issue as quick as possible. |
| FI Contact and FI Contact Info | Financial Institution Contact and Financial Institution Contact Info are two fields that should be filled out a point of contact (usually the reporter of the issue, but can be someone else) and a way to contact that person in case of escalation or unexpected issues. The info can be a telephone or email. |
