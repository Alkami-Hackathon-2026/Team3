The Widget Header is a set of components to help introduce a widget to the user and provide upfront navigational aid and call to action.

The Widget Header is composed of three pieces:

- Title - Used to describe the Widget's function
- Navigation - Help the user access all the branches of functionality in the widget
- Actions - Provide widget wide actions that a user can take. e.g. 'Add Payee' action in Bill Pay.

There are a couple of ways to control these Widget Header elements.

1) Refer the the SDK sample at C:\AlkamiSDK\Samples\Widgets\Sample.Client.Widget.CustomCssAndJs and you will fine examples of simple CSS changes that can be used to hide these elements.

2) Programmatically by following the instructions below.

### Usage

In the Widget Header's most simple form, you may not have to interact with these components at all. The components try to determine the information they need on initialization. You might need to provide new Widget actions or custom navigation.

The backbone of using these components are the events that are triggered. You will see these examples favor using the events over using the global entries available. The instance of the WidgetHeaderService can also be found at Alkami.WidgetHeader if you find it necessary to use it.

widgetHeaderInitBefore and widgetHeaderInitAfter gets fired on the header element which can be referenced by Alkami.WidgetHeader.headerElement but for brevity and more portable code, we will use the fact that events bubble up to document.

You will also want to initialize the events outside of any ready function or DOMContentLoaded event. There is a possibility to miss these events otherwise.

Here are some basic usage examples.

#### Update the Widget Title. (also known throughout the SDK as the widget's "DisplayName")

We will use the widgetHeaderInitAfter event so that we know the header information was fully initialized.

```
document.addEventListener('widgetHeaderInitAfter', function(event) {
const service = event.detail;
const header = service.header;

header.title = 'My Custom Title';
});
```

#### Add a new Navigation Item

```
document.addEventListener('widgetHeaderInitAfter', function(event) {
const service = event.detail;
const header = service.header;
const NavigationItem = service.NavigationItem;

/* Add custom navigation for widget */
const navigationItem = new NavigationItem({
title: 'Custom Tab',
url: 'Widget/Custom/Path'
});

header.navigation.append(navigationItem);
});
```

#### Add a new Widget Action

We will use widgetHeaderInitBefore event because action items don't need anything from header info.

```
document.addEventListener('widgetHeaderInitBefore', function(event) {
const service = event.detail;
const header = service.header;
const ActionButtonItem = service.ActionButtonItem;

/*add our new Action Item */
const actionItem = new ActionButtonItem({
iconName: 'dollar',
buttonId: 'money_making_action_item'
});

actionItem.element.addEventListener('widgetActionItemActivated', actionItemActivatedHandler);
header.actions.append(actionItem);
});

function actionItemActivatedHandler(event) {
// Give our users a message.
alert('step 3: Profit!');
}
```

#### Prevent System Content pull

There may be a reason to fully own the Widget Header by your widget. Potentially you are an unregistered SSO widget that is just iframing stuff in. In this case you can opt out of the round trip to the server.

```
document.addEventListener('widgetHeaderInitBefore', function(event) {
const service = event.detail;
service.preventDefaultFetch = true;

/* update your header yourself here */
});
```

#### Using Widget Header in a SPA

A more advanced use case of the Widget Header is to handle when one is building a single page application (SPA) style widget completely with javascript. The Widget Header provides hooks to do such a thing.

Since the navigation items must be backwards compatible with the standard widget, you must pass in an option to any new navigation Item preventClick: true to keep from making a full page refresh.

Doing this also enables two events attached to the Widget Navigation element, widgetNavigationItemActivated and widgetNavigationItemSelected. You will need to handle the selection of the tabs yourself. This is useful when you have a need for building the UI dynamically. When a user clicks on a tab, a widgetNavigationItemActivated event will fire that you can subscribe to. If everything is successful then you will want to select that navigation item. Subscribing to the widgetNavigationItemSelected event allows you to display the view and fire any async calls you might need to make.

Here is an example of how one might setup their Widget Header for a SPA.

```
const routes = [
{ title: 'Item 1', url: '/Widget/Item1'},
{ title: 'Item 2', url: '/Widget/Item2'},
{ title: 'Item 3', url: '/Widget/Item3'}
];

// If you want full control over your Widget through the frontend,
// you will want to prevent System Content pull and set your own title
document.addEventListener('widgetHeaderInitBefore', function (event) {
const service = event.detail;
const header = service.header;

service.preventDefaultFetch = true;
header.title = 'My Groovy SPA';
})

document.addEventListener('widgetHeaderInitAfter', function(event) {
const service = event.detail;
const header = service.header;
const navigation = header.navigation;
const navigationElement = navigation.element;
const NavigationItem = service.NavigationItem;

routes.forEach(function (route) {
const navigationItemOptions = Object.assign({ preventClick: true }, route);
navigation.append(new NavigationItem(navigationItemOptions));
});

navigationElement.addEventListener('widgetNavigationItemActivated', ItemActivatedHandler);
navigationElement.addEventListener('widgetNavigationItemSelected', ItemSelectedHandler);
});

function ItemActivatedHandler(event) {
const navigation = event.detail.navigation;
const navigationItem = event.detail.navigationItem;

// Dynamically build any UI needed here...

navigation.selectedItem = navigationItem;
}

function ItemSelectedHandler(event) {
const navigationItem = event.detail.navigationItem;

// Display new view here...

alert(navigationItem.id + ' Selected.');
}
```

### API
#### Widget Header Service

This is used to control and clear storage of Widget Header data.

The Widget Header Service is available through Alkami.WidgetHeader. Events also contain a reference to the instance and are the preferred way to interact with the Widget Header Service.

##### Events
###### widgetHeaderInitBefore

widgetHeaderInitBefore fires just before the widget header is initialized with data. The header will not contain any internal navigation, title or actions at this time. This is the perfect time to interact with the service or add new action items.

event.detail - A reference to the WidgetHeaderService instance

###### widgetHeaderInitAfter

widgetHeaderInitAfter fires after the widget header is initialized with data. The header should be fully saturated at this point. This is the time to set your own title, add your own navigation, or to interact with any system initialized Action Items such as the Articles Action Items.

event.detail - A reference to the WidgetHeaderService instance

##### Constructors

ActionButtonItem - constructs a new WidgetActionButtonItem, the preferred way to introduce a new Action Item.

ActionItem - constructs a new 'WidgetActionItem', for advanced Action Item creation.

NavigationItem - constructs a new WidgetNavigationItem, the preferred way to introduce a new Navigation Item.

##### Properties

currentWidgetName - string - the current system name for the widget. Usually synonymous to the Area folder your widget lives in. This is used to fetch the cached information from local storage.

header - WidgetHeader instance of Widget Header that was created when the service is initialized.

headerId - string - reference to the header element ID. Use when you need to fetch the element such as when attaching event listeners. document.getElementById(Alkami.WidgetHeader.headerId)

preventDefaultFetch - boolean - prevent default header initializing behavior. Use this during the widgetHeaderInitBefore event to totally own the initializing of the header yourself. Default value is false.

##### Functions

fetchHeaderInfo() - Promise<WidgetHeaderInfo>- Get information about the header from the client. Used internally to initialize the header.

storeHeaderInfo(widgetHeaderInfo) - void - cache the information about the header in local session storage.

resetHeaderInfoStorage() - void - clear the cache of stored header info.

initHeader() - void - responsible to initializing the header and it's navigation as well as providing event hooks for the initializing process. Runs when DOM is ready.

#### Widget Header Component

Widget Header is a component abstraction of the markup used to define the Widget Header and provides an api to do the most common place things such as updating title, navigation, and action items.

The Widget Header instance can be access globally through Alkami.WidgetHeader.header or preferably through one of the events defined by the Widget Header Service.

##### Properties

actions - WidgetAction - get a reference to the WidgetActions instance.

element - HTMLElement - get the HTML element that the WidgetHeader is bound.

navigation WidgetNavigation - get a reference to the WidgetNavigation instance.

title - string - gets or sets the title of the Widget.
NOTE: we do not support custom HTML via this property and reserve the right to make breaking changes to those that use innerHTML

#### Widget Navigation

Widget Navigation is a component abstraction of the markup used to define the tab navigation and provides an api to manipulate and attach Navigation Items.

##### Events
###### widgetNavigationItemActivated

widgetNavigationItemActivated fires when a tab has been activated by a click or keypress. This is where you will need to wire up logic to your custom navigation items to load and make selected in a spa setting.

event.detail - provides access to both the navigation component and the activated navigation item.

- navigation - WidgetNavigation - reference to the WidgetNavigation instance.
- navigationItem - WidgetNavigationItem - reference to the WidgetNavigationItem that was activated.
###### widgetNavigationItemSelected

widgetNavigationItemActivated fires when navigationItem.selected = true; has been called.

event.detail - provides access to both the navigation component and the activated navigation item.

- navigation - WidgetNavigation - reference to the WidgetNavigation instance.
- navigationItem - WidgetNavigationItem - reference to the WidgetNavigationItem that was selected.
##### Properties

element - HTMLElement - get the HTML element that the WidgetNavigation instance is bound to.

items - WidgetNavigationItem[] - get an immutable array of the WidgetNavigationItems.

length - number - get the amount of WidgetNavigationItems contained in the navigation.

selectedItem - WidgetNavigationItem - set or get the selected WidgetNavigationItem.

##### Functions

append(widgetNavigationItem,...) - void - append 1 or more WidgetNavigationItems to the navigation.

getItem(index) - WidgetNavigationItem - get the WidgetNavigationItem at the specified index.

getItemIndex(widgetNavigationItem) - number - get the index of a specified WidgetNavigationItem in the navigation.

insert(widgetNavigationItem, index) - void - add a WidgetNavigationItem into the specific index.

prepend(widgetNavigationItem,...) - void - prepend 1 or more WidgetNavigationItems to the navigation.

refreshUI(rebuildList) - void - refreshes UI elements to match the navigation control. rebuildList is a boolean that controls rendering the WidgetNavigationItem UI.

remove(widgetNavigationItem) - void - remove a WidgetNavigationItem from the navigation.

#### Widget Navigation Item

Widget Navigation Item is a component abstraction of the markup for the tab navigation item and provides an api to manipulate that navigation.

##### Constructor

**NavigationItem(options) - creates a new WidgetNavigationItem The constructor can be referenced from the service emitted from the event or globally from Alkami.WidgetHeader.NavigationItem.

The following options are available:

Required

- title - string - text displayed in the navigation
- url - string - url for the navigationItem.NOTE: for backwards compatibility this must be set and unique in the navigation list or you need to set the id option

Optional

- id - string - id to use for navigationItem. The default is generated from the url.
- preventClick - boolean - prevent the default action of the click. This is useful for SPA applications.
##### Properties

element - HTMLElement - get the HTML element that the WidgetNavigationItem instance is bound to.

id - string - get the id of the element.

linkElement - HTMLElement - get the link element inside the the WidgetNavigationItem.

selected - boolean - set or get the selected state of the WidgetNavigationItem.

title - string - set or get the text displayed in the navigation. NOTE: we do not support custom HTML via this property and reserve the right to make breaking changes to those that use innerHTML

#### Widget Actions
##### Properties

element - HTMLElement - get the HTML element that the WidgetActions instance is bound to.

items - WidgetActionItem[] - get an immutable array of the WidgetActionItems.

length - number - get the amount of WidgetActionItems contained in the actions component.

##### Functions

append(widgetActionItem,...) - void - append 1 or more WidgetActionItems to the actions component.

getItem(index) - WidgetActionItem - get the WidgetActionItem at the specified index.

getItemIndex(widgetActionItem) - number - get the index of a specified WidgetActionItem in the actions component.

insert(widgetActionItem, index) - void - add a WidgetActionItem into the specific index.

prepend(widgetActionItem,...) - void - prepend 1 or more WidgetActionItems to the actions component.

refreshUI() - void - refreshes UI elements to match the actions control.

remove(widgetActionItem) - void - remove a WidgetActionItem from the actions component.

#### Widget Action Button Item

Widget Action Button Items are used to wrap up the most common use case of an Action Item, adding a button. It provides an event that provides the Action Item instance for you to utilize.

Widget Action Button Item Extends Action Button Item so all properties from there is also available.

##### Examples

See Widget Actions Examples

##### Events
###### widgetActionItemActivated

widgetActionItemActivated fires when an action button has been activated.

event.detail - provides access to the action Item that was activated.

- actionItem - WidgetActionButtonItem - reference to the WidgetActionButtonItem instance.
##### Constructor

ActionButtonItem(options) - creates a new WidgetActionButtonItem The constructor can be referenced from the service emitted from the event or globally from Alkami.WidgetHeader.ActionButtonItem.

The following options are available:

- buttonId - string - id to use for the button element inside the WidgetActionItem.
- containerId - string - id to use for the WidgetActionItem container element that wraps the button
- href - string - if the button is just a link, provide a href.
- iconName - string - the Icon Name from the Iris Icons. e.g. class name minus font-icon-.
- text - string - if text is needed in the button, provide this option.
- buttonAttributes - Object - a map of HTML attributes needed to be added to the button. e.g. {'title': 'My Title', 'aria-label': 'label me please!'}
##### Properties

buttonElement - HTMLElement - get the underlying button HTML element.

buttonId - string - get or set the id of the button.

containerElement - HTMLElement- get the container Action Item HTML element. Same as calling element.

containerId - string - get or set the container Action Item element id. same as calling id.

element - HTMLElement - get the container Action Item HTML element. Same as calling containerElement.

id - string - get or set the container Action Item element id. same as calling containerId.

visible - boolean - get or set the visibility of the Action Item.

#### Widget Action Item

Widget Action Items are a thin wrapper around elements to put into the Action bar. This provides a consistent API to interact with those elements. In most use cases you will want to use the Widget Action Button Item instead unless you know what you are doing and it's a special component.

##### Constructor

ActionItem(element: HTMLElement) - creates a new WidgetActionItem from the HTML element provided. The constructor can be referenced from the service emitted from the widgetHeaderInitBefore or widgetHeaderInitAfter event or globally from Alkami.WidgetHeader.ActionItem.

##### Properties

element - HTMLElement - get the container Action Item HTML element.

id - string - get or set the container Action Item element id.

visible - boolean - get or set the visibility of the Action Item.
