### Get-SDKSupport function is not present.

If the client runs Get-SDKSupport and they receive the following error.

```
Get-SDKSupport : The term 'Get-SDKSupport' is not recognized as the name of a cmdlet, function, script file, or
operable program. Check the spelling of the name, or if a path was included, verify that the path is correct and try
again.
At line:1 char:1
+ Get-SDKSupport
+ ~~~~~~~~~~~~~~
+ CategoryInfo : ObjectNotFound: (Get-SDKSupport:String) [], CommandNotFoundException
+ FullyQualifiedErrorId : CommandNotFoundException
```

Have the client run the following command in an admin powershell window and attach the results.

```
clist alkami -lo
```

The best fix for this issue is to upgrade to the latest Alkami.Powershell.SDK version.

```
choco upgrade Alkami.Powershell.SDK -y
```

### Reset an SDK Developer's Machine Feeds for Support

If the developer needs to have their password reset or the nuget feeds are missing from Visual Studio the following command set can be used to reset/add those feeds.

```
nuget sources remove -name "Alkami Dev"
nuget sources remove -name "Alkami Third-Party"

New-SDKMachineSetup
```

The New-SDKMachineSetup command will prompt the developer for their username, which will be their email address for non-alkamists and their feeds password. This command does more than just reset/add the feeds but those are beyond the scope of this solution.

### Dev Admin Inaccessible (Stack trace showing System.Memory assembly)

Sometimes an SDK environment has been updated so many times over the years that an accumulation of extra DLLs and other files will end up in the webclientadmin/bin and webclient/bin folder. If old copies of DLLs that do not have the version number in the filename are found in both the shared folder and in the webclient and webclientadmin bin folders you will have problems.

With the 2022.6 SDK upgrade these two files were found to be a problem. Ensure that a newer version is in the shared folder and then remove then from c:\orb\webclientadmin\bin.

### Submissions service will not start due to "Access is denied" error

The first thing that needs to be checked in the Application log in the Event Viewer. Based on what is found in the logs the solutions will be listed below

##### TCP port 50001 is being used by another application.

This is due to the port reservations not being in place before the installation of the SDK. This could happen with a fresh install or after a hard reset of the SDK, Remove-SDK -Hard.

1. Run netstat -ano | findstr 50001 in Powershell and get the PID of the application using the port.

2. Open task manager and search for that PID and kill the process. You may also want to check to see if there is something using port 12345 and terminate that process as well.

3. Once that process has been stopped run the commands below in Powershell.

netsh int ipv4 Add excludedportrange protocol=tcp startport=12345 numberofports=2
netsh int ipv4 Add excludedportrange protocol=tcp startport=50000 numberofports=30

You should now be able to start the subscription service.

### Alkami Service running under "Local System" instead of "Local Service"

Recently there was an issue with an FI developer machine where they could not log into the member site. This particular situation resulted in an error in the Alkami.Microservices.Authentication.Workflow.Service.Host.log shown below

Screenshot

The cause of this was the service running under the incorrect user, Local System.

Without knowing the password for Local Service, which is not known to the SDK team, but is probably some Microsoft default password you should follow the steps below.

Run clist <service name> -lo to get the current installed version of the service. Obviously replace <service name> with name or part of the name of the actual service in question, clist workflow -lo was used.

Once you have the version you will need to remove the service from the registry by running Invoke-SCExe @('delete', $service). In this instance $service was changed to 'Alkami.Microservices.Authentication.Workflow.Service.Host'. Yes the single quotes are required, Invoke-SCExe @('delete', 'Alkami.Microservices.Authentication.Workflow.Service.Host').

Delete the package folder from the C:\ProgramData\chocolatey\lib parent folder.

Reinstall the package, choco install Alkami.Microservices.Authentication.Workflow.Service.Host --version 1.33.1 -y.

After the pack is reinstalled open the services panel and set the startup mode to Automatic and start the service. As with any Alkami service please wait 30 seconds to 1 minute for the service to register with the Subscriptions service.

### Numerous Alkami services will not start and present an "Access is Denied" error

If there are multiple services that will not start and the subscription service is running please check the NetTcpPortSharing service. We have had instances where that service for one reason or another would not start properly. If the NetTcpPortSharing service will not start it will need to be uninstalled from Windows Features followed by a reboot of the system. After the system comes back up the NetTcpPortSharing service will need to be reinstalled in Windows Features followed by a reboot. After this second reboot the services should start. If you notice that not all Alkami services, excluding radium, are started run Restart-SDKServices.

#### Incorrect registration fields showing

Correct fields configured in the Alkami Stage environment:

#### Unable to complete member registration after correctly locating member record on the core

After successfully locating a member on the core the attempted registration fails showing the screen below.

You will need to open the Alkami.MS.Registration.Service.Host log to investigate. If there is an error similar to the one listed below you will need to verify the correct registration providers are in place.

{"@t":"2025-10-20T20:21:45.7380149Z","LogMessage":"Error when trying to create user on IDP for ***********","Message":"Error when trying to create user on IDP for ***********","LogLevel":"Error","SourceContext":"Alkami.MS.Registration.Management.Service.RegistrationManagementService"

```
select * from core.[Provider] prov
```

```
GETUTCDATE())
SET @ProviderID = (SELECT TOP 1 ID FROM core.Provider WHERE Name = 'Alkami Static Registration Service')
END

DECLARE @ItemID BIGINT = (SELECT TOP 1 ID FROM core.Item WHERE ItemType = 'Connector' AND ParentId = @ProviderID)

BEGIN
INSERT INTO [core].[Item]
([ItemType],
[ParentId],
[SecondaryId],
[Name],
[CreatedUtc],
[Version],
[Deleted])

@ProviderID,
@BankID,

```
