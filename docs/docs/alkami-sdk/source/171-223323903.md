This tutorial describes what the SSO (Single Sign-On) provider service is and how to create a service using Alkami's Visual Studio template.

Developers use SSO Provider services to define configurable settings and their Single Sign-On implementation. Widgets can use these services to automatically log in logged in users to other associated applications or domains. Manage the settings from Alkami's Admin Portal. To do this, go to the Setup menu and select Integration Settings>Providers. Admin users can manage those settings without requiring code changes.

## The Alkami SDK Template

The SDK template will create a structured Visual Studio solution with the generic SSO Host project.

### Install the Template

Close Visual Studio

The choco installer will run the VisualStudioInstaller.exe in the background. This requires any current running instances of Visual Studio to be closed.

```
choco install Alkami.SDK.Templates -y
```

### Create the Service

The SDK template will create a structured Visual Studio solution with the generic SSO Service Host project. This project will have all the required method implementations to stand up a custom SSO service using Alkami's standard contracts and data objects.

Run As Administrator

Visual Studio must run as an Administrator to attach to the debug process when running the service.

- Open Visual Studio and on the Create a new project dialog, search for SSO to find the SSO Provider template.
- Select the Alkami Generic SSO Service template and click Next.
- Name the project per the Microservice Coding Guidelines page. This example uses USBFI.MS.MyCustomSSO.
- Select a path close to the root of the C:\ drive. Click Create.

### Build the solution

Feed Authentication

Visual Studio will most likely prompt for user credentials to authenticate with the feed server. The credentials are the same set used for https://feeds.alkamitech.com/ (https://feeds.alkamitech.com/feeds/choco.dev).

To get access, see Getting Started with Alkami's SDK - Do I have Access? (https://confluence.alkami.com/display/SDKC/Getting+Started+with+Alkami%27s+SDK)

- By default the Service.Host will be the Startup Project. If it is not, right-click the project and select Set as StartUp project.
- Build the solution to restore the NuGet packages and create a Debug build of the service.
### Configure the service
- To insert the service configuration into the DeveloperDynamic database, locate the insert_provider_setting.sql in the Service.Host project and open it with a SQL engine.
- Run the script.Submit ConfigurationsThe SQL script is provided for local development only. You will need to submit a Provider Configuration ticket to the SDK team to have these values added to stage and production environments.
### Run and Test the Service

Alkami Subscription Service

The Alkami.Services.Subscriptions.Host must be running to debug this project.

- Open the Service project and place a break point on the first line of of the SsoServiceImp.GetOptions() method in the SsoServiceImp.cs class.
- Run (F5) the solution in Visual Studio (as Administrator). This opens a cmd.exe window that encapsulates the Host project to make debugging easier. See Topshelf's documentation page for more information about this strategy. A console window is running the service and a solid red break point is in the GetOptions() public method.
#### Alkami Micro Service Tester

To exercise and test the service, use Alkami's Micro Service Tester (https://feeds.alkamitech.com/feeds/choco.dev/Alkami.MicroServiceTester/).

```

```

- After installation, open the Windows Start Menu and search for microservicetester.
- From the left pane, double-click a service to view the available contract methods.
- Select a contract method.In this example, we will select GetOptions.
- Click Send Message. The tester will send a request and the code execution will pause on the break point in the GetOptions() implementation method.

#### Unit Tests

NUnit 3 Test Adapter

Download and enable the NUnit 3 Test Adapter in Visual Studio to run the tests. See NUnit 3 Test Adapter (https://marketplace.visualstudio.com/items?itemName=NUnitDevelopers.NUnit3TestAdapter) for more information.

### SSO Provider Contracts

The following NuGet packages provide the Alkami standard SSO contracts:

- Alkami.MicroServices.SSOProviders.Contracts
- Alkami.MicroServices.SSOProviders.Service.Client
#### Service contract

This is the contract that your SSO service has to implement.

ISsoProvidersContract

```
public interface ISsoProvidersContract
{
//Get SSO options list
Task<GetOptionsResponse> GetOptions(GetOptionsRequest request);
//Get SSO information
Task<GetSsoResponse> GetSso(GetSsoRequest request);
//Determine which provider to call, and if it's found, i.e., can process SSO requests
Task<CanProcessResponse> CanProcess(CanProcessRequest request);
}
```

#### Request object contracts

These are the request object contracts that you must use in your service

SsoBaseRequest

```
public class SsoBaseRequest : BaseRequest
{
public long? ProviderId { get; set; }
public string ProviderKey { get; set; }
}
```

CanProcessRequest

```
public class CanProcessRequest : SsoBaseRequest { }
```

GetOptionsRequest

```
public class GetOptionsRequest : SsoBaseRequest
{
public IDictionary<string, string> Parameters { get; set; }
}
```

GetSsoRequest

```
public class GetSsoRequest : SsoBaseRequest
{
public IDictionary<string, string> Parameters { get; set; }
public Guid? AccountIdentifier { get; set; }
public string ClientIpAddress { get; set; }
}
```

### Response object contracts

These are the response object contracts that you must use in your service

SsoBaseResponse

```
public class SsoBaseResponse : BaseResponse
{
public long ProviderId { get; set; }
}
```

CanProcessResponse

```
public class CanProcessResponse : SsoBaseResponse
{
public bool CanProcess { get; set; }
}
```

GetOptionsResponse

```
public class GetOptionsResponse : SsoBaseResponse
{
public IDictionary<Guid, string> Parameters { get; set; }
}
```

GetSsoResponse

```
public class GetSsoResponse : SsoBaseResponse
{
public string Url { get; set; }
public IDictionary<string, string> Parameters { get; set; }
public DisplayMethod DisplayMethod { get; set; }
}
```

### Update SsoServiceImp

The methods are stubbed out with minimal information and example values. At a minimum, the GetSso and GetOptions methods must be updated to properly build a custom SSO URL.

- Update the SsoServiceImp.cs so that the service retrieves an SSO URL per specifications provided by your SSO vendor.
- Recompile the solution and use the Tests project to verify that the URL, DisplayMethod, and any additional info in Parameters is returned as expected.
- Run the service and test it using Alkami Microservice Tester application.
### SSO Troubleshooting

Confirm that the service has been implemented according to the SSO provider specification. Verify that the options (implemented as settings) have correct values.

##### Explore Logs to Investigate the Error
- Contact the provider regarding any Unauthorized, Access Denied, or File Not Found errors.
##### If a Certificate (Thumbprint) is Needed

Logs will likely indicate if there is a problem with the certificate.

Example error

"Certificate named '57315D3356625180E1204D88FCB2B07A228EB7E0' was not found in Personal Store Local Machine"

- Confirm that the certificate is installed and not expired.
- Verify that appropriate permissions have been given for the private key.
##### Verify that the Base URL is Valid

If you receive an error stating that the site can’t be reached, there is likely a problem with the URL.

Verify that the Base Url is reachable: copy the Base URL from the provider settings and paste it into the browser.

If you can connect to the site, the URL is probably fine, even if you receive an error once. It might be expecting parameters, credentials, or a certificate that would be sent through the SSO.
