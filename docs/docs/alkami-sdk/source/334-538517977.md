Analytics events can be sent to your Alkami Firebase project to track user behavior, metrics, and errors.

The best methods for using Firebase are demonstrated on the Analytics Example page.

#### Firebase Dashboard Permission

Access to Firebase dashboards can be granted to a user by request. An email address and a desired user role (owner, editor, viewer) is necessary.

#### Accessing Firebase from Flutter Platform

Alkami's Flutter Platform package provides access to its Firebase instance via its core dependencies.

import 'package:flutter_platform/alkami_core_dependencies.dart';

#### Analytics vs Crashlytics

Analytics events are used for long-term, low-stakes metrics tracking. Analytics events appears in Firebase after a long enough time has passed or a great enough volume of similar events have been logged.

Crashlytics events are intended to be used for tracking errors, both fatal and non-fatal. They include a stack trace and appear in Firebase more quickly and with more granular detail than typical analytics events.

If a crash occurs within Alkami Embedded, a Crashlytics event will be logged automatically.

#### Debugging Analytics events

Firebase doesn't allow simple debugging of incoming events. It can be achieved by configuring environment variables on the native level. Firebase documents the methods for doing so.

Debugging events in Firebase using the Debug View (https://firebase.google.com/docs/analytics/debugview?sjid=770057769933645615-NA)

See more in analytics_example.dart.
