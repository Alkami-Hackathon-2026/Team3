Albus provides various commands that enable you to work with front end assets via the Albus presets that are installed.

For all of the commands listed here, you will need to use npx (https://www.npmjs.com/package/npx) in front of each of the commands.

CLI usage

```
Usage: albus <command> [options] or
albus <presetName> <scriptName>

Commands:
albus scry Information about your project
[aliases: info, v]
albus catalyst [orbWidgetName] Initialize your project.
[clientFolderName] [areaFolderName]
[projectNamespace] [aliases: init, i]
albus transmute Build your project.
[aliases: build, b]
albus saturate Deploy your project
[aliases: deploy, d]
albus substantiate Test your project [aliases: test, t]
albus evaporate Clean your project
[aliases: clean, c]
albus panopticon Watch changes in your project
[aliases: watch, w]

Options:
-c, --configPath Path to configuration file.
[string] [default: albus.config.js]
-h, -?, --help Show help [boolean]
-v, --version
-C, --chdir Path to working directory. [string]
-D, --debug Turns on (the much slower) debug mode. [boolean]
-S, --silent Turns off all output except errors. [boolean]
-V, --verbose Turns on all logging. [boolean]
-t, --token specify token.<key> <value> to create key value
pairs.
-p, --preset list of presets to use. [array]
-P, --prod, --production use production mode [boolean]
```

#### Catalyst (alias: init, i)

Initializes an albus project with a default setup and configuration based off the installed presets. Running it without any parameters will cause it to try and intuit them itself.

Catalyst usage

```
$ albus catalyst [orbWidgetName] [clientFolderName] [areaFolderName] [projectNamespace]
```

- orbWidgetName - This is the Name of your widget. This corresponds to the Area folder that your widget gets deployed to. *e.g. C:/orb/WebClient/Areas/**WidgetName**/*
- clientFolderName - This is most likely 'WebClient' or 'WebClientAdmin'
- areaFolderName - This is usally specified as 'Areas', though modules get installed into 'Modules' instead.
- projectNamespace - Usually something like **Alkami.Apps.WidgetName**. This corresponds to the name of the directory that your project code lives in the solution. this is only used in times when you want an entire solution to reference one project (the old way).
#### Evaporate (alias: clean, c)

Cleans the project of any generated files the enabled presets have created.

Evaporate options

```
Options:
-c, --config Path to configuration file.[string] [default: albus.config.js]
-h, -?, --help Show help [boolean]
-v, --version Show version number [boolean]
-C, --chdir Path to working directory. [string]
-D, --debug Turns on (the much slower) debug mode.
[boolean] [default: false]
-S, --silent Turns off all output except errors. [boolean] [default: false]
-V, --verbose Turns on all logging. [boolean] [default: false]
```

#### Panopticon (alias: watch, w)

#### Saturate (alias: deploy, d)

Deploys all files as configured in the Albus and preset configurations.

Saturate options

```

-c, --configPath Path to configuration file.
[string] [default: albus.config.js]
-d, --deployPath Override the deploy path defined in the
configuration. [string]
-f, --force, --redeploy Force the deploy of all files instead of checking for
newer. [boolean]
-h, -?, --help Show help [boolean]
-v, --version Show version number [boolean]

-V, --verbose Turns on all logging. [boolean]
-t, --token specify token.<key> <value> to create key value
pairs.
-p, --preset list of presets to use. [array]
```

#### Scry (alias: info, v)

Gives detailed information about albus and it's presets. Albus' diagnostic tool when trying to understand issues.

Scry options

```
Options:
-c, --config Path to configuration file.
[string] [default: albus.config.js]
-C, --chdir Path to working directory. [string]
```

Substantiate options

```
Options:
-c, --configPath Path to configuration file.
[string] [default: albus.config.js]
-h, -?, --help Show help [boolean]
-v, --version
-C, --chdir Path to working directory. [string]
-D, --debug Turns on (the much slower) debug mode. [boolean]
-S, --silent Turns off all output except errors. [boolean]
-V, --verbose Turns on all logging. [boolean]
-t, --token specify token.<key> <value> to create key value
pairs.
-p, --preset list of presets to use. [array]
-P, --prod, --production use production mode [boolean]
-w, --watch Watch tests for changes. [boolean]

-g, --coverage Provide Code Coverage statistics. [boolean]

tests (requires albus-module-cypress) [boolean]
```
