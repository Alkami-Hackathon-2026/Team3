## Bumping Your Widget Version

When you submit a widget through the SDK, Alkami checks the version against everything that's been submitted before. Duplicate versions are rejected. If your submission fails because the version already exists, you need to bump the version and resubmit.

There are two files to update. They need to stay in sync.

### Files to update
#### 1. sem.ver

Lives at the root of your widget project. Small JSON file with the semantic version split into Major, Minor, and Patch:

```
{
"Version": {
"Major": 1,
"Minor": 0,
"Patch": 0
}
}
```

#### sem.ver
#### 2. Properties/AssemblyInfo.cs

Same version, expressed as the .NET assembly version and file version:

```
[assembly: AssemblyVersion("1.0.0.0")]
[assembly: AssemblyFileVersion("1.0.0.0")]
```

The .NET format has a fourth segment (revision). Leave it at 0 unless you have a specific reason to change it.

AssemblyInfo

### Which number to bump

Follow semantic versioning (https://semver.org/):

- Major — Breaking changes. The widget's contract changed in a way that isn't backward compatible.
- Minor — New functionality added in a backward-compatible way.
- Patch — Bug fixes and small tweaks. No new features, no breaking changes. For most resubmissions (small fixes, config corrections, retrying after a failed submission), bumping the patch is the right call.
### Example

You're resubmitting a widget with a bug fix. Current version is 1.2.3. Bump the patch to 1.2.4.

sem.ver:

```
{
"Version": {
"Major": 1,
"Minor": 2,
"Patch": 4
}
}
```

Properties/AssemblyInfo.cs:

```
[assembly: AssemblyVersion("1.2.4.0")]
[assembly: AssemblyFileVersion("1.2.4.0")]
```

Rebuild the project, then resubmit.

### Common mistakes
- Updating sem.ver but forgetting AssemblyInfo.cs, or vice versa. Both files need to change.
- Reusing a version you've submitted before. The check looks across all prior submissions, not just the most recent. Going backwards or sideways won't work either.
- Forgetting to rebuild after changing AssemblyInfo.cs. The version baked into the compiled DLL is what gets checked at submission time, so an un-rebuilt project will submit with the old version.
