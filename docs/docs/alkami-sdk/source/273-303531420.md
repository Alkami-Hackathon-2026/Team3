When building widgets on the Alkami platform there are many times that a JavaScript file will have dependencies from other files. The best example of this is a utilities file with some business logic in it (e.g. formatting currency) that needs to be used across multiple files. Previously you would either have to include that as another script tag in your page, or bundle the files together into a single file.

This solution presents a few issues. First, if you refactor your code and a code block is no longer used, it will still be in the resulting bundle. Second, in order to get the proper TypeScript typings requires manually writing a definition file that describes those functions in other files.

This preset is a modern implementation of code bundling, utilizing Webpack to automatically analyze the code entry points and perform the correct bundling as needed for your files. Additionally because you are now able to use the import syntax, the typings and unused code removal happens seamlessly in the compilation steps. This preset does a handful of things:

- Bundles all code needed for a given file to function
- Removes any unused code blocks
- Allows the use of ES6 import syntax for dynamic inclusion of code from other files
- Minifies the resulting file
### Installation

To install this preset use the following command:

```
$ npm install @alkami/albus-preset-webpack --save-dev
```

#### Additional Requirements

This preset has additional file requirements. Either run albus catalyst or manually create them (/spaces/SDKC/pages/303531407/Additional+Files).

If you are using TypeScript:

- tsconfig.json
- tslint.json

If you are using SCSS:

- postcss.config.js
- .browserslistrc

All of these files go into the solution's root.

### Plugins

This preset only has one plugin that runs all of the compilation and tasks needed for compilation: webpack.

#### Webpack

The webpack plugin is the crux of this preset and handles everything from compiling TypeScript, splitting out code into optimized chunks, and the minification of all output artifacts. Let's look at the configuration to see how to get things setup.

Default configuration

```
'webpack': {
config: {}, // See autoinject configuration section below
deploy: null, // Where to deploy the resulting files to
entry: { // Register main application files (e.g., app.ts)
app: path.resolve('<projectNamespace>/Scripts/app.ts')
},
// Configure output directory of resulting files
outputPath: path.resolve('<projectNamespace>/Scripts/'),
// Only used for leveraging JavaScript testing (see accompanying docs for more info)
testConfigPath: path.resolve(path.join(__dirname, '../../configs/jest.config.js'))
}
```

### Configuration

If there is only one file that is the root of your application, you can name it app.ts and place it in your <projectNamespace>/Scripts folder and everything will immediately begin compiling and outputting as expected.

With a setup like this, the only thing that needs to be in your albus.config.js file are the tokens that albus needs:

Basic Configuration

```
module.exports = {
tokens: {
projectNamespace: 'Alkami.Apps.WidgetName',
orbWidgetName: 'WidgetName'
}
}
```

#### Multiple Entry Points

Many times you will need to slightly configure Webpack, particularly if you have multiple files that need to be compiled (e.g. a mobile and desktop TypeScript file). For this type of setup, we can leverage the entry configuration option exposed in the preset to add additional files or just to specify a different name other than app.ts.

Start by creating a configuration object for the Webpack preset and set up an entry object like this:

Entrypoint Configuration

```
entry: {
desktop: './<projectNamespace>/Scripts/main.ts',
mobile: './<projectNamespace>/Scripts/Mobile/main.ts',
}
```

Let's break down what this configuration is doing. entry maps to the Webpack Configuration (https://webpack.js.org/concepts/entry-points) of the same name. This tells Webpack where to find the starting files that will import all additional dependencies.

In the entry object, the key is the "entry name" that will be used throughout the compilation process and "entry path" is how Webpack will find the files in your widget.

Full Multiple Entrypoint Configuration

```
module.exports = {
tokens: {
projectNamespace: 'Alkami.Apps.Widget',
orbWidgetName: 'Widget'
},
presets: ['webpack'],
presetConfiguration: {
'webpack': {
plugins: ['webpack'],
pluginConfiguration: {
'webpack': {
entry: {
desktop: './<projectNamespace>/Scripts/desktopScriptName.ts',
mobile: './<projectNamespace>/Scripts/Mobile/mobileScriptName.ts',
},
},
},
},
},
};
```

For clarity...

Your "entry name" and file names can be whatever you want. This is just a way for webpack to internally name the files that it is compiling. desktop and mobile are not required nor reserved.

#### Custom webpack configuration

In addition to the entry configuration alias, this preset also allows you to add any additional Webpack configuration that you want for your application. To leverage this, use the config key in the preset configuration and it will be merged with the "base" settings that comes with this preset before running the Webpack compilation. Since Webpack configuration objects are quite complex, we use a project called Webpack Merge (https://www.npmjs.com/package/webpack-merge) to make sure everything merges correctly.

Depending on the object key, different merge strategies are employed. Review the project documentation for more information.

To add your config to the Webpack config, use the config key in the albus.config.js preset settings:

Webpack Configuration

```
pluginConfiguration: {
'webpack': {
config: {
output: {
filename: '[name].[hash:8].min.js',
},
},
},
},
```

Any configuration listed in the Webpack Configuration Docs (https://webpack.js.org/configuration) is supported.

This preset also allows specifying environment specific configuration. To do that, add a key for production or development into config and it will only be merged with the corresponding environment config.

Environment Specific Configuration

```
pluginConfiguration: {
'webpack': {
config: {
development: {
output: {
filename: '[name].development.min.js',
},
},
production: {
output: {
filename: '[name].production.min.js',
},
},
},
},
},
```
