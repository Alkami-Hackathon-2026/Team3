Before we dive into the "how" of testing a Vue component, it is important to align on the philosophy of testing.

Testing a Vue component is not the same as running a UI test. It is not meant to replace the solutions like selenium or puppeteer that open a headless browser, interact with the UI, and then assert that a long chain of interactions resulted in an expected result. Instead these tests are meant to test the components as if they were a function.

In Vue, components ultimately get compiled down into functions, and just like functions a component has an interface (i.e. props) that a consumer interacts with, and methods that get called based on triggers (i.e. clicking a button, or receiving an event). These interactions is where our tests will be based in, instead of trying to render an entire page and pretending to be a user. By focusing our tests in this manner we are able to create isolated and reproducible test cases that exercise the states of a component to ensure it responds the way we expect it to.
