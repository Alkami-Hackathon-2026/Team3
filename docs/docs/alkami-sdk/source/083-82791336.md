### Step-by-step guide
#### Your first step is to identify your target users and devices.
- Which people should be able to use the Widget?
- Which devices (desktop computers, browsers on mobile phones, native IOS app users, etc.)

#### If your Widget will need to be visible on the menu to native app users:

Open a Jira ticket as described at the bottom of this page in the section How to request a Widget configuration or package setting change for a Widget. In that request you will describe exactly what you need done to install your Widget and to make it visible to the proper users and devices. For the users, you will probably be specifying the name of the package (flavor) where the Widget will be added, and whether you want the Widget added by default to new users, or favorited by default to new users who register for online banking, and whether you want the Widget added or favorited to all users who are already registered in the system. Following is some of the details you will want to consider when you make the request.

Specify the Widget Name, Widget Display Name, Description, and assembly information for the Widget.

Specify the proper value for the DisplaySettings on the Widget (Desktop, mobile, Tablet, none).

Detailed control is available regarding which native apps the Widget should be shown in. The setting that controls this is called the NativeDisplaySetting. See the following definition of the values you can select from for this field.

Values for NativeDisplaySetting

```
public enum NativeDisplaySetting
{
Unknown = 0x00,
IosPhone = 0x01,
IosTablet = 0x02,
AndroidPhone = 0x04,
AndroidTablet = 0x08,
Phone=IosPhone|AndroidPhone,
Tablet=IosTablet|AndroidTablet,
}
```

#### If your Widget will NOT need to be visible on the menu to native app users:

If your Widget will not be used in the native apps, then it is possible to self-serve to configure your Widget. (Of course you can also have Alkami do it for you – just follow the instructions at the bottom of this page. However, self-serving will allow your changes to take effect almost immediately.)

If this is a new Widget that is being deployed for the first time into the environment, then you first need to register your Widget using the Widget Settings tool in the admin site.

Login to the admin site in Stage or Prod and under the Setup menu you will find Widget Settings. (note: you can practice this in your SDK)

Select Widget Registration on the sub-menu on the left. Fill out the form using the same values that will be in the sql script you use to add the Widget to your SDK environment.

Registering your Widget as just described must be done prior to the a maintenance window (typically prior to the maintenance window when the Widget package will be deployed into the environment). This is because the DLL for the Widget will not be loaded unless the Widget configuration is already in the database prior an environment restart.

Now that your Widget is registered, you can add it to a package and create a package assignment rule to move users into the new package. Moving users into the package will cause the setting for that package to be applied to the users, such as setting the Widget to "Added" or making the Widget a "Favorite" for users.

A product guide can be found on Midas that describes in detail how this is done. See this page and download the pdf product guide.

https://community.alkami.com/customer-service-61/packages-and-automatic-package-assignment-product-guide-v2-09-636 (https://community.alkami.com/customer-service-61/packages-and-automatic-package-assignment-product-guide-v2-09-636)

If you'd like to create package assignment rules in your SDK to test this functionality, you may need to install the following chocolatey packages:

choco install Alkami.MicroServices.Rules.Service.Host

choco install Alkami.MicroServices.Rules.Package.Service.Host

choco install Alkami.MicroServices.Rules.DataSheet.Service.Host

If you do not, or cannot create a new package and rule as described in the guide, then follow the instructions at the top of this page as if you need the Widget to be on the menu in the native apps. We will need to perform a small professional services project for you to accomplish that you want to do and use an existing package.

### How to request a Widget configuration or package setting change for a Widget

Alkami has some new internal tools to take care of this type of request now. This type of request no longer requires a CCR. But there is a queue for getting this type of request completed (meaning some amount of lead time) because this work is typically completed at night, so plan ahead.

- Then open a Client Services ticket of type "Task"
- In the issue summary enter: "Request for package change"
- In the description, put in the detail information about the Widget name and the name of the package(s) where you want the Widget added. For added clarity, you can add a note that you want the Widget added for all existing users in the package as well as for new users.
- Include details to indicate whether the widget should be available to mobile users, and specific details about access in native mobile apps (IOS only? Android only? All native apps? )
- Add a comment to the ticket mentioning "@sdksupport" with the text "Please monitor this request and let me know if it looks like I entered anything that will be confusing to the TI team who will take care of it." (Do NOT add any comment that might look like the SDK team will be taking care of the request. We do not have access to execute this type of request, and adding such a comment might cause the ticket to sit unworked.)
