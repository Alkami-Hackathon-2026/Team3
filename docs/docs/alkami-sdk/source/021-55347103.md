Tip

Prior to using the Alkami SDK or coming to SDK training, Alkami highly recommends that SDK developers get some experience with their financial institution's Alkami online banking system including mobile banking. Ideally, you would do this by having an account at the FI and being enrolled in online banking. Alternatively, you could receive a comprehensive demo of the system. Being familiar with the system gives you context for the use of the SDK.

This video walks you through all the steps on this page, as well as the SDK installation that follows after you complete these prerequisites. You might find it useful to view the video as an aid while you complete the steps on this page.

Hardware Requirements

### Minimum computer and processor

The following are the minimum specifications required to run the Alkami Platform on a developer machine:

- Processor: 2.4-GHz Intel core i5 or i7 (10th generation or later) with at least 4 physical cores (e.g., i5-10200H,i5-10500, i7-10700, i7-10750H). Note: The Apple M series chips will work but you will need to follow this document.
- Memory: 32-GB 1600-MHz DDR3
- Storage: 500-GB SSD with at least 100 GB of free disk space. Alkami recommends that if local disk encryption is used, it be done in the SSD hardware, and not with CPU-based software encryption.
- Optional: Hypervisor: VMWare Workstation Pro (Windows), or VMware Fusion Professional (Mac), or Parallels Desktop (Mac). Must be within the latest two major versions. Other hypervisors might work, however, Alkami has not tested with others and might not be able to support you.

The following are sample configurations that should provide reasonable performance.

- Windows: Dell XPS 15 model 9520, i7-12700H processor, 16-GB DDR5 Memory, 1 TB M.2 PCIe NVMe SSD
- Mac: MacBook Pro (16 inch, 2019), 2.4-GHz Intel core i9-9980HK, 32-GB 2667 MHz DDR4, 500-GB+ SSD, Parallels Desktop 17 If you have Mac computer running with a M1 or M2 processor, see
### Virtual Machine

The host machine must have at least the Recommended settings to adequately run a VM for use with the Alkami SDK environment.

Important: To get adequate performance, your host computer must have a total of at least 8 threads, and a fast solid-state storage drive (SSD). If the machine lacks the recommended 8 threads, performance will suffer. The SDK virtual machine is running all three tiers of the Alkami platform and using less than the recommended number of threads will provide sub-optimal performance.

The suggested resource allocation for the VM instance running the Alkami SDK is as follows:

- 4 processor cores
- 16 GB memory
- 100 GB storage space
### One Environment Per Developer

Each developer must have their own environment to complete the SDK training and use the SDK. You can trade off different sessions of using the machine, but you cannot have more than one developer using the machine simultaneously. This is because you'll be using the Visual Studio debugger to attach to processes, and the Visual Studio debugger doesn't work well if several people are attached to processes on the same machine.

### Network Access

The SDK environment (either physical or virtual machine) will need egress access to the public Internet. If you control access each endpoint, then you must have access to the following:

- https://feeds.alkamitech.com
- https://assets.orb.alkamitech.com
- https://iris.alkamitech.com

and access to the source from which you receive Windows updates, updates to Visual Studio, and the sites to download and install the software listed later. You might also need access to reach typical top-level certificate authorities to retrieve certificate revocation lists. If you come across the need for specific other endpoints, please let us know.

Alkamists must use the packagerepo.orb.alkamitech.com (https://packagerepo.orb.alkamitech.com/) with your AD credentials instead of the feeds.alkamitech.com (http://feeds.alkamitech.com). See your SDK Admins for this access.

## Software Requirements

Important

Ensure each of these requirements are installed and configured before installing the Alkami SDK components.
### Windows 11, Server 2019, or Server 2022
- Latest update available from Microsoft
- Local user must have Administrator privileges
- You must be able to run PowerShell as admin on the machine (we have seen some cases where organizations block PowerShell by default)

Important note

If using Server 2019, you must install the Framework 4.8 developer kit from https://dotnet.microsoft.com/en-us/download/dotnet-framework/thank-you/net48-developer-pack-offline-installer (https://dotnet.microsoft.com/en-us/download/dotnet-framework/thank-you/net48-developer-pack-offline-installer)

### SQL Server 2019/2022 (Developer Edition or Enterprise Edition)

https://www.microsoft.com/en-us/sql-server/sql-server-downloads (https://www.microsoft.com/en-us/sql-server/sql-server-downloads)

- Alkami highly recommends SQL 2022. Anything earlier than SQL 2017 will not work.
- You must install a local instance of SQL
- Use the default instance during installation
- The Database Engine is the only requirement
- Use Windows Authentication (Or both Windows auth and SQL auth.)
- The user who will be using the SDK must be a sysadmin in SQL. The easiest way to ensure this is for that user to be the one who installs SQL. If another (such as IT personnel) installs SQL, make sure they add the user who will be using the SDK as a sysadmin in the SQL instance.

Important

Do not install a trial version unless you really intend to use it. (The developer edition is something different that the trial version.) You cannot use the Express or Standard editions. We have some indexing commands that use the online=on flag and this is only supported in the Developer and Enterprise editions.

### Configuring Chocolatey and NuGet Command Line

The Alkami feed sources have to be added to each of these configurations. Clients and employees have different feeds, please add the one that pertains to your role.

Alkamists must use the packagerepo.orb.alkamitech.com (https://packagerepo.orb.alkamitech.com/) with your AD credentials (username and password) instead of the feeds.alkamitech.com (http://feeds.alkamitech.com). See your SDK Admins for this access.

#### Alkami Client Configuration

```
# Add Alkami's NuGet sources
nuget sources add -name "Alkami Dev" -source https://feeds.alkamitech.com/nuget/nuget.dev -user emailAddress -password secret
nuget sources add -name "Alkami Third-Party" -source https://feeds.alkamitech.com/nuget/ThirdParty -user emailAddress -password secret
nuget sources add -name "Alkami Third-Party Core" -source https://feeds.alkamitech.com/nuget/ThirdParty-Core -user emailAddress -password secret

# Then add our Chocolatey Dev feed as a choco source, passwords with special characters will need to be surrounded in "'mypassword'" double and single quotes
choco source add -n=AlkamiChocoDev -s "'https://feeds.alkamitech.com/nuget/choco.dev'" -u="'emailAddress'" -p="'password'"
```

Note: If you ever change change your feeds credentials you will need to update the sources used by Chocolatey and NuGet with the new username or password. The following block shows how to make the updates.

```
# This is how you update the credentials for the nuget sources
nuget sources update -name "Alkami Dev" -username emailAddress -password secret
nuget sources update -name "Alkami Third-Party" -username emailAddress -password secret
nuget sources update -name "Alkami Third-Party Core" -username emailAddress -password secret

# To update credentials for the chocolatey source, you need to remove and re-add the source as follows.
$ (Make sure that your credentials are each surrounded by both single and double quotes)
choco source remove -n=AlkamiChocoDev
choco source add -n=AlkamiChocoDev -s "'https://feeds.alkamitech.com/nuget/choco.dev'" -u="'emailAddress'" -p="'password'"

```

### Reserve the TCP sockets needed for the Alkami Subscriptions service

```
# Note: Run below 2 commands to reserve specific ports.
netsh int ipv4 Add excludedportrange protocol=tcp startport=12345 numberofports=2
netsh int ipv4 Add excludedportrange protocol=tcp startport=50000 numberofports=30

# Note: Run below 2 commands to enable listening on IPv4 and IPv6 respectively
netsh http add iplisten 0.0.0.0
netsh http add iplisten ::

# Note: If this fails with an error saying that "file already exists", or "The process cannot access the file because it is being used by another process"
# it either means these commands have already been entered, or you have already installed the Alkami SDK and some of the services are running.
# If it is the latter reason, run "stop-IISandservices" and try the commands again. When you are finished enter "start-IISandservices"
```
