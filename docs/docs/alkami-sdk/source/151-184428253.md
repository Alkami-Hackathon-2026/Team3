Please note: When you use pre-compiled views, it will speed up the first-time (per each web server) you access a view after an environment restart. But perhaps the greater benefit is it greatly reduces CPU utilization on the web servers and that benefits everything on those web servers.

A video walkthrough of the steps on this page can be viewed here (https://youtu.be/C_bhc2FZBpM).

Here are steps to update widgets to pre-compile Razor views:

- Make sure all .cshtml files are included in your project's .csproj file. Otherwise, the compiler will not process those views.
- Save a copy of your widget project directory, including the bin folder. This will be a backup in case something goes wrong, and also will make it easy for you to compare the size of the Widget dll before and after the views are included into the dll.
- Install 'RazorGenerator.MsBuild' and 'WebActivatorEx' pages from the Alkami Third Party Feed (https://feeds.alkamitech.com/feeds/ThirdParty).
- Add the following line to the pre-build event of the project. This line will delete the folder for every new build in order to regenerate the compiled views.Pre-Build event command ``` if EXIST "$(ProjectDir)\obj\CodeGen\" (rmdir /s /q "$(ProjectDir)\obj\CodeGen\") ```
- Add 'exclude="**\obj\**\*.*"' as below into nuspec file. This will prevent the CodeGen folder being copied over into the nuget package.Note: The CodeGen folder contains compiled .cs view files. After the build process, since they will already be included in the output .dll, it is unnecessary to include them into the nuget package.
- Build the solution. The installed packages should now generate .cshtml.cs files from the .cshtml files in "(ProjectDir)\obj\CodeGen\" folder as part of the build process. NOTE** There should be a release folder. make sure to build in RELEASE mode
- Resolve any reference issues in the existing .cshtml files including below.HTML helper method does not contain 'Image' method with two string parameters signature. Therefore, if you have a method call such as '@Html.Image(source, alt),' replace it with a simple image tag (<img src="source" alt="alt">).If you find any reference to Alkami.Client.WebClient.Helpers.ThemeHelper let the SDK Team and we will help you determine if there is a workaround.
- Add any additional references to your project that might be needed to get the compilation to succeed. Typically you will need to add System.Web. Some projects will also need System.Core if you don't already have it included as a reference. But go ahead and compile first to see what errors you get. Tip: Close any tabs that you have open in VisualStudio to .chstml files when you compile to avoid misleading error messages related to VS not being able to syntax check file properly.
- If you are using Iris.Vue, then you will probably need to add this reference package: Alkami.WebAssets.Helpers (Specifically HtmlHelper<Model Name>' does not contain a definition for 'IrisVueScriptsSnippet' or 'IrisVueLinksSnippet')
- Once the build process succeeds, the .cshtml.cs files will have been compiled and the view code will be inside the Widget dll.
- Compare the size of the new dll to the backup you made in step #1 to make sure the new one is larger than the old one.
- Open WebClient and navigate to the widget to confirm that the views are correctly rendered and that they come up quickly.
- Important information: When you are doing your development, you will no longer be able to edit the View file in the areas folder and then simply refresh the screen to see the changes. Remember that the views are not inside the widget's dll file. If you wish to, you can open any .cshtml file in the deployed widget's area folder and delete the content (but keep the empty file). If the precompiled .cs files are correctly used to render the widget, deleting the .cshtml content should not affect the view. However, .cshtml files are still being used for the routing purpose. Therefore, deleting the .cshtml files will fail the widget.
- If you are transitioning your project to the SDK style csproj you'll need to add the following comment in your project csproj to effectively convince the precompiling logic that this is a MVC project it can update. If this is the case, add this line to your csproj. ``` <!-- System.Web.Mvc, Version=5 - This line only exists so that RazorGenerator picks this up as an MVC project --> ```
- After you have validated all of the above is complete and is working as expected to pre-compile your views, then make this change to the .csproj file. After the change, pre-compiling will only occur when you build in release mode. That way you can build in debug mode and will have the ability to edit your views in the areas folder. Before submitting to Alkami you will build in release mode (and test locally one more time!), then submit that final choco package to Alkami.

<Import Project="..\packages\RazorGenerator.MsBuild.2.5.0\build\RazorGenerator.MsBuild.targets" Condition="Exists('..\packages\RazorGenerator.MsBuild.2.5.0\build\RazorGenerator.MsBuild.targets')" />
