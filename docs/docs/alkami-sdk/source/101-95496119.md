### The Risk Workflow

When working with our risk architecture, the developer will use the Risk Evaluation Module to determine if an event requires elevation and what to present the user when requiring step-up authentication. This diagram illustrates the flow of data from the member-facing widget to the consuming risk microservices.

Configuration

Complete the MFA Product Guide (https://midas.alkami.com/product-guide/multi-factor-authentication-mfa-product-guide/) to configure the risk evaluation feature for each user, independently of the SDK.

### Use the Risk Evaluation Module

The example controller method will accept AJAX posts from the browser. The method instantiates a risk request and calls the controller extension IsAllowedByRiskEvaluation() to evaluate the action. The Alkami Risk Evaluation Web Extension (https://feeds.alkamitech.com/feeds/nuget.dev/Alkami.RiskEvaluation.WebExtension) shows the 2FA views based on the options configured by the member user.

- Use the Visual Studio NuGet Package manager to add the RiskEvaluation.WebExtension NuGet package to your widget's C# project.
- Update your .nuspec file so that your widget packages these libraries as part of your submission (the versions might be newer than the ones listed here).
- Alkami.MicroServices.Risk.Client 1.31.0Alkami.MicroServices.Risk.Contracts 1.31.0Alkami.RiskEvaluation.WebExtension 2.30.1

### Call for Risk Evaluation

Implement this code in your widget's view and it's controller. This example includes a button and some JavaScript that executes the necessary ajaxsecurepost() method to POST an action to the controller method so that the user is prompted for elevation.

```
<!--Make sure this is included in the widget view-->
@Html.IncludeSiteTextScript()
<button class="iris-button iris-button--primary" id="auth_2fa">Authorize 2FA</button>

<script>
// Store form input elements to reference later on submit
var sendAlertButton = document.getElementById('auth_2fa');

if (sendAlertButton) {
sendAlertButton.addEventListener('click', function (event) {
var success = function () {
console.log("hey now");
}
var error = function () {
console.log("oh no");
}

ajaxSecurePost("/MySDKWidget/Auth2FA", '{}', success, error, function(){}, null, 'application/json');

});
}
</script>
```

The controller code will accept this POST action and send the risk request to the risk evaluation service.

```
using Alkami.RiskEvaluation.WebExtension;
using Alkami.MicroServices.Risk.Contracts.Requests;

...

[HttpPost]
public JsonResult Auth2FA()
{
try
{
var request = new UpdateContactRiskRequest()
{
//If your widget needs to pass additional parameters to the risk evaluation microservice, you can add them to the below SessionInformation
//SessionInformation = new Dictionary<string, string>()
};

if (!this.IsAllowedByRiskEvaluation(request))
return null;

return Json(new { success = true });
}
catch (Exception e)
{
Logger.Error("Unable to Auth2FA", e);
return Json(new { success = false, error = e.Message });
}
}
```

### Complete 2FA Prompt

When escalated, you will see a prompt for the user action. In the SDK's development environment, you'll see a prompt for questions; in other environments, it might be a phone or SMS. In the development environment, the answer to these question is the last word in the written question. After completion, you will not be prompted again in this session.
