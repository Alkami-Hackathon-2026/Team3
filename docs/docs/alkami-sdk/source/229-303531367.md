The data store ,store for short, is where all the data of the application gets shared and allows various components to subscribe to changes in it. A general rule is if a piece of data is shared by more than one component it should go into the store, otherwise it should stay local to the component.

At the most basic, a store consists of an object with state, getters, and actions as properties of that object.

Store structure

```
import { defineStore } from 'pinia';

const appStore = defineStore('app', {
state: () => ({}), // Any data points to be shared across components
getters: {}, // Kind of like computed properties for state; only returns a subset of the state.
actions: {}, // Methods that ultimately end in mutating state.
});
```

Each of these properties makes up the store and used in tandem with each other. Let's take a look at each in detail to see examples of them in use.

#### State

The state property is where all shared data goes. These can be simple primitive values (e.g. boolean) or more complex ones (e.g. nested objects). Every time the store gets setup, whatever is listed in state will be created on a globally available object and accessible on every component through computed methods. This also means that default values can be selected and set in state to be available when the initial Vue instance gets created.

State Definition

```
state: () => ({
availableTenants: [] as ITenant[], // Array of Objects
colorScheme: 'light', // String
hasLoadedInitialData: false, // Boolean
selectedTenant: {} as ITenant, // Object
}),

// or use an interface

interface IMyAppStore {
availableTenants: ITenant[];
colorSchema: string;
hasLoadedInitialData: boolean;
selectedTenant: ITenant | null;
}

state: ():IMyAppStore => ({
availableTenants: [];
colorSchema: 'light';
hasLoadedInitialData: false;
selectedTenant: null;
}),

```

Things of note:

- All values must be declared with an initial state. You can't add a property after the state has been initialized
- Any value can be set as a default value when defining state
- Primitive and complex values can be set and tracked through state
- Using type casting after the value will give TypeScript support for those values used in the remaining properties
- Interfaces can be actively utilized towards state
- Alphabetizing your variables is the recommended pattern, but feel free to group properties logically as well
#### Actions

Just like the name implies, actions are a way for the store to take action and then modify state. They are the equivalent of methods in components. The most common use for this is to first make an API call to modify data in the database and then update that data in the state.

Actions Definition

```
actions: {
// Tenants
// =============================================================================
clearSelectedTenant(state) {
state.selectedTenant = {} as ITenant;
},
populateAvailableTenants(state, payload: ITenant[]) {
state.availableTenants = payload;
},
setSelectedTenant(state, payload: ITenant) {
state.selectedTenant = payload;
},

// Page Level
// =============================================================================
updateColorScheme(payload: string) {
switch (payload) {
case 'dark':
this.colorScheme = 'dark';
break;
default:
this.colorScheme = 'light';
break;
}
},
updateLoadingState(payload: boolean) {
this.hasLoadedInitialData = payload;
},
async getInitialData(context) {
const userData = await Promise.all([Api.getAccounts(), Api.getCategories()]); // Make both API calls needed for the data

// Then call mutations for each of the returning datasets
context.commit('setAccountData', userData[0]);
context.commit('setCategoriesData', userData[1]);

// Then set the selected account to the first account in the list
context.commit('selectAccount', userData[0].Checking[0]);

// Then make an additional call for the transactions and set those accordingly
const selectedAccountTransactions = await Api.getTransactions(30, userData[0].Checking[0]);
context.commit('setSelectedAccountTransactionsData', selectedAccountTransactions);
},
},
```

Things of note:

- Actions should be the only thing that modifies state
- Actions are like methods in components and can be asynchronous or synchronous
#### Getters

The getters property is filter functions for state live. Think of getters like computed values for state, performing some filtering logic on a dataset in state and returning that to a component. This can either be a hardcoded filter logic (e.g. only return credit card accounts) or something more dynamic (e.g. filter accounts that have a balance greater than the parameter passed in).

Getters Definition

```
getters: {
favoriteTenants(state) {
return state.availableTenants.filter((tenant) => tenant.isFavorite);
},
filteredTenants: (state) => (query: string) => {
return state.availableTenants.filter((tenant) => {
// If there is no query passed in, return all available tenants
if (!query) {
return true;
}

const lowerName = tenant.name.toLowerCase();
const lowerUrl = tenant.bankUrlSignatures[0].toLowerCase();
const lowerQuery = query.toLowerCase().trim();

return (lowerName.indexOf(lowerQuery) > -1)
|| lowerUrl.indexOf(lowerQuery) > -1;
});
},
},
```

Things of note:

- Getters are ways of filtering a dataset in state to return to a component
- Getters can optionally take in a parameter to be used in its computation
- Getters are always synchronous and don't wait on anything.
#### Make the store available

To get the store injected and available to the application, there are three things that need to be done.

- Tell the Vue instance to use it with the `app.use()` method
- Export the entire store from the `store.ts` file
- Import it into the main application file and register it with the main Vue instance

store.ts

```
import { defineStore } from 'pinia'

// You can name the return value of `defineStore()` anything you want,
// but it's best to use the name of the store and surround it with `use`
// and `Store` (e.g. `useUserStore`, `useCartStore`, `useProductStore`)
// the first argument is a unique id of the store across your application
export const useStore = defineStore('main', {
// other options...
})
```

app.ts

```
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'

const pinia = createPinia();
const app = createApp(App)

app.use(pinia)
app.mount('#app')
```

#### Use the store from a component

Using the store from a Vue component is simple since by injecting it into the main instance, it automatically becomes available to every child. The store can be accessed through the `this.$store` variable. Let's take a look at the various ways you can access it:

Accessing the Store

```
<template>
<div class="flex flex--wrap pad-y--xl">
<iris-chip
v-for="tenant in store.filteredTenants"
:key="tenant.id"
:label="tenant.name"
:name="'label' + tenant.id"
class="mar-right--lg"
/>
</div>
</template>
<script type="ts" setup>
import { computed } from '@vue/reactivity';
import { useStore } from './store';
import { getFilters } from './api'

const store = useStore();

function getTenantById(id): ITenant {
return store.filteredTenantsById(id); // Return the value of a getter by passing a parameter to the function
}
async function fetchPageData() {
store.getInitialData(); // Dispatch an action to be invoked in the store
}
async function fetchAvailableFilters() {
const filters = await getFilters(this.selectedTenant.bankIdentifiers[0]);
store.populateAvailableFilters(filters); // Commit an action from a component.
}
</script>
```

Things of note:

- use actions to mutate the store
- use computed properties
