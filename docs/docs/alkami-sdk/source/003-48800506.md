- To install the SDK, open PowerShell as administrator and run the following commands. ``` ## Update PowerShell's execution policy Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy Bypass -Force;Set-ExecutionPolicy Bypass -Scope Process -Force; choco install Alkami.PowerShell.Configuration Alkami.PowerShell.Database Alkami.PowerShell.Choco Alkami.Powershell.IIS Alkami.Powershell.SDK Alkami.Installer.Services -y Enable-WindowsOptionalFeature -Online -FeatureName IIS-WebServerRole Install-Nexus Install-SDKRelease -Latest ## Note: you might see some error messages related to AppPools. ## As long as the installation continues, you don't need to worry about those errors. choco install Alkami.SDK.Templates -y choco install Alkami.SDK.Samples -y winrm quickconfig ## If you have troubles getting the Alkami services to start, try a reboot before panicking and doing further troubleshooting. ```

### Upgrade the SDK Runtime

Alkami Wildcard Certificate Update

Alkami always prefers that you keep your SDK environment up-to-date. That means upgrading to version 2024.4. However, if you did not upgrade before November 2, 2024 then you must run this command to upgrade a certificate that expired on Nov 2nd.

choco upgrade Alkami.DeveloperKit.Certificates.Wildcard -y

It should install package version 1.2.11.

This is something you will do about every two or three months to bring your SDK up to the current version.

### Troubleshoot After an Upgrade

The following steps are structured to address the most common issues first and the edge case scenarios later. Anytime the SDK is not responding as expected, work through this checklist and eliminate these steps one-by-one. After you have completed these steps, if your issue is not resolved, open an SDK Support Incident ticket. For us to triage your setup, run the following command and attach the log that it creates to the ticket.

```
## Make sure that you are updated to the latest version
choco upgrade Alkami.Powershell.SDK -y

Get-SDKSupport
```

#### 1. Use the Task Manager to stop all Alkami services, then run Restart-SDKServices.

You will likely want to do this if Alkami's microservices are stuck in the Starting status, while the Alkami Subscriptions service has not been started. Remember, the Subscriptions service must be running so that all other services can properly route their messages.

To identify this, open the Services.msc application and check the state of the Alkami.Services.Subscriptions.Host. In the following screenshot, you can see a service stuck in Starting, as well as the Subscriptions service not running.

With the services in this state, complete the following steps:

- Start the Subscription service. If it starts, then go to step 3.
- If the Subscriptions service fails to start, then run Stop-SDKServices to kill all running Alkami processes.
- Run Restart-SDKServices.

After the environment is down, you can run Restart-SDKServices to restart everything.

#### 2. If you cannot reach the Login page, stop any applications that are listening to port 808

Port 808 is used by the NET TCP services. NET TCP requires port 808 to be free of any other listeners or else it will not allow IIS to run our website. Kill any occupying process task and then restart the Net TCP Port Sharing Service, Net TCP Listener Adapter, and the Windows Process Activation Service.

- Run the following command and review the output ``` Get-Process -Id (Get-NetTCPConnection -LocalPort 808).OwningProcess ```
- If your output is anything other than SMSvcHost, kill the process. ``` #Handles NPM(K) PM(K) WS(K) CPU(s) Id SI ProcessName #------- ------ ----- ----- ------ -- -- ----------- # 563 27 36024 38260 0.39 25820 0 SMSvcHost ```
- You use the taskkill command to kill the tasks, specifying the process ID. ``` taskkill /f /pid 25820 ```
- Restart the Windows Process Activation Service ``` restart-service @("WAS") -Force ```
#### 3. In the Internet Information Services Manager, confirm the Application Pools are properly setup.

In this case the login page cannot be reached. This is a less common issue and occurs when IIS is being used for non-Alkami projects. All the App Pools must have a single application except for WebClient and WebClientAdmin, which can have more than one application assigned if you're working with the ORBFX or AFX API projects.

If any other app pools have assigned applications, it can cause the service to fail.

- Select Application Pools, then select a row that has more than one Application. In this example, the Audit service has an extra application.
- In the right panel, click View Applications to open a list of applications assigned to this pool.
- In this example, the InvadingWebSite illustrates that any other service that isn't the Audit service must be assigned to another application pool or removed from IIS. To do this, you can right-click the offending row and change the application pool, or use the right panel to manage the invasive application directly. After reassigned or removed, attempt to login to the browser.
#### 4. If you cannot login, and the login page only asks for the username.

All systems should ask for the username and password on the initial page.

Confirm that the Alkami Authentication Workflow Service is running and set to automatic start mode. In older versions of the SDK this service was not required, but it is now required.

#### 5. Getting a 500 error on DashboardV2 after an update.

Run the following script against your DeveloperDynamic database (or you stage-match database):

```
update core.FlavorWidget set NativeDisplaySetting = 0 where NativeDisplaySetting is null
```

### Reset Your Development Environment

You are about to remove projects that might not be added back by the SDK machine setup. This is necessary but risky if you are not tracking your specific needs.

```
# copy the output of this command to another folder outside of C:\Orblogs
Get-SDKSupport

```

Stop IIS and Services and then complete the steps in order, killing processes where necessary to remove tied up folders that can't be deleted.

```
# as admin
Stop-IISAndServices

```

#### Soft Reset
- Run powershell command remove-sdkservices
- Delete every Alkami folder in C:\ProgramData\chocolatey\lib and all packages in lib-bad or lib-bkp directories if they exist.
- Delete C:\Orb
- Optional: Delete AlkamiMaster and DeveloperDynamic databases.If the databases are deleted or not installed, the Environment Variable Alkami_SDK_Initialization_DatabaseStandup must be deleted as well. ``` # as admin Remove-EnvironmentVariable -Key 'Alkami_SDK_Initialization_DatabaseStandup' -StoreName Machine Remove-EnvironmentVariable -Key 'Alkami_SDK_Initialization_DatabaseStandup' -StoreName Process ```

If a service is not deleted, but has been marked Disabled and is Marked for Deletion then open Task Manager > Details and end the process of the Disabled service.

If this does not work, reboot your machine so that the services are removed on machine setup.
