Before beginning a project, it helps to understand how you will integrate with Alkami.

Review the following models. When you’re ready to start your project, use the Feature Request Template to submit an SDK Project Proposal (/pages/viewpage.action?pageId=282933017).

### Standard SSO

A single sign-on (SSO) interface that uses a set of predefined fields, limited to one account at a time. This no-code approach supports connecting to several SSO protocols through a configuration script.

#### Alkami Standard SSO Configuration Tool (Jarvis)

Standard SSO provides a generic means to interact with a variety of SSOs. Review the following documentation for insight into how to construct the JSON configuration for the service.

Unless you are familiar with the SSO protocol you will implement, Alkami suggests that you ask the third party for a sample of the type of URL, request body, or assertion (if using SSAML) that you need. This helps you know what you must produce with the Alkami Standard SSO tool.

- Certificates for SAML SSO configuration in your SDKUse this example to generate a self-signed certificate to test your SAML SSO.
- Standard SSO - Expression GlossaryRefer to this for details about the built-in expressions available through configuration to the Standard SSO microservice.
- Standard SSO - Expression SyntaxUse this for general syntax rules-building expressions.
- Standard SSO - Test in SDK EnvironmentsVerify what must be installed into your SDK to test the use of Standard SSO configurations.
### SDK Widget and Microservice Integration

A widget, microservice, or provider that connects to an external system. These typically have specialized business logic that is performed prior to passing data to an external system.

Example: A custom widget with a microservice that checks account permissions before passing to an external system.

Sample: See MyMoney Sample (https://confluence.alkami.com/sdk/mymoney-sample-141531845.html).

### SDK Provider Integration

Example: A card management provider that works behind the Alkami Card Management interface.

Sample: See Working with Card Management (https://confluence.alkami.com/sdk/working-with-card-management-241342567.html).

### SDK SSO Integration

Example: A more complex SSO that requires business logic or fields unavailable through Standard SSO (for example, bill pay determines permissions on accounts before passing to an external interface).

Sample: See My First SSO Provider (https://confluence.alkami.com/sdk/my-first-sso-provider-223323903.html) and Generic SSO Microservice (https://confluence.alkami.com/sdk/generic-sso-microservice-250893074.html).

### SDK with API

A widget calling an external interface that requires re-authentication within the third party to call APIs on the Alkami platform.

### API

An external application that requires user authentication into the Alkami platform to retrieve account information, initiate transfers, and so on.

### Custom Integration

A different form of integration that does not fit in, or uses a combination of, previously defined models. Contact Alkami if your integration requires something different.
