Shared Access is not a distinct widget, but rather a set of UI elements that you can find in the Shared Access tab of the Settings widget, and back-end logic that occurs in ORB when accessing other features such as M2M Transfers.
It is currently available for development, QA, staging and production environments.
Shared Access allows an end user (an Inviter) to share their accounts with another user (an Invitee), including account holders and non-account holders of that FI.
The Inviter can assign permissions and restrictions by account for the Invitee to Transfer To, Transfer From, View Balance, and/or Pay Bills.

## Architecture and Design

The Shared Access feature consists of the following main components:

- Settings Widget (Componentized)
- ORB

If an FI wants to enable Shared Access for its end users, they must install and configure the Settings widget (Alkami.Apps.Settings).
After this is done, an FI must add the widget to the ORB flavors of their choice through the admin UI screen.
Shared Access also requires updates to several ORB tables (core.feature, core.flavor, core.flavorwidget, etc).
For instructions about how to install and configure the Settings widget and run Shared Access scripts, see How to Implement.

## How to Implement
#### Prerequisite

Ensure you have the following Widget and MS installed and running.

- Settings Widget
- Alkami.Services.SharedAccess

To Install: choco install Alkami.Services.SharedAccess

- Alkami.Services.Tenant

To Install: choco install Alkami.Services.Tenant

#### Configuration Scripts (Step-by-Step Guide)

The following illustrates steps that must be done at the database (DB) level to enable shared access.

(–-COMMIT is commented out, first see if script is able to execute cleanly before uncommenting it out)

1. Insert a new record in core.feature called "SharedAccess"

Core.Feature

```
BEGIN TRAN

CREATE TABLE #FeatureMergeOutput ( Action nvarchar(100), NewId bigint, NewName nvarchar(50), NewIsEnabled bit, NewCreateDate datetime, OldId bigint, OldName nvarchar(50), OldIsEnabled bit, OldCreateDate datetime)
DECLARE @feature table (name nvarchar(200), isenabled bit)

insert into @feature
values('SharedAccess',1)

merge core.feature target
using (select * from @feature) source
on target.name = source.name
when matched and target.IsEnabled <> source.isenabled then
update set target.IsEnabled = source.isenabled
when not matched then INSERT (name, isenabled,CreateDate)
values(source.name, source.isenabled,GETUTCDATE())
OUTPUT CONCAT($ACTION, ' core.feature'),inserted.id,inserted.name,inserted.IsEnabled,inserted.CreateDate,deleted.Id,deleted.Name,deleted.IsEnabled,deleted.CreateDate into #FeatureMergeOutput;

IF EXISTS(SELECT 1 FROM #FeatureMergeOutput)
BEGIN
SELECT CONVERT(NVARCHAR,COUNT(*)) + CASE WHEN COUNT(*) = 1 THEN ' row inserted' ELSE ' rows inserted' END + ' in core.Feature' AS FeatureRowsAffected FROM #FeatureMergeOutput WHERE Action LIKE 'insert%' UNION ALL
SELECT CONVERT(NVARCHAR,COUNT(*)) + CASE WHEN COUNT(*) = 1 THEN ' row updated' ELSE ' rows updated' END + ' in core.Feature' AS FeatureRowsAffected FROM #FeatureMergeOutput WHERE Action LIKE 'update%' UNION ALL
SELECT CONVERT(NVARCHAR,COUNT(*)) + CASE WHEN COUNT(*) = 1 THEN ' row deleted' ELSE ' rows deleted' END + ' from core.Feature' AS FeatureRowsAffected FROM #FeatureMergeOutput WHERE Action LIKE 'delete%'
SELECT* FROM #FeatureMergeOutput
END

--CLEAN UP
DROP TABLE #FeatureMergeOutput

ROLLBACK
--COMMIT
```

Steps 2 and 3 are only needed if enabling shared access for guest user accounts.

2. Add Flavor named "DefaultGuestUserFlavor" to use when adding guest user access. (REPLACE FILL_IN_BANK_ID_HERE WITH YOUR BANK ID)

Core.Flavor

```

DECLARE @bankid bigint = (select top 1 id from core.bank where name = 'FILL_IN_BANK_ID_HERE')
DECLARE @idlelogouturl nvarchar(500) = (select IdleLogoutURL from core.Bank where id = @bankid)
```

3. Add the following widgets to the flavor.

Note: This is adding the following permissions to the DefaultGuestUserFlavor. If you do not have all of those Widgets installed, it will not execute successfully. So you will need to comment out the line in the script.

- Dashboard
- Accounts
- Transfers
- Bill Pay
- Settings
Core.FlavorWidget

```
begin tran

declare @guestID int = (select top 1 ID from core.Flavor where name = 'DefaultGuestUserFlavor')
declare @dashboardID int = (select top 1 ID from core.Widget where AssemblyInfo = 'Alkami.Client.Widgets.Dashboard.V2')
declare @accountsID int = (select top 1 ID from core.Widget where AssemblyInfo = 'Alkami.Client.Widgets.MyAccounts.V2')
declare @transfersID int = (select top 1 ID from core.Widget where AssemblyInfo = 'Alkami.Client.Widgets.TransferV2')
declare @billpayID int = (select top 1 ID from core.Widget where AssemblyInfo = 'Alkami.Client.Widgets.BillPayV2')
declare @settingsID int = (select top 1 ID from core.Widget where AssemblyInfo = 'Alkami.Client.Widgets.Settings')

CREATE TABLE #FlavorWidgetMergeOutput ( Action nvarchar(100), NewID bigint, NewFlavorID bigint, NewWidgetID bigint, NewAddedByDefault bit, NewFavedByDefault bit, NewCreateDate datetime, NewOrdering int, NewIsDefault bit, NewDisplaySetting tinyint, NewNativeDisplaySetting int, OldID bigint, OldFlavorID bigint, OldWidgetID bigint, OldAddedByDefault bit, OldFavedByDefault bit, OldCreateDate datetime, OldOrdering int, OldIsDefault bit, OldDisplaySetting tinyint, OldNativeDisplaySetting int)

declare @flavors TABLE (
FlavorID int,
WidgetID int,
AddedByDefault bit,
FavedByDefault bit,
Ordering int,
IsDefault bit,
DisplayName nvarchar(max)
)

insert into @flavors values
(@guestID, @dashboardID, 1, 1, 10, 1, 'Dashboard'),
(@guestID, @accountsID, 1, 1, 20, 0, 'Accounts'),
(@guestID, @transfersID, 1, 1, 30, 0, 'Transfers'),
(@guestID, @billpayID, 1, 1, 40, 0, 'Bill Pay'),
(@guestID, @settingsID, 1, 0, 50, 0, 'Settings')

UPDATE core.Widget
set CanBeRemoved = 0
where ID in (@dashboardID)

MERGE core.FlavorWidget as target
using (select rf.FlavorID, rf.WidgetID, rf.ADdedByDefault, rf.FavedByDefault, GETUTCDATE(), rf.Ordering, rf.IsDefault, null, 0
from @flavors rf)
as source (FlavorID, WidgetID, AddedByDefault, FavedByDefault, CreateDate, Ordering, IsDefault, DisplaySetting, NativeDisplaySetting)
on (target.FlavorID = source.FlavorID and target.WidgetID = source.WidgetID)
when matched and (target.AddedByDefault <> source.AddedByDefault OR target.FavedByDefault <> source.FavedByDefault OR target.Ordering <> source.Ordering OR target.IsDefault <> source.IsDefault OR target.DisplaySetting <> source.DisplaySetting) then
update set target.AddedByDefault = source.AddedByDefault, target.FavedByDefault = source.FavedByDefault, target.Ordering = source.Ordering, target.IsDefault = source.IsDefault, target.CreateDate = source.CreateDate, target.DisplaySetting = source.DisplaySetting
when not matched then
insert values (source.FlavorID,source.WidgetID,source.AddedByDefault,source.FavedByDefault,source.CreateDate,source.Ordering,source.IsDefault,source.DisplaySetting,source.NativeDisplaySetting)
OUTPUT ($ACTION + ' FlavorWidget') as Action, inserted.*, deleted.* into #FlavorWidgetMergeOutput;

IF EXISTS(SELECT 1 FROM #FlavorWidgetMergeOutput)
BEGIN
SELECT CONVERT(NVARCHAR,COUNT(*)) + CASE WHEN COUNT(*) = 1 THEN ' row inserted' ELSE ' rows inserted' END + ' in core.FlavorWidget' AS FlavorWidgetRowsAffected FROM #FlavorWidgetMergeOutput WHERE Action LIKE 'insert%' UNION ALL
SELECT CONVERT(NVARCHAR,COUNT(*)) + CASE WHEN COUNT(*) = 1 THEN ' row updated' ELSE ' rows updated' END + ' in core.FlavorWidget' AS FlavorWidgetRowsAffected FROM #FlavorWidgetMergeOutput WHERE Action LIKE 'update%' UNION ALL
SELECT CONVERT(NVARCHAR,COUNT(*)) + CASE WHEN COUNT(*) = 1 THEN ' row deleted' ELSE ' rows deleted' END + ' from core.FlavorWidget' AS FlavorWidgetRowsAffected FROM #FlavorWidgetMergeOutput WHERE Action LIKE 'delete%'
SELECT* FROM #FlavorWidgetMergeOutput
END

--CLEAN UP
DROP TABLE #FlavorWidgetMergeOutput

ROLLBACK
--commit tran
```

### FAQs
#### Can we customize the names of any of the permissions that show up (i.e. "View eStatements" instead of "Access to Statements")?

The text display of permissions is not supported through site text, but rather derived from the PermissionDisplayName of the SharedAccessPermissionGroups bank setting.

#### Can we prevent admins from accessing this?

Yes, but it's not preferable. This is managed through the SharedAccessPreventAllAdminActions setting.

#### Why is the recommended duration invitation 24 hours?

We feel this is a reasonable window for a legitimate guest user to accept the invitation, while mitigating security concerns.

#### How can the Shared Access feature be disabled?

Updating the core.Feature table and setting "IsEnabled" flag to "0" will disable Shared Access.

#### Do we support multiple Guest Packages?

Yes. By default all Shared Access users are placed in the DefaltGuestUserFlavor but an Admin can move them into another GuestPackage if one exists.

#### Is there an alert that is sent to the initiating user when they send a Shared Access invitation?

No, there is no alert sent to the initiator at this time.

#### What accounts can a user share using Shared Access?

Only accounts that have been synced by the core can be shared to another user. The user must have at least ViewSummary permissions on the account. The account cannot be an external account. The user creating the invitation must not have received access to the account from another user using Shared Access.
