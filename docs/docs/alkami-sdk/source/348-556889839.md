When creating a Standard SSO admin template it is recommended that you use the tool found here: https://gitlab.mgmt.alkami.net/WIDD/standardssotemplater (https://gitlab.mgmt.alkami.net/WIDD/standardssotemplater)

This document will now walk through the flow of using the tool to make a template, but there is also great information in the projects readme.

## Workflow Summary:

The easiest way to run this tool is to pull down the repository and run locally for example using Visual Studio.

User is prompted for the dev ticket number

- This gets used in the [MicroServiceMigration] attribute for migration tracking

User is prompted for the name of the SSO provider

- This determines the file and template name

User is asked if the template is for a legacy provider conversion

- If the answer is yes, the user will then supply the following to be used for migration purposes:The legacy provider nameThe legacy widget name
- Values you enter here need to match the values that are present in core.Provider and core.Widget for the legacy providers. Ideally this would be the same for all FIs but in the event that a provider or widget name differs the template will fail to pre-fill.

User is prompted for form items using this format: key=Label|Type|DefaultValue

- key which is used to reference the field value in the configex. "[FieldName]": $.[key],
- Label which will appear in the Admin UI
- Type where supported types include: text, select, or boolIf the type is select (dropdown), the user will also be prompted for the dropdown’s label/value pairs
- DefaultValue which is optional and determines the initial state of the formProvided there is a legacy provider that is successfully mapped to as mentioned above, you may want the default value of form items to be informed by legacy settings from the provider or widget.Legacy Provider settings can be accessed with $.providerSettings.[SettingName]Legacy Widget settings can be accessed with $.widgetSettings.[SettingName]ex: url=SSO Url|text|$.providerSettings.requesturl ? $.providerSettings.requesturl : ''''

User is prompted for altering the DisplayLocation default value

- Choose 1 for Inline, or press Enter / leave empty for NewWindow

Finally, user pastes the raw StandardSSO config as it was built

- values in the config don't matter / will not interfere with form item assignment

## Key Template Transformations

In case something goes wrong and a template needs to be made or modified manually understanding the basics of JSONata will be helpful.

During conversion, the following transformations are applied:

- All " double quotes → replaced with doubled single quotes ('') with some exceptions (see embedded JSON notes)
- Single quotes (') inside of double quotes → replaced with backticks (`)
- Embedded raw JSON (like "Body") → must use double escape quotes (\"") to remain valid

We make consistent use of $. this is essentially how we map to a specific field of an input from JSONata as explained in the following documentation

- $ refers to an entire input document https://docs.jsonata.org/simple
- . maps to a field withing said document https://docs.jsonata.org/path-operators

Full JSONata documentation found here https://docs.jsonata.org/overview.html (https://docs.jsonata.org/overview.html)
