As more and more interactive support vendors are being implemented in our application (e.g., Glia), it's important that we remain vigilant in protecting our user's information. When a user shares their screen with a support agent (e.g., a co-browsing engagement in Glia), everything on the screen is shared regardless of what it is. Because of the sensitivity of certain data, authors of widgets in our system need the ability to conceal specific elements on the page.

The types of concealment available are different for each vendor and must be implemented by their SDK. To prevent the need of hard-coding vendor specific HTML classes or attributes, we have implemented an abstraction layer so that generic attributes can be used. At a high level, this is how it works:

```
<!-- Instead of hard-coding a Glia specific class -->
<div class="sm_cobrowsing_hidden_field">
Sensitive data!
</div>

<!-- A generic attribute can be used instead -->
<div data-cobrowsing-hidden>
Sensitive data!
</div>

<!-- Then, on page load (or an emitted event) the specific class is added -->
<div class="sm_cobrowsing_hidden_field" data-cobrowsing-hidden>
Sensitive data!
</div>
```

This ensures the vendor classes are only added when needed, and a widget's codebase can remain completely agnostic of what support provider might be loaded on a given page.

### Glia Specific

The Glia SDK (https://docs.glia.com/glia-dev/docs/html-and-css#cobrowsing) provides three types of concealment for elements on the page. They are:

- Hidden - Completely removed from the agents screen. This should be used for any elements displaying sensitive information (e.g., SSN).
- Masked - The value of the element is replaced by asterisks before being shown to the agent. This should be used for any data input elements that contain sensitive information (e.g., password input field).
- Disabled - The input elements is disabled from being able to be interacted with, but the agent can view the element and contents. Use this for items that an agent shouldn't be using on a user's behalf (e.g., submit button).
#### Hidden

To prevent elements from being shown in the operator's session during the observation or engagement add the attribute data-cobrowsing-hidden.

```
<div class="element-that-should-be-hidden" data-cobrowsing-hidden>
<!-- This content will not be displayed to the operator -->
</div>
```

#### Masked

To prevent a field value from being shown to the operator during observation or engagement add the attribute data-cobrowsing-masked to the desired html elements.

```
<form action="action" method="get">
Social Security Number:
<!-- This input field value will be shown as `*`(s) to the operator -->
<input
class="element-that-should-be-masked"
type="text"
name="social_security_number"
data-cobrowsing-masked
/>
</form>
```

#### Disabled

To disable an element so the operator can not interact with it during an observation or engagement add the attribute data-cobrowsing-disabled to the element(s).

```
<form action="action" method="get">
Phone Number:
<!-- The operator can see the field and its value but he/she can not modify the field value -->
<input
class="element-that-should-be-disabled"
type="number"
name="phone_number"
data-cobrowsing-disabled
/>
</form>
```

### Triggering Concealment

In order to facilitate hiding this information, we have introduced a pattern that can be triggered anywhere in the application to properly conceal HTML elements that contain sensitive information. There are two ways this will happen – when the page is first loaded, and manually triggered via a browser event.

#### Page Load

On each page load, this library will attempt to find elements with the proper data attributes and add the necessary classes. If a widget is static and all content is loaded initially, there is nothing else that needs to be done.

```
<!-- Initial markup -->
<div class="some-sensitive-data" data-cobrowsing-hidden>
Sensitive data!
</div>

<!-- Automatically on page load -->
<div class="some-sensitive-data sm_cobrowsing_hidden_field" data-cobrowsing-hidden>
Sensitive data!
</div>
```

#### Event Trigger

Many times, the content needing to be concealed will not be available when the initial page load event occurs (e.g., Vue based widget). In order to account for these scenarios, the library also listens for a browser event to be emitted that will execute the concealment logic again. In its simplest form, this is what that looks like:

```
document.dispatchEvent(new Event('conceal-elements'));
```

When the library processes that event, the same logic will run again.

This event method also has some additional flexibility built into it, such as only targeting a subset of elements on the page. By default, whatever element the event is emitted from is used as the "root" element for the method. This means that only children of that element will be concealed.

```
<div class="parent-element">
<div class="some-sensitive-data" data-cobrowsing-hidden>
Sensitive data!
</div>
</div>

<div class="some-other-sensitive-data" data-cobrowsing-hidden>
Sensitive data!
</div>
```

```
const rootElement = document.querySelector('.parent-element');
rootElement.dispatchEvent(
// With listener on the top level document, we need to bubble up the event
new Event('conceal-elements', { bubbles: true }),
);
```

Will result in this HTML:

```
<div class="parent-element">
<!-- Children of the root are concealed -->
<div class="some-sensitive-data sm_cobrowsing_hidden_field" data-cobrowsing-hidden>
Sensitive data!
</div>
</div>

<!-- All other elements are left alone -->
<div class="some-other-sensitive-data" data-cobrowsing-hidden>
Sensitive data!
</div>
```

#### Custom Event Trigger

In addition to triggering the event on a specific element, the library also listens for a CustomEvent (https://developer.mozilla.org/en-US/docs/Web/API/CustomEvent) that can specify a specific element to be used as the root (either by passing the element itself or a CSS selector to find the element). The interface for the event looks like this:

```
// Interface for the custom event
interface IMaskingCustomEvent {
detail: {
element?: HTMLElement;
selector?: String;
}
}
```

This technique would allow an event to be triggered from one area of the application to conceal elements in another. Here is an example:

```
<div class="page">
<main class="main">
<div class="some-sensitive-data" data-cobrowsing-hidden>
Sensitive data!
</div>
</main>

<aside class="sidebar">
<button id="conceal">Conceal Elements</button>
</aside>
</div>
```

```
const buttonElement = document.getElementById('conceal');
buttonElement.addEventListener('click', () => {
document.dispatchEvent(
new CustomEvent('conceal-elements', {
detail: {
selector: '.main',
},
}),
);
});
```

When the button is clicked, an event will be emitted and only conceal elements inside of the div with the main class.

```
<div class="page">
<main class="main">
<div class="some-sensitive-data sm_cobrowsing_hidden_field" data-cobrowsing-hidden>
Sensitive data!
</div>
</main>

<aside class="sidebar">
<button id="conceal">Conceal Elements</button>
</aside>
</div>
```

### Annotated Examples:

Here are the examples seen in this documentation with some additional annotation.

```
// Dispatch an event on the document element
// This will search the entire DOM and add the classes on their respective elements
document.dispatchEvent(
new Event('conceal-elements')
);

// Dispatch an event on a specific element
// This will only apply classes on elements that are children of the event target
// NOTE: Since the event listener is on the document, the event needs to be set to bubble up to be triggered
document.querySelector('.main').dispatchEvent(
new Event('conceal-elements', { bubbles: true }),
);

// Dispatch a custom event for a specific element
// This will allow a custom HTML element to be passed in as the root element
document.dispatchEvent(
new CustomEvent('conceal-elements', {
detail: {
element: document.querySelector('.main'),
},
}),
);

// Dispatch a custom event for a specific selector
// This will allow a CSS selector to be used to find the root element
// NOTE: This will use the first element that matches the selector in the document
document.dispatchEvent(
new CustomEvent('conceal-elements', {
detail: {
selector: '.main',
},
}),
);
```
