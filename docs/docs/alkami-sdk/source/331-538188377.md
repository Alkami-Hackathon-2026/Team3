## Merlin One Click Submission

One Click Submission is the new standard for submitting SDK widgets and services to Alkami. Submit, track, and deploy—all from one place.

One Click Submission is available for SDK Clients only. Partners and system integrators should continue using the existing process.

What's changed? Previously, SDK clients uploaded packages to a feeds repository and waited for Alkami to download and review them manually. One Click Submission replaces that workflow entirely — you now submit, validate, and deploy packages directly through Merlin. You no longer need to upload packages to your feeds repository. Alkami will not download or review packages from that location.

### Getting Started

Before submitting packages, install Merlin and configure your credentials.

#### Install Merlin

Download and install Merlin on your machine. See SDK Machine Setup (/spaces/SDKC/pages/40403249/SDK+Machine+Setup) for instructions.

##### Network Requirements

If your network has strict firewall or proxy policies, ask your IT team to whitelist the following URLs before proceeding:

- atl-gen-alk-sdk-prod-installer-us-east-1.s3.amazonaws.com
- atl-gen-alk-sdk-prod-installer-us-east-1.s3.us-east-1.amazonaws.com
- atl-gen-alk-sdk-dev-installer-us-east-1.s3.amazonaws.com
- atl-gen-alk-sdk-dev-installer-us-east-1.s3.us-east-1.amazonaws.com
- https://api.dev.alkami.com/tooling
#### Log In

Launch Merlin and log in with the feeds credentials provided during onboarding.

Having trouble logging in? If your credentials aren't working, verify you're using the feeds credentials from your original onboarding email — not your Alkami portal credentials. If you need new credentials or never received them, contact SDK Support for assistance.

#### Configure Jira Integration

First-time users will be prompted to connect Jira. This integration automatically creates and updates Jira tickets as your submissions move through the pipeline, so you can track review status without leaving your existing workflow.

- Click the Submissions tab.
- Click Navigate to generate your Jira API key.
- Paste your key and click Start Exploring.
### Submitting a Package

The submission flow validates your package locally and on the server before queueing it for review.

#### Step 1: Upload

Drag and drop your .nupkg file (widget or microservice) into Merlin and click Next.

#### Step 2: Local Validation

Merlin checks your package structure against SDK requirements (file layout, manifest format, required metadata). If any issues are flagged, fix them in your project and re-upload. Once everything passes, click Next.

#### Step 3: Server Validation

Select the target environment you intend to deploy to. Merlin validates your package against that environment to confirm:

- The bank identifier is valid for the selected environment.
- The version number is unique (hasn't been submitted before).
- All dependencies required by your package exist in the target environment.

Validation errors most commonly mean a dependency is missing in the target environment. Check your package's dependency list against what's installed in the environment. If you're unsure which dependencies are available, contact SDK support.

#### Step 4: Submit

Review your package details — name, version, target environment — and click Submit.

Your package is now queued for automated security scanning and manual code review.

### The Submission Pipeline

After submission, your package moves through the following stages. You can track progress from the Submissions tab on the Developer Dashboard.

| Stage | What Happens | Typical Duration |
| SUBMITTED | Package received and queued. | Immediate |
| SECURITY SCAN | Automated static analysis checks for vulnerabilities and policy violations. | ~15 minutes |
| CODE REVIEW | An Alkami reviewer manually inspects your code for quality and compliance. | 0–2 business days |
| DEPLOY READY | Your package passed all checks and is ready for deployment. | — |

If you see CHANGES REQUESTED, a reviewer has flagged issues in your submission. Open the associated Jira ticket to review their comments, make the necessary changes in your code, and resubmit an updated package through Merlin.

View and manage all submitted packages.

### Deploying a Package

Once your package reaches DEPLOY READY, you can deploy it to your environments.

Staging before Production: Production environments are locked until you successfully deploy to at least one Staging environment. This gate ensures you can validate your package in a test environment before it reaches end users.

#### Step 1: Open the Deployment Modal

In the Submissions tab, find your package and click the rocket icon 🚀 to open the deployment modal.

#### Step 2: Select Target Environments

The modal displays all available environments, labeled as Staging or Production. Each environment shows one of the following statuses:

- Available for deployment — Ready to select.
- Deployment scheduled — Already queued from a previous request.
- 🔒 Locked — Production environment waiting for a Staging deployment to complete.

Click to select one or more environments. You can select multiple Staging environments at once. Selected environments are highlighted with an orange border.

#### Step 3: Confirm and Deploy

Click the Deploy button. A confirmation dialog appears showing how many environments you're deploying to.

Hold to Confirm: Press and hold the button for 2 seconds to finalize. This prevents accidental deployments. This action cannot be undone.

#### Step 4: Track Your Deployment

After confirming, your deployment is queued. Navigate to the Deployments tab to monitor progress. Deployments move through these stages:

| Stage | Description |
| SCHEDULED | Deployment is queued and waiting to be picked up. |
| IN PROGRESS | Deployment is actively being applied to the target environment. |
| COMPLETE | Deployment finished successfully. |

Once a Staging deployment shows COMPLETE, Production environments will automatically unlock for deployment.

### Tracking Deployments

Use the Deployments tab to monitor all deployment activity.
