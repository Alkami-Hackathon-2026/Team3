## Creating a new Provider for Quick Apply Microservice
### Pre-requisites
- Install the Quick Apply WidgetInstall choco package Alkami.Apps.QuickApply: Install Quick Apply Widget Expand source ``` choco install Alkami.Apps.QuickApply ``` Run SQL script to install and configure widget: Quick Apply Widget sql script Expand source ``` use ***DATABASEGOESHERE*** ----------------------- WIDGET + FLAVOR ----------------------- IF NOT EXISTS (SELECT ID FROM core.Widget WHERE Name = 'QuickApply') BEGIN DECLARE @BankID bigint; DECLARE @icon varbinary(max) = null; SELECT @BankID = ID FROM core.Bank; INSERT INTO core.Widget (BankID, Name, AssemblyInfo, Salt, Active, IconImage, IconContentType, CanBeRemoved, DisplaySettings, WidgetType, IconName) VALUES (@BankID, 'QuickApply', 'Alkami.Client.Widgets.QuickApply', 0, 1, @icon, 'image/png', 1, 3, 0, 'quick-apply'); DECLARE @WidgetID int = SCOPE_IDENTITY(); INSERT INTO core.FlavorWidget (FlavorID, WidgetID, AddedByDefault, FavedByDefault, Ordering) SELECT DISTINCT f.ID, @WidgetID, 0, 0, MAX(fw.Ordering) + 1 FROM core.Flavor f JOIN core.FlavorWidget fw ON f.ID = fw.FlavorID WHERE fw.Ordering < 999 GROUP BY f.ID; END ```

- Install Quick Apply Service Host (Microservice)Install choco package Alkami.MicroServices.Audit.Service.Host (this must be installed prior to the quick apply microservice due to audit schema dependencies). Install Audit Microservice Expand source ``` choco install Alkami.MicroServices.Audit.Service.Host ``` Install choco package Alkami.MicroServices.QuickApply.Service.Host Install Quick Apply Microservice Expand source ``` choco install Alkami.MicroServices.QuickApply.Service.Host ```

- Install Quick Apply Admin WidgetInstall choco package Alkami.Admin.Quickapply Install Quick Apply Admin Widget Expand source ``` choco install Alkami.Admin.Quickapply ```
### Steps
- Get the Visual Studio TemplateInstall choco package Alkami.Template.QuickApplyProvider Install Quick Apply Provider Template Expand source ``` choco install Alkami.Template.QuickApplyProvider ```
- Create new project from templateGenerates all required classes and methodsGenerates provider installation scriptGenerates sample capability mapping script
- Customize providerMay need to add external packages to communicate with the core/secondary providerBasic implementations of the contract methods for the provider interface (IQuickApplyProviderContract) are done for you with the logic areas for you to change placed in the BusinessLogic folder.GetJointOwnerActionReturn a list of joint owners which the user may select when applying for an application.GetProductsActionReturn a filtered product list for the current user.This method receives the products which have been created via Quick Apply Admin and allows filtering down based on your own logic (custom rules, api endpoint products, etc). More details can be found as xml comments on the method itself.OpenAccountActionThis method is used to open the new account on your core/endpoint.You can apply any rules here as needed to help with the account opening decision.The response object contains a Decision property for declaring the result as well as the AccountNumber for a reference to the new account and/or ConfirmationNumber for when a new account is not opening immediately so the end user will have a reference for the application submission to your system.StatusActionReturns if your endpoint is reachable.If this method returns false then the provider (and products) will not show for the end user.GetSupportedFieldsActionReturns a list of Fields which application fields are mapped (used) by the OpenAccountAction.This method is currently underutilized but will control which fields are 'recommended' in ORB's QuickApply Admin Field Configuration.Currently the AllowAllFields value is set true to allow all fields to be used as expected.Set the ItemList of Field to the fields used by OpenAccountAction.ValidateProductActionValidates that a product id (core identifier) is valid in the target system/core endpointThis method is currently underutilized but will allow ORB's QuickApply Admin Product editor to reflect if the identifier is known to be valid.
- Run the SQL script (automatically generated) found in the ProviderScripts folder to install the new provider
- Build and run the MicroService from Visual Studio
- Configure a new Category and Product for this new provider via the Quick Apply Admin Widget
- Open online banking and go to the Quick Apply Widget
