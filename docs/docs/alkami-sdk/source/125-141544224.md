The focus of this page is to identify the points during the following listed SDK Process and where billing will be affected.

- SDK Submission process (see Software Development Kit (SDK) Product Guide - SDK Submission Process)
- SDK Support Tickets submitted
### SDK Submissions

The SDK submission and eventual production deployment process consist of the following phases:

- The SDK development package is delivered by the client (created in FI development area).
- The package is uploaded by the client into the customers dev feed on the Alkami feeds server and a Jira "SDK Submission" ticket is created for tracking this submission.
- Alkami completes a review of the SDK submission for coding issues and security issues.(Steps 1- 3 are repeated as long as needed until SDK package is ready for Staging deployment.)
- When all coding and security issues have been addressed, Alkami schedules the Staging deployment of the SDK package and updates the ticket with a status of "Waiting for Stage Validation." If the submission reaches this point, it is billable.
- After the client tests and approves the submission in stage, Alkami completes the Production deployment of the SDK package.

During these phases, much of the development is accomplished by the Financial Institution (FI). Where Alkami assistance is typically needed is at the following areas:

- Code correction suggestions
- Security vulnerability analysis

Alkami will provide basic support for these conditions. If the FI requires deeper consultation and programming help, Alkami may bill for the additional time spent.

For SDK update submissions there are 2 standard scenarios:

#### Scenario A

Alkami requests the FI to change something in the submitted package and the exact modification requested by Alkami is submitted. In this scenario, there would be no billable items for the requested re-submission.

#### Scenario B

The FI has made changes of their own design to their package (whether or not Alkami has also requested specific changes). In this scenario, there would be billable items for the additional submission.

### SDK Support Tickets

Jira tickets of type SDK Support Incident are the normal mechanism for communicating with the Alkami SDK and Support teams for help in using the SDK. Simple questions will be answered by Alkami and these incidents are not considered billable. Tickets that take significant Alkami effort to resolve may be billable. Alkami will make a determination if:

1) The time spent by Alkami is minimal (not billable)
2) The reason for the incident was caused by Alkami (not billable)
3) The nature of the support required becomes more of a consulting engagement (billable)4) significant Alkami resources are required to resolve the issue. All issues requiring 4 hours or more form Alkami fall into this category. (billable)

Alkami has anticipated client needs for these SDK Support Incidents for standard SDK use. Review the Master Service Record to identify how many service tickets are allocated before charges accrue. Beyond the number covered by the Master Service Record, further support tickets can be opened and submitted.

There is a special type of a Support Incident use for the purpose of a "Stage Match request." Each FI will receive one such Stage Match every 3 years without charge. If the client requires a fresh Stage Match more often, those are billable incidents.
