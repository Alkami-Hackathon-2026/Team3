## Description

Create an Admin widget for managing Standard SSO widget implementations. Providing the ability to view, create, update, and validate the widget Configuration for FIs, SDK clients, TI, and Support.

## Business Case
- By providing an administrative interface we will empower those who need to create, update, or validate Standard SSO configurations to do so from a single location in a more standard approach.
- The admin widget will deliver a training platform by validating the JSON configuration, as well as displaying an up to date Expression Glossary available for use.
- This approach will avoid mistakes that might happen through the current process of SQL scripts through DST by standardizing how the configurations are created, and updated.
- SDK implementations for Standard SSO are going to be easier with a facade that will handle widget, and configuration mapping in the database for the users.

- Potential for abuse in sandbox - testing SSO to vendors
- Widget Management (Permissions)

## Database Changes
### Feature Flag

There is a new feature flag under Internal.StandardSSOAdmin called EnableStandardSSOAdmin. This must be enabled to use this widget

Once this is rolled out for everyone this feature flag will be removed and needs removed from this doc

### Template

[Id] [INT] IDENTITY (1,1) CONSTRAINT [PK_Template_Id] PRIMARY KEY,
[Name] VARCHAR(128) NOT NULL,
[Configuration] VARCHAR(MAX) NOT NULL,
[CreatedDate] [DateTimeOffset] NOT NULL,
[LastUpdateDate] [DateTimeOffset] NULL,
[LastModifiedBy] VARCHAR(128) NULL,
[ConversionProviderName] varchar(128) NULL,
[ConversionWidgetAssemblyInfo] varchar(128) NULL,
[Disabled] BIT DEFAULT 0 NOT NULL

### Configurations

ALTER TABLE [sso].[Configuration]
ADD [TemplateId] INT NULL CONSTRAINT [FK_sso_Configuration_sso_Template] FOREIGN KEY REFERENCES [sso].[Template](ID)
