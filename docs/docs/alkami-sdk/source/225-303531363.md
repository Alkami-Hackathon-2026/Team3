The API folder is where all methods that make a request to an API go. This "request" layer allows us to separate out the logic needed to make a request. By exporting each of these functions from a single file, we are able to choose whether to import all methods at once or specific methods needed into a consumer file.

Only import what you need

Due to the way Webpack bundling works, there are generally better results in terms of performance and file size if the only imports in a file are ones that are actually required. While it is easier to import the entire request layer into a component, it will be better in the long run to only import the methods needed.

```
import * as Requests from './Scripts/api/requests'; // DON'T: Imports everything
import { getTenants } from './Scripts/api/requests'; // DO: Only imports the method needed
```

This is an example of what the requests file would look like:

requests.ts

```
// GET Requests
// =============================================================================
export async function getTenants(): Promise<ITenant[]> {
const response = await fetch('/api/tenants');

if (response.ok) {
const tenantsResponse: ITenantResponse = await response.json();

if (!tenantsResponse.hasError) {
// Only return the itemList since we know the request was successful.
return tenantsResponse.itemList;
}

throw new Error(consolidateValidationMessages(tenantsResponse));
}

throw new Error(response.statusText);
}

// POST Requests
// =============================================================================
export async function authenticateAsUser(request: IUserAuthRequest): Promise<{ url: string, syncCompleted: boolean, hasError: boolean }> {
const fetchOptions = {
method: 'POST',
body: JSON.stringify(request),
headers: {
'Content-Type': 'application/json',
},
};

const response = await fetch('/api/loginasuser', fetchOptions);

if (response.ok) {
const loginResponse: IUserAuthResponse = await response.json();

return ({
url: loginResponse.url,
syncCompleted: loginResponse.syncCompleted,
hasError: loginResponse.hasError,
});
}

throw new Error(response.statusText);
}
```

Things of note:

- Each request is exported from the requests file
- Every method is async and returns a promise to allow for asynchronous communication
#### Importing into a component

To use a request, you can simply import it into a component that needs to make use of it.

Component.vue

```
<script lang="ts">
import Vue from 'vue';
import { authenticateAsUser } from '../api/requests'; // Import the method here

export default Vue.extend({
// ...
methods: {
async getLoginUrl(isMobile: boolean) {
const newPayload: Api.IUserAuthRequest = {
isAdmin: this.user.isAdmin,
isMobile,
bankIdentifier: this.user.fiBankIdentifier,
loginBankUri: this.user.fiBankUri!,
loginUserIdentifier: this.user.userIdentifier,
loginUsername: this.user.username,
requireSync,
source: 'Orion website',
};

const authPayload = await authenticateAsUser(newPayload); // Using the request method here

this.$store.commit('addRecentUser', this.user);
window.open(authPayload.url, '_blank');
},
},
// ...
});
```

#### Grouping API Requests

Sometimes an application will have many API requests and it becomes desirable to break the requests out into their own logical grouping by files. This could look like having a "users.ts" and "accounts.ts" file to be able to separate the requests for these resources. This still works the same as above, but in order to support importing all requests at once, it's necessary to create what is known as a "barrel file" that exports all functions in a single place. The pattern for this is very simple, just create an "index.ts" file at the root of the API folder and export all of the children underneath it.

index.ts

```
export * from './users';
export * from './accounts';
```

By using the `export *` syntax, this file will automatically make available any method that is exported from the files listed here. You can then import all requests using this syntax:

Import all Requests

```
import * as Requests from '../Api/index';
```

The "as Requests" syntax here puts all exported members under an object named "Requests" that is then accessible through standard object notation.
