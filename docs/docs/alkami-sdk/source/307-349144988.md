In this example we'll take a deeper look at how we can leverage the SSO Template.

#### Prerequisites

Install NodeJs

Download our fake Authentication Server. This is a node application thats created to give you an idea how it would work in a real life scenario.

node-oauth2-server-example.zip (/download/attachments/349144988/node-oauth2-server-example.zip?version=2&modificationDate=1710897516634&api=v2)

#### Introductions

The above is a very simple implementation of Oauth2 Server in nodeJs. It's purpose is to showcase how SSO could work in real world scenario.

Download the above project, and install all the dependencies with npm install and npm start to run the server. The server should be running on your http://localhost:3000 (http://localhost:3000)

You can verify that it's running by directly visiting the URL in your browser.

Obtaining a token

to obtain a token, send POST to http://localhost:3000/oauth/token (http://localhost:3000/oauth/token)

we'll be using client_credentials grant type to obtain an access token.

The following headers and body need to be added to the request payload.

- HeadersAuthorization: "Basic " + clientId:clientSecret base64'd(for example, to use confidentialApplication:topSecret, you should send Basic Y29uZmlkZW50aWFsQXBwbGljYXRpb246dG9wU2VjcmV0)Content-Type: application/x-www-form-urlencoded
- Bodygrant_type: client_credentials

For example, using curl:

```
curl http://localhost:3000/oauth/token \
-d "grant_type=client_credentials" \
-H "Authorization: Basic Y29uZmlkZW50aWFsQXBwbGljYXRpb246dG9wU2VjcmV0" \
-H "Content-Type: application/x-www-form-urlencoded"
```

You should receive a response like this:

```
{
"accessToken": "951d6f603c2ce322c5def00ce58952ed2d096a72",
"accessTokenExpiresAt": "2018-11-18T16:18:25.852Z",
"client": {
"id": "confidentialApplication"
},
"user": {
"id": "confidentialApplication"
}
}
```

SlimSSOService

SlimSSOService inside the SDK Samples folder contains a working implementation of the Microservice hitting the local Auth Server.

If you don't see it inside your SDK Samples, make sure to update to the newest version.

Open the project and build it in Debug mode!

The main business logic resides in this function; GetAccessToken()

Its important to note; in this example, we are not attaching any customer unique identifier to the Auth Server. In most cases, you might want to. (e.g Customer UUID, customer first name, last 4 card number)

Build the project in Release Mode to install the Service from nuget package. The Service nuget Package should be in this path ....\USBFI.MS.SlimSSOService.Service.Host\Installer

Install it locally via choco;

choco install USBFI.MS.SlimSSOService.Service.Host -s C:\Users\hillman.chen\source\repos\USBFI.MS.SlimSSOService\USBFI.MS.SlimSSOService\USBFI.MS.SlimSSOService.Service.Host\Installer

Once you build the project in release mode. Copy over the Client and Data nuget package to a local folder and add the local folder as a nuget source. This will allow you to reference those packages when you build your widget.

Hooking it up to the Widget

Create a new Widget Project and select the SSO Checkbox.

Since we brought in new package dependencies, its important that we include it in the final build output. Add this line in the .nuspec file

```
<file src="bin\USBFI.MS.*" target="lib" exclude="**\*.config"/>
```

Add the USBFI.MS.SlimeSSOService.Client and Data package into your widget.

```
// Instantiate the client
private static Func<ISlimSSOServiceServiceContract> ssoServiceFactory = () => new SlimSSOServiceServiceClient();
```

SimpleRedirect function

```
public ActionResult SimpleRedirect()
{
GetAccessTokenRequest accessTokenRequest = new GetAccessTokenRequest();
this.AugmentRequest(accessTokenRequest);
var response = AsyncHelper.RunSync(() => ssoServiceFactory().GetAccessToken(accessTokenRequest));

if (response.HasError) return View("Error");

// This is the actual SSO URL, in this case its our local running server
// this is set to http:/localhost:3000/
var url = GetWidgetSetting("SsoUrl");

NameValueCollection queryString = System.Web.HttpUtility.ParseQueryString(string.Empty);
queryString.Add("access_token", response.ItemList.First().token);

var redirectUrl = $"{url}?{queryString.ToString()}";
return Redirect(redirectUrl);
}
```

Ensure you have the local Auth server running, access the widget via Developer.dev.alkamitech.com page and if everything is correct you'll see something like this.

Note: This is doing plain redirect, while this may work it may not provide the best user experience. Are you able to make it render in an iframe?
