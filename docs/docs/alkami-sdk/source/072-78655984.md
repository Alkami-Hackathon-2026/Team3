This tutorial is an introduction to Alkami's widget template. A widget is an MVC application that plugs into the base Alkami platform.

The example source for this tutorial is located in the latest version of the Alkami Samples package under MyMoney. Run the following upgrade command to get the latest samples.

```
choco upgrade Alkami.SDK.Samples -y
```

## Alkami's Widget Platform

The Alkami platform is a web-based application that is extended and customized with plugins called widgets. Users can use these widgets to access their banking details with a customized desktop and mobile experience. This tutorial will guide you from project creation with a Visual Studio template to deploying a fully working widget with desktop and mobile views.

## Alkami's Widget Template
- Install the templateClose Visual StudioThe choco installer will run the VisualStudioInstaller.exe in the background. You must close any running instances of VS. ``` choco install Alkami.SDK.Templates -y ```
### Create and build the widget

Run As Administrator

You must run Visual Studio as an Administrator to locally deploy and debug .

- Open Visual Studio.
- Create a new project and filter on the Alkami Platform type or search widget to find the Alkami Client Widget template.
- In Project name, type USBFI.Client.Widget.MyMoney. This widget will belong to the My Money feature set, which includes the My Money service and My Money admin widget.
- Select a Location on your hard drive and target .NET Framework 4.7.2.Feed AuthenticationVisual Studio will likely prompt for user credentials to authenticate with the feed server. The credentials are the same used for https://feeds.alkamitech.com/. For information on getting access, see Getting Started - Do I have Access?
- Build the solution and verify it succeeds.
### Configure the widget

Each widget needs a database entry for it to be loaded during platform startup.

- Go to the Tools folder and open the install_widget.sql.
- Change the @WidgetDisplayName to My Money.
- Un-comment Line 27 and comment out Line 26. Note: This script is in rollback mode. This changes it to commit mode.
- Save and execute the script to insert the widget's configurationLocal DevelopmentThis script is for local development only and adds a database entry that is used to load the widget during application startup.

- Edit the USBFI.Client.Widget.MyMoney.nuspec metadata section with information relevant to your development team and un-comment Line 30 so that the package will capture the proper C# libraries during packaging. Chocolatey Packaging | Nuspec FilesIn the previous step you added two NuGet packages from the Visual Studio package manager. These installer packages added a group of files that are used to create a Chocolatey package. Chocolatey is an implementation of the NuGet packaging software, building on the base framework so that developers can use the same patters to package and install runnable applications. See Chocolatey's Creating Packages page for more information.See our documentation page for more information about Alkami's installers Nuspec RequirementsFailing to fill out the .nuspec metadata or not defining what library to package will result in a failed package or empty package. Be sure to pay attention to the Visual Studio output when building your widget. There are two main sections in the .nuspec file: metadata and files.
- You must complete the metadata entirely, with fully qualified URLs and values for the blank fields. Visual Studio will fail to package your project if these fields are not completed.
- The files section will look something like the following and must define all the files that are to be packaged. Out-of-the-box, the bin files line must be uncommented. Additional line items might be needed if the widget depends on any other microservices.NOTE: In this example, we used the wildcard notation src="bin\USBFI.*" so that the package will target any libraries beginning with USBFI. This will be helpful in the next steps when you add the My Money service integration to the widget. USBFI.Client.Widget.MyMoney.nuspec ``` <?xml version="1.0"?> <package> <metadata> <id>USBFI.Client.Widget.MyMoney</id> <version>1.1.0</version> <title>USBFI My Money Client Widget</title> <authors>Alkami Technology, Inc.</authors> <owners>Alkami Technology, Inc.</owners> <projectUrl>https://confluence.alkami.com/display/SDKC/Samples+and+Tutorials</projectUrl> <iconUrl>https://www.alkami.com/files/alkamilogo75x75.png</iconUrl> <requireLicenseAcceptance>false</requireLicenseAcceptance> <description>The My Money demo widget is used to train Alkami SDK developers</description> <releaseNotes>This widget should not be deployed to stage or production environments other than SalesDemo</releaseNotes> <tags>SDK WIDGET Demo MyMoney</tags> <copyright>Copyright © 2021 Alkami Technology, Inc.</copyright> </metadata> <files> <!-- The following defines where to find the files for packaging and what to exclude--> <file src="tools\chocolateyInstall.ps1" target="tools" /> <file src="tools\chocolateyUninstall.ps1" target="tools" /> <file src="AlkamiManifest.xml" target="AlkamiManifest.xml" /> <file src="**\*.*" target="src" exclude="**\obj\**\*.*; ... redacted/> <!-- bin files | define the libraries that should be a part of this package --> <file src="bin\USBFI.*" target="lib" exclude="**\*.config"/> <!-- WebClient content --> <file src="**\Scripts\" target="content\Areas\App" /> <file src="**\Styles\" target="content\Areas\App" exclude="**\*.scss" /> <file src="**\Views\" target="content\Areas\App" /> <file src="**\Images\" target="content\Areas\App" /> <file src="**\_SiteText\" target="content\Areas\App" exclude="**\*.xx.xml"/> </files> </package> ```
- Edit the AlkamiManifest.xml and add the BankIdentifier for your financial instituition.
- Edit the iconName and displaySettings to the appropriate values. In the Visual Studio window, there is a file opened called AlkamiManifest_explained.txt. Read this entire file to understand the requirements of the AlkamiManifest.xml.
- After editing, the AlkamiManifest.xml might look something like this, where the GUID and other values are specific to your package and FI.AlkamiManifest.xml ``` <?xml version="1.0"?> <packageManifest> <version>1.0</version> <general> <creatorCode>USBFI</creatorCode> <compound>USBFI_SDK</compound> <element>USBFI.Client.Widget.MyMoney</element> <componentType>Widget</componentType> <bankIdentifiers> <bankIdentifier name="USBFI">12DBFCD2-4133-41D1-B0DE-D0EABE11D7A0</bankIdentifier> </bankIdentifiers> </general> <!-- Widget --> <widgetManifest> <widgetName>USBFI.Client.Widget.MyMoney</widgetName> <displayName>My Money</displayName> <!--This value needs to match the Display Name in the previous SQL--> <description>The My Money financial solution you've always needed.</description> <!-- <widgetInstall>Client|Admin|Generic</widgetInstall> - Generic means this gets installed in both Admin and Client with v1.0 manifests --> <widgetInstall>Client</widgetInstall> <areaName>USBFIMyMoney</areaName> <assemblyInfo>USBFI.Client.Widget.MyMoney</assemblyInfo> <!-- <displaySettings>Desktop|Mobile|Tablet|DesktopMobile|All</displaySettings> --> <displaySettings>All</displaySettings> <iconName>piggy</iconName> </widgetManifest> </packageManifest> ```
