## SAML at Alkami

Alkami has an optional utility library to assist with SAML connections. If you prefer to implement your own SAML classes then you do not have to use the following class examples.

Alkami also has a mechanism to build a single sign-on (including a SAML-based SSO) that is driven through configuration, without custom code in most cases. For information about the Alkami Standard SSO the information on this page is useful background information, but for implementation information see Alkami Standard SSO Configuration Tool (Jarvis) (https://confluence.alkami.com/sdk/alkami-standard-sso-configuration-tool-jarvis-141527390.html (https://confluence.alkami.com/sdk/alkami-standard-sso-configuration-tool-jarvis-141527390.html)).

### Implementation Details

Typically, there is a contract between the financial institution and the third-party vendor, an exchange of information and an agreement as to what unique identifiers are required, what certificates for signing and encryption are required, and what URL addresses must be called as part of the authentication pattern. Alkami's utility class intends to make these steps simple and we will assist where needed when you configure the certs and the credential workflow.

Whitelisting URL Endpoints

The staging environment is restricted by egress networking rules and you must know the host name of the URLs with which the SAML implementation will be communicating. Provide these details as part of your SDK project submission.

### Generate Your Certificates

Use the following commands to generate the .cert you will give to Alkami so that your service provider can read it and then generate the .pfx archive for use within your identity provider.

Alkami's SAML utilities expect a SHA256 hashing algorithm and an RSA 2048 bit asymmetric encryption. In addition, the Cryptographic Service Provider (-CSP) must be set as Microsoft Enhanced RSA and AES Cryptographic Provider when you create the PKCS12 archive.

Generate the .cert

```
openssl.exe req -x509 -nodes -sha256 -days 3650 -subj "/CN=Local" -newkey rsa:2048 -keyout Local.key -out MyLocalCert.crt
```

Generate the .pfx archive

```
openssl.exe pkcs12 -export -in MyLocalCert.crt -inkey MyLocalCert.key -CSP "Microsoft Enhanced RSA and AES Cryptographic Provider" -out MyLocalCert.pfx
```

### GetSamlResponseXml()

This is the main method to which the developer will pass parameters. Alkami implemented the underlying details and will return the SAML response in the standard XML format. Typically, a developer will do the following things before calling this method:

- Verify incoming parameters
- Get all provider settings required to interface with the SP, which at minimum require:Recipient Base URLIssuer (usually alkami but can be any unique value)Subject (user/name/memberId being authenticated)SAML Audience
- Use Alkami.Utilities.Saml to build the SAML signing parametersOptional certificate for signingOptional certificate for encryptionExpected signature types
- Call GetSamlResponseXml(), passing in the previous details where necessary
### Example Utility Pattern

Many of the values are stored as provider settings. You must update your service to account for these new settings.

Signing Requirements

If you are signing your request with a .crt it must adhere to certain specifications for best security as detailed in the previous section. If your certs are issued by a third party and cause errors in Alkami's SAML implementation, contact Alkami to discuss the options.

MySsoClass.cs

```
// We'll be using Alkami's utility class referenced above
using Alkami.Utilities.Saml;
...

// If we're signing then we'll have a certificate installed and fetch with the name thumbprint stored in the settings
var samlSigningCert = Saml20Utility.GetCertificateForSigning(X509FindType.FindByThumbprint,
settings[Provider.SettingKeys.CertThumbPrintForSigning], true);

// Encryption is optional, if required it's not necessary to TryGetValue(), otherwise return null
string encryptsetting;
settings.TryGetValue(Provider.SettingKeys.CertThumbPrintForEncrypt, out encryptsetting);
var samlEncryptionCert = !string.IsNullOrWhiteSpace(encryptsetting)? Saml20Utility.GetCertificateForEncryption(X509FindType.FindByThumbprint,
settings[Provider.SettingKeys.CertThumbPrintForEncrypt], true) : null;

// Build objects to interface with Alkami's Saml20Utility. This may differ per implementation
var samlSigningParameters = new Saml20Utility.SigningParamaters {Certificate = samlSigningCert,SignatureLevel = Saml20Utility.SignatureType.Response};
var samlEncryptiongParameters = samlEncryptionCert == null ? null : new Saml20Utility.EncryptionParameters{Certificate = samlEncryptionCert, KeyEncryptionAlgorithm = EncryptedXml.XmlEncRSAOAEPUrl };

// This is typically a unique value agreed upon between Financial Institution, Alkami and the vendor
var partnerId = settings[Provider.SettingKeys.PartnerId];

// These attributes may not be required
var samlAttributes = BuildSamlAttributes(user, partnerId,bankIdentifier, settings);

// Generate the SAML response by calling the GetSamResponseXml() method
var samlResponse = Saml20Utility.GetSamlResponseXml(settings[Provider.SettingKeys.BaseUrl], // BaseURL
settings[Provider.SettingKeys.Issuer], // Issuer
settings[Provider.SettingKeys.Domain], // Domain
Guid.NewGuid().ToString(), // Subject
new List<string> // Audience
{
settings[Provider.SettingKeys.Domain]
},
settings[Provider.SettingKeys.AuthnContxt], // AuthNContext
samlAttributes,
samlSigningParameters,
samlEncryptiongParameters,
SamlAttribute.NAMEFORMAT_URI); // UTC TimeOffSet (default to -60sec)

// Flip bits into any format you may need, at this point we're working with raw XML
var samlBytes = Encoding.UTF8.GetBytes(samlResponse);
var base64Saml = Convert.ToBase64String(samlBytes);
```
