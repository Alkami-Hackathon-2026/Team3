MVC 5 Updates

You can now update your widgets to MVC5! To do so follow these steps:

- Upgrade Alkami.Webtoolkit, Alkami.WebToolkit.Extensions, Alkami.Webtoolkit.Scripts to version 2.0.0
- Upgrade package Microsoft.AspNet.Mvc to version 5.2.3
- Upgrade package Microsoft.AspNet.WebPages to version 3.2.3
- Uninstall package Mvc3Futures. If you believe you still need the 5.0.0 version of Microsoft.AspNet.Mvc.Futures, please talk to Architecture
- Uninstall package MvcContrib.Mvc3-ci
- If there is a web.config under the Views folder, please delete that web.config from your componentized widget.

After updating, please recompile, test and submit the changes to the SDK team.

##### Razor Syntax and Boolean Serialization

You may notice that boolean dom values are not serializing properly. Please update any razor serialization by adding .ToString() to the model’s boolean value.

WIF 3.5 Removal

In addition to removing WIF 3.5, this change is major step in truly modularizing ORB. With this changes comes the first WebExtension/Module that is considered mandatory for ORB to run. This module is what has taken the place of the previous HttpModules that were provided by WIF 3.5.

This opens the door to us dynamically choosing the type of authentication we run with orb instead of our current hard coded version. Imagine a world where you could log in to ORB with your LDAP credentials instead of looking up a user every time in secret. The possibilities are endless!

Settings Microservice Contract Changes

In order to allow settings exposed by provider based microservices to be viewable with setting descriptors and validators and for them to be editable by admin, a breaking change to the Settings MS was required.

The breaking change was a change to the SettingDescriptor namespace. It has changed from Alkami.TrackableObjects.SettingDescriptor to Alkami.MicroServices.Settings.ProviderBased.Contracts.SettingDescriptor.

Also instead of a providerService inheriting from DisributedServiceBase you need to inherit from ProviderBasedService where T : Alkami.TrackableObjects.Plugins.Plugin

Update packages as follows:

- Alkami.ConfigurationDrivenObjects >= 4.1.2Alkami.ConnectorsAndProcessors >= 4.1.2Alkami.MicroServices.Settings.Contracts >= 4.1.0Alkami.MicroServices.Settings.Client >= 4.1.0Alkami.MicroServices.Settings.ProviderBased.Contracts >= 4.1.2

Add these packages to your service host:

- Alkami.MicroServices.Settings.ProviderBased.Contracts >= 4.1.2Alkami.MicroServices.Settings.ProviderBasedService >= 4.1.2

In your provider service you will need to override the ServiceContract property and ensure it is initialized on start so that the base ProviderBasedService class can use it when implementing the base GetSettingDescriptors, GetDefaultSettings and ValidateChangedSettings methods used by admin.

Given the current limitations of our QA environments to only support a single MS instance, all consumers of the settings MS will need to be updated to reference version >= 4.1.0

Message Center Breaking Changes

A breaking change has been introduced if you have any custom integrations working with Alkami’s ORB Message Center. Changes were made to the Common Data Contracts and the Message Center Service to allow admin users to toggle a users ability to respond to messages.

In short, this means any code depending on Alkami.App.MessageCenter.Contracts and Alkami.Client.Services.MessageCenter will need to tested against the new assembly versions. These latest assemblies are found in the C:OrbShared directory.
