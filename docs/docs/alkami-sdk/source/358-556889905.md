Encryption can be performed for different algorithms which might have different requirements.

To use encryption the EncryptMethods section should be filled out.

## EncryptMethods

Listed are the supported algorithms and required parameters for each.

### AES

Symmetric encryption which uses the same secret key to hide and later reveal (encrypt and decrypt) a secret message.

#### Required properties
- Algorithm
- Encoding
- InputEncoding
- IVEncoding
- IVGenerationMode
- Key
- KeyDerivationMethod
- Mode
- PaddingMode
- SharedKey
#### Defaults
- KeyType - String
### RSA

Asymmetric encryption relies on keys made of two parts: a private (secret) part and a public (non-secret) part. For encryption on our end to send the data we rely on the public key, once encrypted we have no way of decrypting the data as the vendor will own the private key for decryption.

#### Required properties
- Algorithm
- Encoding
- InputEncoding
- Key
- RSAPaddingMode
- Thumbprint
## DeriveKeyMethods

Key derivation functions (KDFs) are often used in these scenarios to derive one or more strong keys from a single, secret value.

Some cryptographic algorithms and protocols can have keys that are known to be weak (http://en.wikipedia.org/wiki/Weak_key), and thus should be avoided; KDFs can help avoid weak keys in such systems.

#### Expression

Usage of the key derivation is done through the DeriveKey expression which depends on having defined the section DeriveKeyMethods with a matching Key.

```
{{ DeriveKey( 'DeriveKeyName', 'Secret', 16, 32 ) }}
```

Arguments:

- #1 - A constant string that refers to the DeriveKey's Key.
- #2 - The secret used to derive the key.
- #3 - The desired key size.
- #4 - Optional - if provided, the key will be offset by this size. For example for key size of 16 with an offset of 32, a key with a length of 16 bytes will be derived after being offset by 32 bytes.
#### Required properties
- HashEncoding
- Key
- Salt
- SaltEncoding
#### Defaults

Iterations - 1000
