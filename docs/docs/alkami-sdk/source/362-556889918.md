## Overview

HTTP services allow for the Standard SSO microservice to perform intermediate HTTP requests to retrieve data for subsequent use.

## JSON vs. XML vs. Text

The HTTP service possesses the ability to parse either JSON, XML, and Text responses based on the configuration of the ResponseType ("Json", "Xml", or "Text").

## Response Handling

If the response does not have an HTTP Status code of 2XX, the expression will error.

## JsonPath

When parsing a JSON payload for a successful response, the OnSuccess path will be interpreted as a JsonPath expression. See the following for documentation (https://restfulapi.net/json-jsonpath/) and examples (https://www.newtonsoft.com/json/help/html/QueryJsonSelectToken.htm).

## XPath

When parsing an XML payload for a successful response, the OnSuccess path will be interpreted as an XPath expression. See the following for documentation (https://www.w3schools.com/xml/xpath_syntax.asp) and examples (https://www.w3schools.com/xml/xpath_examples.asp).

## Text

For Text payloads, the response is taken as is without any parsing for a successful response.

## Certificates

If the request requires a certificate, "Thumbprint" expression is available to be used in the Services section. Please see Expression Capable Locations (https://confluence.alkami.com/display/ISG/Standard+SSO#StandardSSO-ExpressionCapableLocations) in Standard SSO introduction page.
