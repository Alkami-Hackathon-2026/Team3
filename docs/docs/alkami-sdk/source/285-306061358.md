Whether it was in training or through a support ticket, you have heard about a Stage Match environment, but what exactly is it? The simplest explanation is that it is an environment that consists of a copy of the DeveloperDynamic database supplied with the SDK that is overlaid with your settings from your Alkami staging environment and a new site URL that connects to the new database. This environment, along with the appropriate provider packages for your core, will allow you to test your SDK-developed components against your test core.

### I created the request ticket. What are the next steps?

The next step is a ticket is created for the script to be generated. Although you will not have access to that ticket it will be linked to the ticket that you just created. This is where Alkami must set expectations in regard to the time this process takes to complete. There can be a wait for up to two weeks for that script to be generated by the owning team, although sometimes it is faster but not guaranteed.

After that script is delivered, an SDK team member will process it and test it in a local environment. Based on availability this testing can take a few days. After the testing is complete a script package will be zipped and attached to the ticket. An SDK team member will reach out on the ticket to schedule a time to help install the stage match scripts. They will also attach a list of packages specific to your core that must be installed.
