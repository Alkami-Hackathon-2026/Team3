Using the `scoped` attribute in a component's style tag is an incredible benefit we get from Vue that allows us to prevent any naming collisions with our CSS rules. This is almost always desirable expect in one very specific case – trying to style an element that requires a multistep selector to target. Let's look at an example:

component.scss

```
.node-record__view-more {
align-self: center;
display: flex;

// Nested CSS selector
svg {
fill: #333333;
}
}
```

While this would work perfectly with a normal SCSS file, using the scoped attribute outputs an unexpected CSS rule:

```
// What we expect:
.node-record__view-more:hover svg {
fill: #333333;
}

// What actually gets produced
.node-record__view-more:hover svg[data-v-f3f3eg9] {
fill: #333333;
}
```

The reason this is happening is that in order to properly scope styles, Vue adds a unique data attribute on the markup of a component and adds that attribute selector on all scoped CSS that is produced. That is how we could have the same CSS class name used in multiple components and they would never affect each other. Unfortunately, for a situation like this the data attribute is breaking the expected behavior since the data attribute is on the parent and not the SVG element in this case. In order to change this behavior, we need to use a special syntax that is in the SCSS loader that Webpack leverages:

```
.node-record__view-more {
align-self: center;
display: flex;

// Nested CSS selector
::v-deep svg { // ::v-deep tells the loader to leave this selector alone
fill: #333333;
}
}
```

Now that we have prepended the nested rule with `::v-deep` the loader will add the data attribute just before instead of at the end. With this change we get our expected output:

```
// What gets produced
.node-record__view-more[data-v-f3f3eg9]:hover svg {
fill: #333333;
}
```
