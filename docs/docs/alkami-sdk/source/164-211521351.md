The SDK project templates contain a template to create an AtLogin module. These modules are called after users successfully login to the system and before they land on the Dashboard page.

This page explains how to use the template

### What is in the Template?

When you create a new project with the AtLogin module template, it looks like a widget. In fact, it uses the same kind of packaging and installer as a standard widget. If you have never used the SDK to create a Client Widget, Alkami recommends that you create one first (https://confluence.alkami.com/display/SDKC/My+First+Client+Widget) to gain experience and then return to this page to create an AtLogin module.

One of the main differences from a widget is that you will find a class named StepAreaRegistration.cs which is required to connect the MVC routing that is required for this module to function. Do not alter the contents of this class file unless directed by Alkami to do so.

### Remove an AtLogin module from your SDK

To remove the module, you must:

- Remove the code. This means you must delete the folder for the module under c:/orb/webclient/areas. Note: You might need to do an iisreset if files are in use by IIS.
- Remove from the database. To do this, use the following sql script and insert the name of your module instead of the placeholder name. Script To Remove AtLogin Module ``` -- Script to remove an AtLogin module Declare @ModuleName varchar(50) set @ModuleName = 'YourModuleNameGoesHere' Declare @StepId int select @StepId = ID from login.Step where Name = @ModuleName if @StepId is null BEGIN print'Unable to locate a module named ' + @ModuleName END ELSE BEGIN print'Removing module named ' + @ModuleName delete from login.UserStep where StepId = @StepId delete from login.ScenarioStep where StepId = @StepId delete from login.Step where ID = @StepId END ``` Perform a restart-sdkservices command after removing this from the database to confirm nothing is lingering in the application memory or cache.
### Remove an AtLogin module from Alkami Stage and Production environments

Use the same basic steps as previously described to remove from the Alkami-hosted environments. However, access to the servers is limited to specific Alkamists, and only during specific time windows. To have Alkami remove your module you must open an SDK Support Incident and the support staff will coordinate the removal steps. This will take several days, and possibly a couple of weeks depending on your timing and the environment involved. For this reason, you must plan ahead.

Do not submit an AtLogin module to Alkami for installation just to test it. Only send a submission to Alkami if it has been fully tested in your SDK environment and you believe it is ready for long-term use.
