## Provider Based Settings

A ProviderBased service (provider) will allow a developer to create and store settings in the Alkami database. Use the Alkami Admin portal to administer these settings. They are quickly available to the already running service in whichever environment the user has edited. A service can be deployed with default settings and the values updated at a later time when the user chooses.

## Refactoring an Existing Logical Service

Most SDK developers before Fall 2019 will have created a logical based service with a settings helper class that allowed the service to read settings. These settings are not editable from the admin portal and are encouraged to be updated with this guide.

### The Exchange Rates Service

For this example I'm going to refactor the existing Exchange Rates service from the Alkami Samples v2.1.1 (https://feeds.alkamitech.com/feeds/choco.dev/Alkami.SDK.Samples/2.1.1) (or earlier versions). This is a logical service that retrieves exchange rates from the publicly accessible https://api.gdax.com/products (https://api.gdax.com/products) API endpoint. We will see how to turn this service into a configurable, settings based service; referred to as a Provider Based Service or simply provider. We will create a couple settings for the service and change the distributed service type to inherit from the persistent ProviderBaseService class in place of the logical DistributedServiceBase. In addition, we'll create validations for our settings and enable them to be administered from Alkami's Admin Portal.

### Adding Setting Names

Each setting will need a name and the best way to set this up is by creating a new class in the "Data" project that will be referenced throughout the solution.

Create a new SettingNames class

Create a new folder in the Sample.MS.ExchangeRates.Data project called "Settings". Add a new C# class to the "Settings" folder and call it SettingNames.cs

SettingNames.cs

```
using System.Runtime.Serialization;

namespace Sample.MS.ExchangeRates.Data.Settings
{
/// <summary>
/// The names of the Exchange Rates service settings
/// </summary>
[DataContract(IsReference = true)]
public class SettingNames
{
/// <summary>
/// This setting name will represent the base https:// url
/// </summary>
[DataMember(EmitDefaultValue = false)]
public const string ExchangeBaseUrl = "ExchangeBaseUrl";

/// <summary>
/// The base url will be combined with the ApiResource to get a response
/// </summary>
[DataMember(EmitDefaultValue = false)]
public const string ApiResource = "ApiResource";
}
}
```

The members will be sent across the wire and should be attributed with the Serialization classes, as most things living in "Data" should.

### Refactoring and Expanding the Service Implementation

The existing Sample.MS.ExchangeRates.Service/ServiceImp.cs class will need to inherit from a new base class called "Plugin." This will require us to add some NuGet packages and implement some overrides in order to properly configure the service implementation as an Alkami Plugin. We'll start by turning the ServiceImp.cs into a "partial" class and adding two new C# files, also partial classes, called "ServiceImp.Headers.cs" and "ServiceImp.SettingManagement.cs." These new classes will be home to the new settings we've added, effectively keeping "ServiceImp.cs" class populated with business logic and not cluttered by the configuration tasks defined in the new headers and management classes.

We'll also add RestSharp as a dependency and refactor the GetRatesAsync() implementation to do away with the older HTTP request pattern currently in place.

using Alkami.TrackableObjects.Plugins;
using Sample.MS.ExchangeRates.Contracts;

namespace Sample.MS.ExchangeRates.Service
{
public partial class ServiceImp : Plugin
{
private string _providerName = "";

/// <summary>
/// Create a new service for this object
/// </summary>
/// <param name="providerType"></param>
public ServiceImp(string providerType) : base(providerType)
{
_providerName = GetType().AssemblyQualifiedName;
}

/// <summary>
/// Create a new service for this object
/// </summary>
/// <param name="providerType"></param>
/// <param name="providerName"></param>
public ServiceImp(string providerType, string providerName) : base(providerType, providerName)
{
_providerName = string.IsNullOrWhiteSpace(providerName) ? GetType().AssemblyQualifiedName : providerName;
}

/// <summary>
/// Don't change this on configurable microservices.
/// </summary>
public override string ItemType => "Connector";

/// <summary>
/// Defines the name of this microservice
/// </summary>
public override string Name { get => _providerName; }

/// <summary>
/// This is a friendly descriptive name of the service these configurations are a part of
/// </summary>
public const string StaticName = "Alkami Sample Exchange Rates Service";
/// <summary>
/// Our provider types can be customized. Any sample provider created by Alkami's SDK team will have the "SDKSample" provider type.
/// </summary>
public const string StaticProviderType = "SDKSample";
/// <summary>
/// This is the unique name of the provider. This cannot be shared with other providers and is usually the base namespace of this solution.
/// </summary>
public const string StaticProviderName = "Sample.MS.ExchangeRates";
}
}

ServiceImp.SettingManagement.cs

```
using Alkami.Data.Validations;
using Alkami.MicroServices.Settings.ProviderBased.Contracts;
using Alkami.TrackableObjects.Plugins;
using Sample.MS.ExchangeRates.Contracts;
using Sample.MS.ExchangeRates.Data.Settings;
using System;
using System.Collections.Generic;

namespace Sample.MS.ExchangeRates.Service
{
public partial class ServiceImp : Plugin
{

/// <summary>
/// Create default settings that the service expects when first being deployed, these can be anything you'd like them to be
/// </summary>
/// <returns></returns>
public override Dictionary<string, string> DefaultSettings()
{
var ret = base.DefaultSettings() ?? new Dictionary<string, string>();

// In this case we'll use GDAX as our default base url
if (!ret.ContainsKey(SettingNames.ExchangeBaseUrl))
{
ret.Add(SettingNames.ExchangeBaseUrl, "https://api.gdax.com");
}

// and add a /products resource, a valid endpoint that does not require auth
if (!ret.ContainsKey(SettingNames.ApiResource))
{
ret.Add(SettingNames.ApiResource, "/products");
}

return ret;
}

/// <summary>
/// Each setting is required to have a description, ehh.. a "descriptor" in this case, which will allow it to be edited from the admin portal.
/// Use the SettingDescriptor constructor to create a new descriptor for each setting name
/// </summary>
/// <returns></returns>
public override List<SettingDescriptor> SettingDescriptors()
{
var defaultSettings = new List<SettingDescriptor>();
defaultSettings.AddRange(base.SettingDescriptors());
defaultSettings.Add(new SettingDescriptor(SettingNames.ExchangeBaseUrl, "A base URL for the Exchange Rates service.", typeof(string), true, "Validated against a list of known exchanges", false));
defaultSettings.Add(new SettingDescriptor(SettingNames.ApiResource, "An API resource used in conjunction with the exchange base url", typeof(string), true, "Anything you'd like to send", false));
return defaultSettings;
}

/// <summary>
/// Each setting should be validated to the best of the developers ability. This will safeguard the implementation from messy configuration
/// </summary>
/// <param name="settingDescriptor"></param>
/// <param name="settingValue"></param>
/// <param name="errors"></param>
/// <param name="isValidated"></param>
/// <param name="performedValidation"></param>
protected override void ValidateChangedSetting(SettingDescriptor settingDescriptor, string settingValue, List<ValidationResult> errors, bool isValidated, ref bool performedValidation)
{
switch (settingDescriptor.Name)
{
case SettingNames.ExchangeBaseUrl:
{
// We want to make sure the user has a setting actually defined and that it is only calling our known exchange service
if (string.IsNullOrWhiteSpace(settingValue))
{
Logger.Error($"{settingDescriptor.Name} value is null or whitespace [{settingValue}]");
errors.AddValidationError(SettingNames.ExchangeBaseUrl, "Value is required", SubCode.ValueUnsupported);
isValidated = false;
}
Uri testUri = new Uri("https://api.gdax.com");
if (Uri.TryCreate(settingValue, UriKind.Absolute, out testUri))
{
if (testUri.Host.IndexOf("api.gdax") < 0)
{
Logger.Error($"{settingDescriptor.Name} value does not parse as a Uri [{settingValue}]");
errors.AddValidationError(SettingNames.ExchangeBaseUrl, "URL can only be within the api.gdax domain", SubCode.ValueOutOfRange);
isValidated = false;
}
}
else
{
// Unable to parse a URI from the setting
Logger.Error($"{settingDescriptor.Name} value does not parse as a Uri [{settingValue}]");
errors.AddValidationError(SettingNames.ExchangeBaseUrl, $"{settingDescriptor.Name} value does not parse as a Uri [{settingValue}]", SubCode.ValueOutOfRange);
isValidated = false;
}
performedValidation = true;
break;
}
case SettingNames.ApiResource:
{
// We don't care what the user puts here, this is as much validation as we'll need to do.
performedValidation = true;
break;
}
default:
{
Logger.Info($"{settingDescriptor.Name} value was not validated! Has it been defined within the DefaultSettings class and has it been added to the SettingsDescriptors collections?");
performedValidation = false;
break;
}
}
}
}
}
```

Refactor the existing ServiceImp.cs class

We'll change the class to "partial" and inherit from the "Plugin" base class. The "GetRatesAsync()" method has been refactored to use the "GetScopeAsync()" pattern to retrieve the settings. The RestSharp library is then used to create an HTTP client and send a request to the URL created by combining the two settings. The response is deserialized into an object and returned to the caller. The New Relic metrics are retained and logged as they were before.

IExchangeRatesServiceContract

This particular file is the implementation of our contract and the GetRatesAsync() public method. The IExchangeRatesServiceContract interface is required here but was not required when creating the partial ServiceImp.Headers.cs or partial ServiceImp.SettingManagement.cs as they are not responsible for implementing the GetRatesAsync() method.

ServiceImp.cs

```
using Alkami.TrackableObjects.Plugins;
using Common.Logging;
using Newtonsoft.Json;
using RestSharp;
using Sample.MS.ExchangeRates.Contracts;
using Sample.MS.ExchangeRates.Contracts.Requests;
using Sample.MS.ExchangeRates.Contracts.Responses;
using Sample.MS.ExchangeRates.Data;
using Sample.MS.ExchangeRates.Data.Settings;
using System.Collections.Generic;
using System.Diagnostics;
using System.Threading.Tasks;

namespace Sample.MS.ExchangeRates.Service
{
/// <inheritdoc/>
public partial class ServiceImp : Plugin, IExchangeRatesServiceContract
{
private static readonly ILog Logger = LogManager.GetLogger<ServiceImp>();

/// <inheritdoc/>
public async Task<RatesResponse> GetRatesAsync(GetRatesRequest request)
{
// new up some local variables
RatesResponse response = new RatesResponse();
string baseUrl = string.Empty;
string apiResource = string.Empty;

// GetScopeAsync() is how we retrieve settings using the request type of this service
using (var scope = await GetScopeAsync(request))
{
// we pick up our base and api resource urls
baseUrl = scope.GetSettingOrDefault<string>(SettingNames.ExchangeBaseUrl);
apiResource = scope.GetSettingOrDefault<string>(SettingNames.ApiResource);
}

// Do some metrics using the stop watch
Stopwatch stopwatch = new Stopwatch();
stopwatch.Start();

// Make the rest request out to the exchange api
RestClient client = new RestClient(baseUrl + apiResource);
var restReq = new RestRequest(Method.GET) { RequestFormat = DataFormat.Json };
var rawData = client.Execute(restReq).Content;

// stop the watch and record to new relic
stopwatch.Stop();
Alkami.Monitoring.Metric.RecordMetric("Custom/SampleMSExchangeRates/DataRetrievalTime", stopwatch.ElapsedMilliseconds);

// Deserialize the content
response.CurrentRates = rawData;
response.CoinsAndRates = JsonConvert.DeserializeObject<List<CoinDetails>>(rawData);

return await Task.FromResult(response);
}

}
}

```

This is a straightforward refactor where the inheritance type is changed and a couple new constructors are added. /// Our client proxy class used by the consuming application
/// </summary>
public class ServiceClient : ProviderBasedClient<IExchangeRatesServiceContract>, IExchangeRatesServiceContract
{
private const string ProviderType = "SDKSample";

/// <summary>
/// ProviderBased constructor
/// </summary>
public ServiceClient() : base(ProviderType)
{ }

/// <summary>
/// ProviderBased constructor override
/// </summary>
/// <param name="providerId"></param>
public ServiceClient(long providerId) : base(ProviderType, providerId)

Make code changes to the DistributedService.cs and Program.cs files

The distributed service will be changed to inherit from the "ProviderBasedService" base class. This requires a new constructor that needs the provider type and name to be passed as parameters to the base class. In addition to the new constructor, we'll need to enable this service to consume changes to it's settings originating from the Alkami Admin Portal. This is done by adding the Alkami.Broker lines seen below in the "OnStart()" method.

DistributedService.cs

```
using Alkami.MicroServices.Settings.ProviderBasedService;
using Sample.MS.ExchangeRates.Contracts;
using Sample.MS.ExchangeRates.Contracts.Requests;
using Sample.MS.ExchangeRates.Contracts.Responses;
using Sample.MS.ExchangeRates.Service;
using System;
using System.Threading.Tasks;

namespace Sample.MS.ExchangeRates
{
public class DistributedService : ProviderBasedService<IExchangeRatesServiceContract, ServiceImp>, IExchangeRatesServiceContract
{
private IExchangeRatesServiceContract _serviceContract;
private readonly string _providerName;
private readonly string _providerType;

/// <summary>
/// The new provider based service will require additional paramters during construction
/// </summary>
/// <param name="friendlyName"></param>
/// <param name="providerName"></param>
/// <param name="providerType"></param>
public DistributedService(string friendlyName, string providerName, string providerType) : base(friendlyName, providerName, providerType)
{
_providerName = providerName;
_providerType = providerType;
}

/// <summary>
/// The service implementation is instantiated and the Alkami.Broker setup is added in order to handle setting change events from the Admin Portal
/// </summary>
public void OnStart()
{
_serviceContract = new ServiceImp(_providerType, _providerName);

Alkami.Broker.ZeroMq.Setup.PublishUsingZeroMqLocally();
Alkami.Broker.ZeroMq.Setup.SubscribeUsingZeroMqLocally(_serviceCancellationToken.Token);
Alkami.Broker.App.Subscription.InitializeSubscriber();

base.Start();
}

/// <summary>
/// Typical service stop
/// </summary>
/// <param name="fromSeconds"></param>
public void OnStop(TimeSpan fromSeconds)
{
base.Stop(fromSeconds);
}

/// <inheritdoc/>
public Task<RatesResponse> GetRatesAsync(GetRatesRequest request)
{
return _serviceContract.GetRatesAsync(request);
}
}
}
```
