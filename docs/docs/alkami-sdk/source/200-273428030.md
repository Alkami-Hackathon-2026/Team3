Alkami has recently implemented additional validation rules to our deployment process in an effort to ensure the reliability and repeatability of installations. Some of these new rules will require updates to widgets and services. The purpose of this guide is to help navigate any changes associated with the new validation rules and to limit disruption in getting your components deployed to the Alkami environments.

#### Manifest Error: No AlkamiManifest.xml was detected in the root

The AlkamiManifest.xml has been included in the project templates for some time in preparation for our updated installation process to be implemented. Now that the new process is being implemented the location of the manifest needs to be moved to the root level of the of the chocolatey package from where it currently resides in the Host project. We have chosen to do this with a template update for the new services being created from this point forward but for existing projects we are asking that you make a change to the PreBuild event in the Host project of the service. The code below will replace what is currently in the PreBuild event and will copy the manifest to the root of the solution so that it can be included in the chocolatey package at the root level.

```
if $(ConfigurationName) == Release (
if exist "$(ProjectDir)InstallerOverrides\$(ProjectName).nuspec" (
xcopy "$(ProjectDir)InstallerOverrides\$(ProjectName).nuspec" "$(ProjectDir)Installer" /Y
)
if exist "$(ProjectDir)AlkamiManifest.xml" (
xcopy "$(ProjectDir)AlkamiManifest.xml" "$(SolutionDir)$(SolutionName)" /Y
)
)
```

In order to include the manifest in the chocolatey package you will need to add the file inclusion line below to the nuspec file in your host project.

```
<file src="..\..\AlkamiManifest.xml" target="AlkamiManifest.xml" />
```

After the addition of that file inclusion line your nuspec file should look something like this.

Sample Service.nuspec

```
<?xml version="1.0"?>
<package >
<metadata>
<id>Training.MS.ManifestLoc.Service.Host</id>
<version>1.0.0</version>
<title>Training.MS.ManifestLoc Service Host</title>
<authors>Alkami Technology</authors>
<owners>Alkami Technology</owners>
<requireLicenseAcceptance>false</requireLicenseAcceptance>
<description>Contains all the files and assemblies necessary to create and stand up a new instance of the Training.MS.ManifestLoc Micro Service.</description>
<copyright>Copyright 2023</copyright>
<dependencies>
<dependency id="Alkami.MicroServices.Choco.Installer.Logic" version="2.4.8" />
</dependencies>
<tags>ConfigurableMicroservice</tags>
</metadata>
<files>
<file src="..\bin\release\*" target="tools" />
<file src="*.ps1" target="tools" />
<file src="*.psm1" target="tools" />
<file src="..\InstallerOverrides\*.ps1" target="tools" />
<file src="..\..\AlkamiManifest.xml" target="AlkamiManifest.xml" />
<file src="..\..\..\**\*.*" target="src" exclude="**\Installer\**\*.*;**\Dependencies\**\*.*;**\obj\**\*.*;**\.vs\**\*.*;**\bin\**\*.*;**\tools\**\*.*;**\packages\**\*.*;**\.nuget\**\*.*;**\.git\**\*.*;**\.gitignore;**\node_modules\**\*.*;**\.suo;**\.user;**\tests\**\*.*;**\test\**\*.*" />
</files>
</package>
```

#### The chocolateyInstall.ps1 file tools/ChocolateyInstall.ps1 does not match the install file template so this submission will be cancelled.

The updating of the Alkami installation process has also changed the installers that are referenced in the packages from the Logic installer to the Service installer. The reference to the specific installer resides in the ChocolateyInstall.ps1 and ChocolateyUninstall.ps1 files and is a simple update for newer projects. However there are some additional steps that have to be taken if you are updating an older project that still has the Alkami.MicroServices.Installer.Logic package referenced.

We will start with the checking for that package first since the update is more involved.

1. Open your service project and navigate Host project.

2. Click on the Show All Files icon. (It is just to the left of the wrench). Now you will be able to see the installer file folders.

3. Expand the Installer folder in Solution Explorer and select the chocolateyinstall.ps1 and the chocolateyuninstall.ps1 files. Once these files are selected drag them down to the InstallerOverrides folder.

4. Delete all of the following files from the Installer folder, ChocolateyBeforeModify.ps1, Config.ps1 and Library.ps1.

5. Delete the configureInstaller.ps1 file from the root of the Host project.

6. Open the Host projects nuspec file in the Installer folder. There are several updates that you will need to make.

- Update the target in this line, <file src="..\bin\release\*" target="tools" />, from tools to app.
- Add this line to the files section, <file src="..\AlkamiManifest.xml" target="AlkamiManifest.xml" />.
- Remove the dependency for the Alkami Logic installer. It may read <dependency id="Alkami.MicroServices.Choco.Installer.Logic" version="2.4.8" /> or <dependency id="Alkami.MicroServices.Installer.Logic" version="2.4.8" />

When you are done it should look like the screenshot below.

7. In Solution Explorer right-click on the host project and select Manage Nuget Packages.

8. In the Nuget package manager click on the Installed tab and in the search box type installer.

9. If you have the Alkami.MicroServices.Installer.Logic installed please uninstall the package. If it is not installed you can skip this step.

10. Select the chocolateyinstall.ps1 and the chocolateyuninstall.ps1 files in the InstallerOverrides folder and drag them back to the Installer folder.

11. Open both the chocolateyinstall.ps1 and chocolateyuninstall.ps1 files.

12. I know that the top line says to not modify this file, just ignore that and replace the files with the following.

ChocolateyInstall.ps1

```
process {
& C:\ProgramData\Alkami\Installer\Services\install.ps1 $PSScriptRoot;
return;
}
```

ChocolateyUninstall.ps1

```
process {
& C:\ProgramData\Alkami\Installer\Services\uninstall.ps1 $PSScriptRoot;
return;
}
```

13. Once the content of those files are replaced and saved we need to make sure that automatic packaging of your project is enabled like we have in the newer templates. Right-click on the Host project and select Properties. In the left navigation of the Project Properties window select Build Events.

14. Remove the contents of the Pre-Build event and update the Post-Build Events with the content below and click the save all button in the toolbar.

Pre-Build Event

```
if $(ConfigurationName) == Release (
if exist "$(ProjectDir)AlkamiManifest.xml" (
xcopy "$(ProjectDir)AlkamiManifest.xml" "$(SolutionDir)$(SolutionName)" /Y
)
)
```

Post-build event

```
if "$(ConfigurationName)" == "Release" choco pack $(ProjectDir)Installer\$(ProjectName).nuspec -OutputDirectory $(ProjectDir)Installer
```

15. Now that we have the Build Events in place you can rebuild your solution. Make sure that you are in release mode so that it will create the Chocolatey package. Don't forget to bump the version!

16. The package is now build so let's verify that the package contains the updated installer files. Open the Host project in a File Explorer window by Right-clicking on the project in the Solution Explorer and selecting Open Folder in File Explorer.

17. In that File Explorer window open the Installer folder and right-click on the nupkg and open it with 7-Zip. In the tools folder you will have to scroll to find the chocolateyinstall.ps1 and chocolateyuninstall.ps1 files but once you do right-click on them and select view.

18. Verify that the content of the files matches what you replaced it with in Step 12. Once verified you can resubmit the project.
