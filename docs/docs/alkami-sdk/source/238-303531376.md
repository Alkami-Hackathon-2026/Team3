To begin, let's take a very simple component to use as a starting point. For this first example we are going to look at an "empty state" component that will be displayed when there are no results or items to display in another component.

#### Source File
EmptyState.vue

```
<template>
<div class="iris-empty-state">
<div class="iris-empty-state__inner">
<h3 class="iris-empty-state__title">{{ header }}</h3>
<p class="iris-empty-state__copy">{{ message }}</p>
</div>
</div>
</template>

<script lang="ts">
import Vue from 'vue';

export default Vue.extend({
name: 'empty-state',
props: {
header: {
type: String,
required: false,
default: 'Nothing to see here',
},
message: {
type: String,
required: true,
},
},
});
</script>

<style lang="scss" scoped>
.iris-empty-state__title {
font-size: 32px;
}

.iris-empty-state__inner {
max-width: 50%;
}

.iris-empty-state__copy {
font-size: 20px;
}
</style>

```

#### Test File
EmptyState.spec.ts

```
import { shallowMount } from '@vue/test-utils'; // Test utilities for Vue
import EmptyState from '../../../../Scripts/components/global/EmptyState.vue'; // Import the component from your project

describe('EmptyState.vue', () => { // Describe function creates a new test "suite" and is always the name of the file.
it('renders properly when props are passed in', () => { // Test case name (recommended to start with an action verb)
// Mount the component and pass in any mock data to the instance
const wrapper = shallowMount(EmptyState, {
propsData: {
header: 'test header',
message: 'test message',
}
});

// Capture the various elements or items to assert against
const title = wrapper.find('.iris-empty-state__title').text();
const message = wrapper.find('.iris-empty-state__copy').text();

// Assert the various items to be rendered as expected.
expect(title).toBe('test header');
expect(message).toBe('test message');
});
});

```

Things of note:

- The mounting methods (mount and shallowMount) come from the Vue test-utils library.Always use shallowMount if possible instead of rendering the entire children tree as well
- Each file contains a single describe statement corresponding to the file name of the component being tested
- There can be as many test cases under a single describe header
- Always have the expect assertions at the bottom of the test function.
