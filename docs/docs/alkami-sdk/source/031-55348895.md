## This includes notes for 2019.1.1.875 (Maintenance)
Permissions and Authorization

As part of the 2019.01 release, the platform teams have componentized RPSTS.

RPSTS now leverages the Authorization microservice to generate claims and returns four new permission claim types. These permissions can hold an unlimited amount of permissions, as opposed to the hard-coded number (144) limit, which prohibited addition of new permissions after we hit that number.

The following are the new claim types added with the new “expandable” design.

- UserPermissionsExpandable
- EntityPermissionsExpandable
- AccountPermissionsExpandable
- AllGrantedPermissionsExpandable

Since ORB deployment does not include RPSTS now one has to install RPSTS after deploying ORB. All design changes are backward compatible.

The SDK team has added the RPSTS and Authorization microservices as part of the of standard machine setup. Developers will now need to make sure these two services are running when using ORB.

Message Center Componentization

The message center has been componentized into it's own feature. It's no longer a part of the ORB Core distribution and will require a separate installation. This is a special feature in the sense that the WebClient Admin still has some dependencies to properly display message histories and notifications for users in a few of the admin views. This means that certain parts of the admin site will not be functional unless this feature is installed.

The development teams are working diligently to fully remove any dependencies and we look forward to updating you about this in future releases.

Moving forward...

The message center may not be the last feature that is required to run the full ORB site. There are other features that are required but they are mostly thought as a part of the basic functionality (authentication, accounts, settings, sitetext). The SDK Team will continue to provide additional support for these issues as we begin to solidify our internal process for managing these features.
