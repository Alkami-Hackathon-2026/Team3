## How to Install

The latest versions of Sidekick can always be found on our package repository, located here:

https://feeds.alkamitech.com/feeds/choco.dev/Alkami.Sidekick (https://feeds.alkamitech.com/feeds/choco.dev/Alkami.Sidekick)

To install from your machine, simply execute the following command.

Install Script

```
choco install Alkami.Sidekick -y
```

From there, simply open your start menu and search for Sidekick, and click to run the application. The application will request elevated administrator permissions when launched.

### WCF Microservice Request Tool (Key Gesture - Ctrl+R)

This tool allows the user to construct, replay, edit, or modify an existing microservice request to the targeted environment. Each request is sharable once saved and can be imported into other user's tool or saved into source control for later re-use. You can have an arbitrary number of open microservice requests simultaneously to work with multiple services at once.

#### Microservice Target Name

The microservice target is where you select the particular WCF microservice you wish to communicate with. The list will be composed of all registered microservices existing on the target environment and is refreshed with each opening of the dialog. As well, the version of the microservice will be displayed for reference, so you can be sure you're going to talk to the correct version you expect.

#### Microservice Request Name

The microservice request name is the specific service contract signature you wish to invoke on the specified service. After you have selected a service, clicking the magnifying glass icon for the request name will populate a list of available service signatures to invoke.

f you need to change the request you can click on the magnifying glass and it will bring up the modal in the previous screenshot with a list of requests.

#### Body Type

The body type is the specific class or subclass of request you can make to a microservice. For most microservice signatures, there will be only one option. However, various services allow you to specify subclasses when requesting a signature, such as the Risk Management microservice, and this lets you choose a specific request type to target for scaffolding.

#### Request Manipulation Tabs
##### Scaffolding and Request Construction

Scaffolding is the act of translating the running microservice's signature contract and generating a serialized version of the request, which you can then craft modifications or make extensions to.

For example, for signatures that are inserting data, we will automatically scaffold the required request data, and scaffold a sample item to insert into the collection. For fetch requests, we predefine filter, mapping, and sorter properties to use. From here, you can edit the JSON body text as you see fit. The text here will be serialized and sent to the target service when you submit your request.

Restrictions

You can verify the text is valid JSON by clicking the Show Parsed toggle - this will validate your JSON is correctly formed, although is does NOT validate the request conforms to the requirements of your target microservice. For example, if a given property is given an array of values, but the type does not support that, the request will fail to serialize. This failure will be reported in the status bar panel, so you can review and correct the error.

Customization

You can dynamically add subclasses to your JSON bodies. Supply an additional $type member on your JSON object with the fully qualified type name. For example, you can specify that a list of Contacts can be comprised of one Alkami.MicroServices.Contacts.Data.UnParsedAddress and one Alkami.MicroServices.Contacts.Data.Phone inside the same collection, and each can specify the appropriate properties (such as AddressLine1 or Phone) in the relevant JSON body.

##### Authentication

In addition to crafting the request body, you can customize the particular user you use to submit this request with. On the Auth tab, you can select the tenant and user from available filtering options. Additional context is shown when necessary to help you select the desired authentication context, from Service Admin accounts, to FI Admin Users. Selecting an FI Admin user will also allow optional specification of masquerading context.

You can also preview the claims.

When you are ready to make the call click the send button.

##### Response

The response tab will show the serialized response from the service when you send your request. It can be displayed in raw or JSON parsed format for easy consumption. When viewing the JSON response, you can collapse or expand node to easily visualize data, and double clicking any node will copy that content to your clipboard to use.

##### Assertions

Every request is created by default with a single assertion - "HasError = False". A microservice request is marked as a success when all assertions associated with it have passed; this means you can change an assertion to require an error, or add additional assertions to validate the response you receive. Each assertion can be defined using a JPath expression - this expression is evaluated for each response dynamically as you add, edit, or remove them.

Additional Resources

For more information on how to construct JPath expressions, visit https://goessner.net/articles/JsonPath/ (https://goessner.net/articles/JsonPath/). As you type your JPath expressions, the assertions tab will dynamically show you the output when the path matches eligible content.
