## Overview

The Standard SSO provides a generic means, through configuration, to interact with a wide variety of SSOs. The following documentation will provide insight into constructing the JSON configuration for the service.

Pro Tip

Unless you are very familiar with the SSO protocol you are going to implement, we suggest that you should begin by asking the 3rd party for a sample of the type of url, or request body, or assertion (if using SSAML) that is needed. That will make it much easier for you to know what you need to produce with the Alkami Standard SSO tool.

### AccountConfiguration RelationshipType Enum
- Unknown → 0
- PrimaryOwner → 1
- JointOwner → 2
- Linked → 3
- Aggregated → 4
- BusinessAccount → 5
### Expression Capable Locations

The following locations allow for expressions:

- HttpRequest → Uri
- HttpRequest → Body
- HttpRequest → FormFields → Values
- HttpRequest → Headers → Values
- HttpRequest → QueryParameters → Values
- Methods → Values
- Services → Http → Uri
- Services → Http → Body
- Services → Http → FormFields → Values
- Services → Http → Headers → Values
- Services → Http → QueryParameters → Values
- Services → Http → Thumbprint
- Services → Saml → Request → Subject
- Services → Saml → Request → Attributes → Values
### Configuration Tool

Configuration Tool

To help support the creation, validation, and testing of the Standard SSO's configuration, a configuration tool (https://feeds.alkamitech.com/feeds/choco.dev/Alkami.Microservices.StandardSSO.ConfigTool) was created. The tool has the following features:

- Supports generation of configuration through a visual designer.
- Validate configuration (using the Standard SSO's Engine).
- Evaluate configuration (using real or mocked responses).
- Provides several example configurations to help explore the Standard SSO's feature set.
- Allows for exporting the resulting request as a cURL request (which subsequently can be imported into Postman).If the result's URI is relative it will use the Request's RelativeUriHost from the Input Data tab as the host to build an absolute URI.

Install the configuration into your SDK using

```
choco install Alkami.Microservices.StandardSSO.ConfigTool
```

### Customizing Display and Navigation Behavior via Query Parameters

When linking to a Standard SSO from another widget, the display and navigation behavior can be customized via query parameters in the url. Some examples to consider would be:

- How should we open a Loan Payment SSO (with a Jarvis implementation) from the Accounts Widget via the Pay Now button?
- If my SSO opens a PDF file as a landing page, for example to have the user agree to a disclosure, how can I configure the Jarvis SSO widget to allow the end user to close the PDF file and still keep their session open in the platform. In some scenarios, when the the landing page is a PDF file, closing the PDF file actually closes the online banking window as well.
- If I initiate the SSO from a widget like Accounts or Quick Apply, how do I configure my Jarvis widget to go back to the Accounts or Quick Apply after opening the 3rd party's SSO window when they hit the back button instead of going back to the Jarvis widget?
#### Customizing Display Method

To change the display method from the option specified in the standard sso config, add the query parameter displayMethod to the link's url.

```
/StandardSSOUrl?displayMethod=SameWindow --Opens the sso in the same tab/window (_self)
```

```
/StandardSSOUrl?displayMethod=NewWindow --Opens the sso in a new tab/window (_blank)/StandardSSOUrl?displayMethod=Inline --Opens the sso in an iframe
```

Implementation Recommendations:

When "?displayMethod=SameWindow" is used, only a loading spinner will be displayed in the standard sso widget. This is usually a better user experience instead of displayMethod=NewWindow since the standard sso widget will be fully visible to the end user before opening the 3rd party site.

#### Customizing Navigation

When opening a standard sso from a link, the expected behavior when the user closes the tab or clicks the back button is that they are returned to the widget which opened the sso, not the standard sso widget. As an example, if the end user opens a Mortgage Transaction SSO from the Accounts widget via the "View Transactions" button, we would want the user to go back to the Accounts widget when they exit the 3rd party's site.

To accomplish this, add the query parameter backUrl to the link's url.

/StandardSSOUrl?backUrl=WidgetToGoBackTo --When user clicks back from the SSO, they should be back on the original widget

Notes:

This is not applicable to the native app. As of 3/3/2021, Alkami is working on getting this functionality working for Native apps.

On chromium based browsers (Chrome, Edge), pages that quickly get redirected are not added to the browser history. The backUrl query parameter will still need to be used to support other browsers.

#### Opening SSO in a browser on iOS

The iOS native app supports a query parameter to open links in a browser, instead of an in app WebView. This should be handled in the standard sso config by adding the query parameter "target": "browser".

### FAQ
##### Can you make it so it doesn't automatically sso when we go to the widget?

This is only possible when an additional step to choose which account needs to be sent to the SSO is required. Otherwise the experience will be to open the SSO right away to remove the burden of extra clicks from the end user.

##### Can you have multiple buttons for users to SSO to different sites?

This use case is more for Quick Links rather than an standard SSO. If each link accepts an SSO payload and can direct the user to different areas of the application, then a suggestion is to have different Standard SSO widgets for this or a custom widget that can handle this special case.

##### Business Configuration: I have a sub user with one of the listed Role Permissions, why am I getting an Insufficient Permissions page?

In the case of the Business User Configuration Role Permissions, it is an all or nothing condition. The Sub User must have ALL the permissions listed instead of one or the other.
