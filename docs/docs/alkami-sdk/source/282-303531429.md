If you are working with the Albus Webpack Preset (/spaces/SDKC/pages/303531420/Webpack+Preset) or the Vue Preset (/spaces/SDKC/pages/303531417/Vue+Preset), unit testing capabilities come out of the box with no configuration necessary. When executing npx albus test, Albus will look for test files that follow a specific naming pattern and execute the unit tests using Jest (https://jestjs.io/). Here are the file globs that are used to find the test files in a project:

| Preset | Glob |
| Webpack | **/__tests__/**/*.[jt]s?(x)**/?(*.)+(spec|test).[jt]s?(x) |
| Vue | **/__tests__/*.[jt]s**/tests/unit/**/*.spec.[jt]s |

While there are some slight differences in the file globs between the two presets, the structures are almost identical. Whatever files are matched in the above globs will be read in and executed by Jest and the result will be output to the console.

### Writing Tests

If you are unfamiliar with writing JavaScript unit tests, or are used to working in one of the other testing frameworks (e.g., Mocha, Jasmine) it is recommended to read up on Jest (https://jestjs.io/docs/en/getting-started) and how to write tests for it. While there are many concepts and syntax lifted from previous runners, there are some nuances that need to be adhered to. With that said, let's look at a test that is written for a simple JavaScript function:

Source Function | currency.ts

```
export function parseCurrency(input: string): number {
const negated = /-[\$0-9\.,]+|\([\$0-9\.,]+\)/.test(input);
const sanitized = (negated ? '-' : '') + input.replace(/[^0-9\.]+/g, '');

return parseFloat(sanitized);
}
```

And the corresponding tests:

Test File | currency.spec.ts

```
import { parseCurrency } from '../../util/currency';

test('parses simple currency string', () => {
expect(parseCurrency('$345.23')).toBe(345.23);
});

test('parses currency string with commas', () => {
expect(parseCurrency('$23,345.23')).toBe(23345.23);
});

test('parses zeroed currency string', () => {
expect(parseCurrency('$0.00')).toBe(0.00);
});

test('parses parenthesis currency string', () => {
expect(parseCurrency('($0.00)')).toBe(-0.00);
});

test('parses currency string with one cent digit', () => {
expect(parseCurrency('$23,345.2')).toBe(23345.20);
});

test('parses currency string with no cent digits', () => {
expect(parseCurrency('$23,345')).toBe(23345.00);
});

test('parses negative currency string', () => {
expect(parseCurrency('-$23,345.23')).toBe(-23345.23);
});
```

Creating tests is a three step process:

- Export the function that will be tested from its file using the export syntax
- Import the function into the corresponding test file
- Create as many test cases as needed invoking the method that was imported
### Running Tests

Once a test is written, running the test is straightforward in Albus. From a terminal, run npx albus test and the test files being executed will be shown in the console along with the result. By default, only pass or fail will be displayed:

If you would like to see the code coverage numbers as well, you will need to configure Jest to do so. To accomplish this, create a file named jest.config.js at the root of your widget or project and fill it with these contents:

jest.config.js

```
module.exports = {
collectCoverage: true,
collectCoverageFrom: [
'scripts/**/*.{ts,vue}',
'!scripts/api/**',
'!scripts/shims-vue.d.ts', // TypeScript shim file
'!**/node_modules/**',
],
coverageReporters: ['html', 'text-summary'],
}
```

These properties tell Jest to collect coverage, from these files, using a certain reporter. If you would like to read more about the configuration options, please see the configuration reference page (https://jestjs.io/docs/en/configuration#collectcoverage-boolean). ### Pulling Test Coverage in SonarQube

Currently SonarQube doesn't have support for pulling in .vue files that utilize TypeScript. It is on their Roadmap (https://jira.sonarsource.com/browse/MMF-1441) but no determinate timeline. If you would like to get ready for SonarQube or want to try and import into another Test Coverage reporter like Bamboo, You can enable the lcov reporter to your jest.config.js

jest.config.js

```
module.exports = {
collectCoverage: true,
collectCoverageFrom: [
'scripts/**/*.{ts,vue}',
'!scripts/api/**',
'!scripts/shims-vue.d.ts', // TypeScript shim file
'!**/node_modules/**',
],
coverageReporters: ['lcov', 'html', 'text'],
}
```
