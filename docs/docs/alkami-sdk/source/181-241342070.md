## Applicability

If you have properly installed the 2022.6 (or later) Alkami SDK, then there is nothing you need to do to use Alkami's "new navigation." In this case, the documentation below will help you to understand what was installed into your SDK machine.

If for some reason you cannot upgrade to the 2022.6 SDK release then the information below will describe the steps you will need to accomplish to install new navigation.

### Setup

This guide assumes that This SDK Platform Setup Guide (https://confluence.alkami.com/sdk/alkami-platform-machine-setup-48800506.html) has been run using Install-SDKRelease -Latest

While this will implement the new navigation into your local SDK and prepare the admin side with the correct permission it will currently not allow you to create/edit/update the menu configuration. This will have to be done through manually editing the json navigation files.

### *.dev.alkamitech.com Certificate Modifications

Go to Manage Computer Certificates

Make sure that your computer certificate for *.dev.alkamitech.com (https://dev.alkamitech.com/) is set up to include give full control to "Local Service" for use by the microservices.

### Install Choco Packages

Install the following packages that are needed in order to run Navigation Builder

| choco upgrade Alkami.Services.NavigationOrchestration Alkami.Admin.Widget.NavigationBuilder Alkami.Modules.Navigation Alkami.MS.Flags.Service.Host Internal.Services.Session -y Set-SDKServiceStartupType -ServiceName 'All' -StartupType 'Automatic'Set-SDKServiceStartupType -ServiceName 'Internal.Services.Session' -StartupType 'Automatic' |

After installation you may want to run

| Restart-SDKServices |
### Feature Flag

Ensure that the flag "EnableNavigationBuilder" is enabled in the feature.flag table.

Don't see that flag?
Update to the latest Alkami.MS.Flags.Service.Host

### Permissions

Make sure the the admin role your user is under has the "Manage Navigation" permission under Staff → Admin Roles

## Setting up Client For Navigation Builder

For SDK clients and others who do not have access to aws we are slowly updating our Alkami.Services.NavigationOrchestration to remove this dependency and allow everyone to use New Navigation.

There are a few manual steps involved right now until we can completely implement all service calls to route to a different file storage. The idea is that we can leverage our local file system to retrieve, store, and update the json configuration files.

### Local File Path and pre work

To make things easier we will be using the Orb Directory to store everything in. We want to maintain a similar folder structure as the one in s3.

The base path everything will go into is: C:\Orb\WebClient\s3

From this base we will identify all of the folder paths:

#### Static Assets (CDN javascript)

C:\Orb\WebClient\s3\cdn\navigation

The code in here will be 2 files. A minified js and minified css file. These files will be referenced in the Layout files for each theme. These files are required to render the actual navigation bar on the client orb site.

This code is identical to ALL FIs and can be retrieved from inspecting network calls in staging. We have included them here for convenience.

- alkami.modules.nav.min.css
- alkami.modules.nav.min.js
#### User Configuration Files

C:\Orb\WebClient\s3\navigations\BANKINSTANCEIDENTIFIER\FLAVORID\LOCALEID\DEVICE.JSON

- BankInstanceIdentifierThis can be found in your AlkamiMaster.dbo.tenant table.
- FlavorIdThe FlavorId you use here should be the FlavorId of the user's package you want to test. If you want to have this setup for all packages you will need to get those package ids and duplicate the folder structure using each FlavorId.
- LocaleIdThis will most likely just be English 1033 but if you want to test other languages simply create another folder with the other languages LocaleId
- Device.json (do not name your file this, use one of the file names below)desktop.json - This config file will be used when loading the desktop sitemobileweb.json - This config file will be used when loading the mobile web sitenative.json - This config file will be used when loading the native app Version 4xtablet.json - This config is currently not in use as the native team does not consume it yet

Just like the javascript and css files you can retrieve your FIs navigation configuration from the Alkami stage environment. Login to the member stage site with DevTools open so it can capture the network traffic (It will need to be on the Network tab). Once you land on the dashboard you will see a call in the stack that starts with "desktop.json?". Select that call and in the window to the right click on "Response". This is where you will copy the entire payload and put that into the folder listed above and named appropriately "desktop.json". Of course this will be different if you are logging into the mobile site and that should be just a swapping of the name to "mobileweb.json?".

If you have a stage match you will need to follow the instructions above for both DeveloperDynamic and your Stage Match tenant records as the BankInstanceIdentifier will be different.

We have included the default base configuration files here that can be edited to suite your needs.

- desktop.json
- mobileweb.json
- native.json
- tablet.json

Now that we have our file paths set up and the files there, Let's head over to the Alkami.Services.NavigationOrchestration installation folder, "C:\ProgramData\chocolatey\lib\Alkami.Services.NavigationOrchestration\lib".

We have introduced a new app setting. By adding this to the appsettings.json, the service will return back the local file path we created instead of the CDN url.

| "NavigationOrchestrationSettings": { "UseLocalConfigStorage": true} |

The complete Alkami.Services.NavigationOrchestration appsetting.json should match what is below.

### appsetting.json
| { "ServicePath": "navigation-orchestration", "ServiceName": "Alkami.Services.NavigationOrchestration", "NewRelic.AgentEnabled": "false", "NavigationOrchestrationSettings": { "UseLocalConfigStorage": true }} |

We have included the file here as a drop in replacement.

- appsettings.json
### Testing the update

Once you have completed the steps above there are a couple of things that need to be verified before we fire up the member site in your local SDK.

First you will need to verify that the Internal.Services.Session and Alkami.Services.NavigationOrchestration are both started in the services tab.

Finally make sure that the json configuration you pulled from stage is in place.

Now let's fire up the member site in the SDK and this should be what you see...or something close to it.

If for some reason you don't have a successful upgrade please create and SDK Support Incident.
