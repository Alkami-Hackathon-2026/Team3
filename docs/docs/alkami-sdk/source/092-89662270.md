If you are setting up an entirely new SDK environment, then no special steps are required. Proceed as documented on Alkami Platform Machine Setup (/spaces/SDKC/pages/48800506/Alkami+Platform+Machine+Setup)

### When upgrading to this release you will need to perform an extra step.

Before you install the upgrade to Alkami.MachineSetup.SDK you can run batch this file:

Put this into a windows .bat file

```
@echo Before running, launch powershell as admin and run
@echo stop-iisandservices
pause

del C:\Orb\WebClient\web.config
del C:\Orb\WebClientAdmin\web.config
del C:\Orb\AuditService\web.config
del C:\Orb\BankService\web.config
del C:\Orb\ContentService\web.config
del C:\Orb\CoreService\web.config
del C:\Orb\ExceptionService\web.config
del C:\Orb\IPSTS\web.config
del C:\Orb\MessageCenterService\web.config
del C:\Orb\NagConfigurationService\web.config
del C:\Orb\NotificationService\web.config
del C:\Orb\SchedulerService\web.config
del C:\Orb\SecurityManagementService\web.config
del C:\Orb\STSConfiguration\web.config
del C:\Orb\SymConnectMultiplexer\web.config
del C:\Orb\RP-STS\bin\Alkami.Utilities.dll
pause

@echo Now you can launch powershell as admin and run
@echo choco upgrade alkami.machinesetup.sdk
pause

```

Or you can run this one after installing the SDK upgrade.

Put these commands into a windows .bat file

```
copy C:\Orb\WebClient\new.web.config C:\Orb\WebClient\web.config
copy C:\Orb\WebClientAdmin\new.web.config C:\Orb\WebClientAdmin\web.config
copy C:\Orb\AuditService\new.web.config c:\orb\AuditService\web.config
copy C:\Orb\BankService\new.web.config c:\orb\BankService\web.config
copy C:\Orb\ContentService\new.web.config c:\orb\ContentService\web.config
copy C:\Orb\CoreService\new.web.config c:\orb\CoreService\web.config
copy C:\Orb\ExceptionService\new.web.config c:\orb\ExceptionService\web.config
copy C:\Orb\IPSTS\new.web.config c:\orb\IPSTS\web.config
copy C:\Orb\MessageCenterService\new.web.config c:\orb\MessageCenterService\web.config
copy C:\Orb\NagConfigurationService\new.web.config c:\orb\NagConfigurationService\web.config
copy C:\Orb\NotificationService\new.web.config c:\orb\NotificationService\web.config
copy C:\Orb\SchedulerService\new.web.config c:\orb\SchedulerService\web.config
copy C:\Orb\SecurityManagementService\new.web.config c:\orb\SecurityManagementService\web.config
copy C:\Orb\STSConfiguration\new.web.config c:\orb\STSConfiguration\web.config
copy C:\Orb\SymConnectMultiplexer\new.web.config c:\orb\symConnectMultiplexer\web.config
del C:\Orb\RP-STS\bin\Alkami.Utilities.dll
@echo
@echo now open cmd as admin and run IISRESET
pause

```

Within either of these batch files you will see that the extra step involves making use of the new web.config files that are included in the 2020.3 release. This is due to a change to the binding redirect for Common.Logging. Additionally, depending on your upgrade history there may be a dll file that needs to be removed from the bin folder in RP-STS.

If you are not comfortable with running the bat file, you can manually take the same steps that are listed to utilize the new web.config files. The machinesetup upgrade does not overwrite the web.config files. So you either need to delete certain files prior to the upgrade, or make use of a file named new.web.config that is included in the release package.

Note: If you are having trouble getting the subscriptions service to start, be sure you have run these steps as documented on Hardware and Software Requirements (/spaces/SDKC/pages/55347103/Hardware+and+Software+Requirements)

```
# run this to try to get all of the Alkami services stopped (they might already be using the ports you need to reserve)
stop-iisandservices

# Note: Run below 2 commands to reserve specific ports.
netsh int ipv4 Add excludedportrange protocol=tcp startport=12345 numberofports=2
netsh int ipv4 Add excludedportrange protocol=tcp startport=50000 numberofports=30

# Note: Run below 2 commands to enable listening on IPv4 and IPv6 respectively
netsh http add iplisten 0.0.0.0
netsh http add iplisten ::
```

You can download the batch files here

Note: If you have a stage-match database in your SDK and are connecting to your core, you should upgrade the chocolatey packages for your code when you upgrade the SDK. If you have a custom core provider, don't forget to upgrade those packages too. For example, if you are connecting to Symitar (you must do this for Symitar on this release) you would upgrade these:

choco upgrade Alkami.App.Providers.Multiplexer.Client

choco upgrade Alkami.App.Providers.Core.SymConnect

choco upgrade Alkami.MicroServices.SymConnectMultiplexer.Service.Host
