TITLE: FI Rebrand for SDK Components

On occasion we have Financial Institutions that undergo rebranding for various reasons. Here we have listed the requirements as it pertains to SDK components:

- Create New Widget Projects (FI's Responsibility): The FI needs to recreate each widget using the SDK template. This is crucial because the URLs, widget names, and links are more deeply integrated into the widgets than a script can typically alter.
- Transfer Existing Code (FI's Responsibility): The FI should move the code from the old widgets to the new projects to preserve functionality while updating branding.
- Namespace Renaming Caution (FI's Responsibility): We strongly advise against renaming the namespace as a shortcut, due to potential inconsistencies and faults in widgets. This step also falls under the FI's purview.
- Test and Submit New Widgets (Joint Responsibility): After the FI updates the widgets, they should undergo testing. We can assist in this process to ensure everything functions correctly with the new branding.
- Adjust Release Pipeline (Our Responsibility): Once the new widgets are tested and approved, our team (SDK) will manage the release pipeline and partner with the Alkami Release Management team. This includes uninstalling the old widget versions and installing the updated ones on our hosted platform.

The above steps would also apply to any Microservices that accompany or are paired with these widgets.
