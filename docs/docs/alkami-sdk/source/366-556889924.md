## Audience

This page is written for new joiners, developers, QA, and support engineers who need to understand how StandardSSO works end-to-end.

## Purpose

Standard SSO evaluates provider-specific configuration and user context to return one of the following:

- A renderable launch payload (URL/form/body/headers/token artifacts)
- An input state asking for more data
- A typed failure state with validation details
## High-Level Architecture
| Layer | Responsibility |
| Service Orchestration Layer | Receives contract requests, loads configuration, composes dependencies, invokes engine, maps response states |
| Rules and Expression Engine | Parses/validates config, builds expression graph, gathers required data, evaluates expressions, generates render request |
| Integration Layer | (EvaluateProvider) | Retrieves external data and generates secure payload artifacts (HTTP/SAML/JWT/encryption) |
| Persistence Layer | Stores configuration/template/history in sso schema tables |

## End-to-End Runtime Flow (GetSsoAsync)
- Request enters StandardSsoService with ProviderName and Parameters.
- Service opens data scope/context and fetches configuration JSON by ProviderName.
- Service creates EvaluateProvider via factory with all required helpers/utilities.
- Service calls Engine.Evaluate(...).
- Engine executes validation + evaluation pipeline.
- Service maps EvaluateResult to GetSsoResponse.
- Caller receives final State + RenderResult/DataSets/ValidationResults.

### Engine Pipeline
- Parse configuration JSON
- Validate configuration semantics
- Validate access restrictions and selection rules
- Build and validate expression graph + evaluation order
- Determine required external data and validate source compatibility
- Query external data via EvaluateProvider
- Evaluate expressions in order
- Generate client HTTP/SAML/JWT render artifact
- Return EvaluateResult (success or issue list)
### ValidateSsoAsync Flow
- Service calls Engine.Validate(configurationData)
- Engine performs parse + semantic validation checks only
- Response returns normalized issue list
### Response State Model
| State | Meaning | Typical Trigger |
| Render | Ready to launch/render | Engine success |
| Input | Caller must supply additional/valid input | Missing account/card selection, invalid parameters, speedbump not acknowledged |
| Error | Internal/configuration failure | Invalid JSON, invalid configuration, general error |
| NoEligibleAccounts | User has no eligible accounts | Account filtering rules OR user permissions |
| NoEligibleCards | User has no eligible cards | Card filtering rules OR user permissions |
| EmailMissing | Required email missing | User profile precondition |
| RestrictedAccess | Sub-user access restriction | Business user restrictions |
| MissingUserExtendedProperty | Required user property missing | Extended property gate |

### Data Access and Configuration Lifecycle (Used for standard SSO Admin)
- Configuration read path uses data scope + ConfigurationsContext.
- AddOrUpdateConfigurationAsync validates JSON with Engine.Validate before save.
- Save path is transactional.
- Session context username is set for DB trigger-based audit.
- New configuration can trigger widget + localizable resource setup* (see sitetext for standard sso widget below).
### Sitetext for standard sso widget
- Though entries are added into core.itemsetting table for standardsso widget under localizable resouce Itemtype when widget is created from standard sso admin.
- Actual sitetext for the widget are only created only when widget is actually opened (refer - SiteTextController)
### EvaluateProvider Responsibilities
- Resolve user/master-user context from security claims and security service.
- Fetch and filter accounts/cards per provider configuration.
- Fetch user/account extended properties as required by config.
- Fetch transaction/contact context where required.
- Generate secure output artifacts (encryption, SAML, JWT paths).

## Operational Failure Points and Handling
| Failure Class | Behavior |
| Missing provider config | Engine/service returns error state |
| Invalid configuration JSON | Validation issues mapped to Error |
| Invalid request parameters | Mapped to Input |
| No eligible entities | Mapped to NoEligibleAccounts / NoEligibleCards |
| Missing profile prerequisites | Mapped to EmailMissing / MissingUserExtendedProperty |
| External dependency failures | Issue list captured and mapped to response state |
| Payload generation failures | Mapped to Error with internal-safe messaging |
| Certificate expired | Exception captured and added to context issues. |

## Support/Dev/QA Quick Reference
- Fast triage: capture the provider name, and request payload; check service logs and reproduce with `GetSsoPlaygroundAsync` (standard sso admin - try now).
- Error cheat sheet: `ValidationError` = invalid config; `DependencyFailure` = external timeout/5xx; `NoEligibleAccounts`/`NoEligibleCards` = filtering rules; `RenderError` = payload generation failure.
- Where to look: Check for expired certificates if used. Check for expired client credentials. Engine logs for expression ids, EvaluateProvider traces for external calls, and `ConfigurationsContext` for stored JSON.
- Quick actions: re-run the scenario in the playground (standard sso admin), run Engine unit tests.
