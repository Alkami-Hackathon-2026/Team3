### Server Error 503

Typically due to the WebClient app pool being stopped. Go into the IIS Manager and look at the list of app pools and see if any are stopped. Restart the app as needed.

### Unable to Login (Developer Dynamic or Stage Match) Post Fresh Install/Upgrade

If the developer is unable to login to the member site and presented with the error screen below with the matching javascript error and logged error in the Alkami.MicroServices.Authentication.Workflow.Service.Host.log. The issue is more than likely with the new componetized scheduler service. The resolution is to force a reinstall of the same version of the Alkami.App.Service.Scheduler.Host package that is installed on a machine.

### When I build my widget in release mode I am getting something like 'HtmlHelper<dynamic>' does not contain a definition for 'CssWithCacheExpiration' and no accessible extension method 'CssWithCacheExpiration' accepting a first argument of type 'HtmlHelper<dynamic>' could be found (are you missing a using directive or an assembly reference?)

Most likely you need to add these to the top of all of your .cshtml view files

```
@using Alkami.Client.WebClient.Shared.Helpers
@using System.Web.Mvc.Html
@using Alkami.Client.Framework.Utility
```

When building in release mode, you are probably causing pre-compilation of the view files and these assemblies will need to be available at compile time for that to work.
