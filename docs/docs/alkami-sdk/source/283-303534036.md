The following documentation is intended to help resolve package validation checks.

Table of Contents

### MissingAssembliesCheck
- Description"The following assemblies are not included in the package..."
- IssueThe missing assemblies check verifies that all required assemblies that are referenced by the package are included in the final nuget package.
- Resolution stepsReview the missing package is referenced by your package. If the missing reference is already included at the correct version, then verify that your nuspec is including it. Learn more about the Nuspec format hereIf the missing reference is included but at a different version, adjust the version of the reference to match required version.

NOTE: You can verify if the missing assemblies are being included by inspecting the final nuget package.

### ApplicationIs32BitCheck
- Description"......contains a 32-bit application...."
- IssueThe microservice package is built with a preference to run as a 32-bit application.
- Resolution stepsReview the .csproj file for both debug and release configurations to ensure that the Prefer32bit property in the project is set to false.

### AppConfigFilesCheck
- Description"Invalid Configuration detected...."
- IssueThe microservice contains invalid configuration within it's config file (e.g. web.config, app.config) in any of the following areas:The "NewRelic.AppName" setting is configured as "REPLACEME".The "NewRelic.AgentEnabled" setting is configured as "false" or not set.
- Resolution stepsReview the configuration file and remove/update the settings contained within.

### ForbiddenAssembliesCheck
- Description"Package contains forbidden assemblies..."
- IssueThe forbidden assemblies check verifies that the package does not contain any assemblies which are no longer acceptable in production.
- Resolution stepsReview the package dependencies and upgrade version to meet the requirements.

### HostVersionCheck
- Description"Package contains forbidden assemblies..."Subscription service uses Assembly Versions as one of the conditions for contract binding. It is important that the Assembly Version in the service matches the contract it is implementing. Assembly Version does not control the package version. Package Versions are controlled through sem.ver.
- IssueThe host version check verifies that the assembly that contains the ProviderBasedService<T> implementation has a major/minor number that matches the major/minor number of the contract the service hosts.
- Resolution stepsFind the assembly that implements the DistributedServiceBase<T> or ProviderBasedService<T, TPlugin> implementation and then the assembly for the contract that is provided in the generic parameter T for either implementation. These two assembly versions must match in their major/minor numbers.In most cases, this can be fixed by making sure the assemblyInfo.cs in *.Service.Host folder matches up with assemblyinfo.cs in *.Contracts folders.

### NuspecDependenciesCheck
- Description"Nuspec contains invalid dependencies..."
- IssueNuspec Dependencies Check verifies that the submission package does not include any nuspec dependencies. More Info here
- Resolution stepsRemove all nuspec defined dependencies for the package in the .nuspec file.

### SharedDllsCheck
- Description"Package contains invalid assemblies ..."
- IssueThe shared DLLs check verifies that web extensions, providers, or widgets do not contain Orb shared dlls (e.g. Alkami.Common, etc.). More Info about shared .dlls here
- Resolution stepsReview the offending packages;If package dependency is not being used, then remove it completely as a package dependency.If package is required, check .nuspec file and remove line item that includes the .dll in final output.

### InvalidManifestCheck
- Description"Package contains an invalid Alkami Manifest ..."
- IssueThe Invalid manifest check verifies that the package includes a valid AlkamiManifest.xml in the final nuget package. More info on the manifest here.
- Resolution stepsReview the following;The final nuget package has an AlkamiManifest.xml at the root directory. The AlkamiManifest.xml is valid, all the xml elements are filled out. Reference the above confluence page for more information.

### LoggingConfigCheck
- Description"log4net.config should not leverage the following log levels ..."
- IssueThe log level specified in log4net.config is not an acceptable value. More info on the log levels
- Resolution stepsReview the following;Review the configured vaue and change it to one of the allowed values
