## Overview

This is a troubleshooting guide for seeing what needs to be investigated when you encounter an issue with a widget that's implemented in Standard SSO.

### Logs Source

Alkami.MicroServices.StandardSSO.Service.Host.log

Alkami.Client.Widget.StandardSso.log

### Where is the Configuration?

Configuration for Standard SSO can be found in the sso schema under the Configuration table.

The ProviderName will match the slug value of the Widget we're looking for the Configuration.

## Troubleshooting
### Invalid Configuration
#### Issue

InvalidConfiguration error in the Alkami.MicroServices.StandardSSO.Service.Host.log. These will occur when expressions are not properly written.

```
DEBUG2020-10-28 04:02:09 – GetConfigurationData: ConfigurationId - 78554577-9de6-43cd-9085-5868977156d1, ProviderId - TestSSO, StatusCode: OK
DEBUG2020-10-28 04:02:09 – Syntax error ('Unknown expression detected.') occurred in HttpRequest.QueryParameters for the expression: {{ AccountNumbers }}
DEBUG2020-10-28 04:02:09 – Success: False, Issue Count: 1
TRACE2020-10-28 04:02:09 – Issue Code: InvalidConfiguration, Message: Syntax error occurred in HttpRequest.QueryParameters for the expression: {{ AccountNumbers }}
```

#### Solution

In this specific error AccountNumbers is not a valid parameter to use, the correct parameter should be AccountNumber. The logs will describe the invalid expression that needs to be fixed.

```
Syntax error ('Unknown expression detected.') occurred in HttpRequest.QueryParameters for the expression: {{ AccountNumbers }}
```

You can find a list of the valid expressions here (https://confluence.alkami.com/display/ISG/Standard+SSO+-+Expression+Glossary#StandardSSO-ExpressionGlossary-Expressions).

### Invalid JSON
#### Issue

Deserializing JSON failed error in the Alkami.MicroServices.StandardSSO.Service.Host.log.

```
DEBUG2020-10-28 04:25:49 – GetConfigurationData: ConfigurationId - 78554577-9de6-43cd-9085-5868977156d1, ProviderId - TestSSO, StatusCode: OK
DEBUG2020-10-28 04:25:49 – Deserializing JSON failed.
```

#### Solution

The JSON schema provided for the SSO is not valid and will need to be fixed. You can use the Configuration Tool (https://confluence.alkami.com/display/ISG/Standard+SSO#StandardSSO-ConfigurationTool) to help you write a correct JSON schema for the SSO.

### Configuration Not Found
#### Issue

NotFound error in the Alkami.MicroServices.StandardSSO.Service.Host.log.

```
DEBUG2020-10-28 04:42:24 – GetConfigurationData: ConfigurationId - 78554577-9de6-43cd-9085-5868977156d1, ProviderId - TestSSO, StatusCode: NotFound
WARN 2020-10-28 04:42:24 – GetConfigurationData: Unable to pull configuration. ConfigurationId - 78554577-9de6-43cd-9085-5868977156d1, ProviderId - TestSSO, StatusCode: NotFound
DEBUG2020-10-28 04:42:24 – No configuration data provided.
DEBUG2020-10-28 04:42:24 – Success: False, Issue Count: 1
TRACE2020-10-28 04:42:24 – Issue Code: InvalidJson, Message: Configuration was not provided.
```

This error can happen for the following reasons:

- The provider has not been defined for the requested ConfigurationId (FI)
- The provider name does not match
#### Solution

Make sure that the ProviderName in the sso.Configuration table matches the second part of our Slug in core.Widget table.

### Forbidden
#### Issue

I'm getting the Forbidden error in the Alkami.MicroServices.StandardSSO.Service.Host.log.

```
Response:
StatusCode: 403, ReasonPhrase: 'Forbidden', Version: 1.1, Content: System.Net.Http.StreamContent, Headers:
{
Connection: keep-alive
x-amzn-RequestId: xyz

Date: Mon, 19 Oct 2020 22:33:59 GMT

{"message":"Forbidden"}
```

#### Solution

Verify that the ALKAMI.API_GATEWAY_URL environment variable is correct.

- System Properties -> Environment Variables -> System Variables
- Find Variable called ALKAMI.API_GATEWAY_URL
- Example for development: https://xyz.execute-api.us-east-1.amazonaws.com/dev/

### Pop Up Blocking
#### Issue

Standard SSO will try to open SSOs automatically when it can. A lot of times these pop ups will be blocked by the user's browser. Most cases the user will be able to just click the open button and continue. There might be a more rare case though where the user can never open the SSO because the pop up is always blocked.

#### Solution

In this case the user will be required to allow pop ups

### iPhone not working with iFrame
#### Issue

StandardSSO Widget does not load on iPhone mobile web. After clicking the launch button, the loading icon spins and reloads the same screen. Works fine on desktop and mobile view from desktop. After reviewing CHLS logs you'll see the cookies are not set.

Solution

Increased security prevents cookies from different domains to function properly within iframes which is enabled by default for iPhones. For iFrames to work if they depend on cookies they need to be loading a domain that share the same host. This can be achieved by using a DNS record so the cookies are not blocked due to cross-site restrictions. Instead of the iframe loading from the main domain (ie. www.mainDomain.com (https://www.billerpayments.com/)) it would need to load as a subdomain of URL to avoid issues with cross-site cookies. Please refer to documentation on cookies - https://andrewlock.net/understanding-samesite-cookies/ (https://andrewlock.net/understanding-samesite-cookies/).

## FAQ
##### How do we configure sitetext for "individual widgets"? I only see the base widget in admin; And I updated site text, but it doesn't seem to reflect in any of the individual widgets I have configured.

SiteText entries are generated when the widget loads for the first time, you'll have to view the widget first. There is logic in the SiteText controller to insert the appropriate entries into the database but it only happens upon viewing the widget for the first time. The values can then be updated via the Admin widget.

##### Why is SiteText Admin missing a namespace for my widget?

SiteText Admin will show namespaces retrieved from sitetext.Namespace table in the Master database and will display only those that match with the Widget names for the current FI doing so case sensitively.

Make sure the core.Widget Name for your current widget, matches case sensitively the sitetext.Namespace Name.

For Standard SSO widgets the comparison for the Namespace Name is AssemblyInfo + Name.

##### How does caching in the widget work? Can we get a walk through of that? I've noticed that after the ms errors out for Meridianlink, clicking on other tiles like google, genericurllauncher are all showing error page and the break point in the ms was not getting hit for a few attempts. B.P in ms started hitting again after a few clicks.

Restarting the SiteText service will not help; it only contains the master site text entries.

There shouldn't be any caching in the widget or the microservice at this point other than the site text javascript endpoint in the SiteTextController.

##### Is the Standard SSO config in the database cached?
No. After updating the configuration in the database, the sso configuration changes will take effect immediately and you will see the changes in the Standard SSO widget.
##### Can you remove the SSO button completely and just have the site text?
No. What is the purpose of the ask if the widget won't integrate with the SSO? Reason from the FI is that the vendor isn't ready yet and they just want to widget to have a message for the end user to say the SSO will be operational when the vendor is ready. A suggestion is to have them have a campaign for this since that is not the purpose of Jarvis.
##### Can you make it so it doesn't automatically sso when we go to the widget?
This is only possible when an additional step to choose which account needs to be sent to the SSO is required. Otherwise the experience will be to open the SSO right away to remove the burden of extra clicks from the end user.
##### Can you have multiple buttons for users to SSO to different sites?
This use case is more for Quick Links rather than an standard SSO. If each link accepts an SSO payload and can direct the user to different areas of the application, then a suggestion is to have different Standard SSO widgets for this or a custom widget that can handle this special case.
##### Business Configuration: I have a sub user with one of the listed Role Permissions, why am I getting an Insufficient Permissions page?
In the case of the Business User Configuration Role Permissions, it is an all or nothing condition. The Sub User must have ALL the permissions listed instead of one or the other.
##### How to configure a signed certificate using SHA256RSA?

If you find that the signed certificate is using SHA256RSA you will need to configure additional settings which include SignatureMethod and DigestMethod. To determine the Signed algorithm, go to the Details tab of the certificate and review the 'Signature algorithm' value

An example of what the Jarvis config might look like:

"SigningParameters": {
"Thumbprint": "1111111111111111111111111111111111",
"SignatureLevel": "Response",
"IncludeTransform": true,
"SignAssertionsOnly": true,
"CanonicalizationAlgorithm": "http://www.w3.org/2001/10/xml-exc-c14n# (https://www.w3.org/2001/10/xml-exc-c14n)",
"SignatureMethod": "http://www.w3.org/2001/04/xmldsig-more#rsa-sha256 (https://www.w3.org/2001/04/xmldsig-more#rsa-sha256)",
"DigestMethod": "http://www.w3.org/2001/04/xmlenc#sha256 (https://www.w3.org/2001/04/xmlenc#sha256)"
},

Standard SSO - HTTP Services#SAMLSigningandEncrypting (https://confluence.alkami.com/display/ISG/Standard+SSO+-+HTTP+Services#StandardSSOHTTPServices-SAMLSigningandEncrypting)

##### How to limit business users (sub-users) by specific account types, permissions, and/or core names separate from retail users?
When we need to limit business users by different criteria we can create two different widget entries each with it's own Configuration and assign them to the differing packages for the users that need them.
##### When I delete configuration for an implementation that has no history, I get a 404 response via Postman. Is this an issue?

No, this is not an issue. This is expected when you try to retrieve the configuration when it no longer exists. More information in DEV-107065 (https://jira.alkami.com/browse/DEV-107065) - Getting issue details... STATUS .

sso.ConfigurationHistory (Configuration Auditing)

A history record gets created in sso.ConfigurationHistory table during insert and update of records into sso.Configuration through a db trigger. The trigger info can be found in sso.Configuration table.

The stored procedure ([sso].[AddOrUpdateConfiguration]) that was created for adding history records will be obsoleted; Configuration can be added and updated by Insert/update sql statements and history records will be auto populated by the trigger.

Details of the trigger is also documented in this ARD

Standard SSO - DEV-108601 Create database trigger for sso.Configuration to auto-create History records (http://confluence.alkami.com)

##### I need to send a specific set of data when the User is in Mobile vs Desktop, how can I achieve this?

Standard SSO doesn't support conditional operators, the suggested approach is to provide separate configurations for Mobile and Desktop in their own widget and have the widget settings display only for Mobile and Desktop respectively.
