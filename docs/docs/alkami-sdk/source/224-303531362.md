### Folder Structure

Before we dive too much deeper, let's take a look at the overall folder structure of a Vue application.

Vue Application File Structure

```
├── Scripts
│ ├── api # Endpoint communication
│ │ ├── index.ts # Barrel file that exports all request functions
│ │ ├── users.ts # Individual file encapsulating request methods
│ │ └── ...
│ ├── components # All application Vue components logically grouped as needed
│ │ ├── form
│ │ │ ├── TextInput.vue # All component files names should be in PascalCase since they are a class
│ │ │ ├── AccountDropdown.vue
│ │ │ └── ...
│ │ ├── modal
│ │ │ ├── AddAccount.vue
│ │ │ ├── AddPayee.vue
│ │ │ └── ...
│ │ ├── payees
│ │ │ ├── Payee.vue
│ │ │ ├── PayeeForm.vue
│ │ │ └── ...
│ │ ├── shared
│ │ │ ├── Loader.vue
│ │ │ ├── LoaderLarge.vue
│ │ │ └── ...
│ │ └── ...
│ ├── directives # Custom Vue directives to be imported in app.ts
│ │ ├── focus.ts
│ │ └── ...
│ ├── interfaces # TypeScript interfaces that can be imported in various files. Each file should be a single exported interface
│ │ ├── IBaseResponse.ts
│ │ ├── IPayee.ts
│ │ ├── IAccount.ts
│ │ └── ...
│ ├── store # Global store files for Vuex
│ │ └── modules # Optional if breaking up store modules is desired. If a small project, consider putting everything into the index.ts file.
│ │ │ ├── activity.ts
│ │ │ ├── payment.ts
│ │ │ └── ...
│ │ └── store.ts
│ ├── styles # Global scss files to be shared across the application. These should ONLY be variables.
│ │ ├── _animation.scss
│ │ ├── _colors.scss
│ │ └── ...
│ ├── utils # Each of these files should export any function they want to make available
│ │ ├── localStorage.ts
│ │ ├── userStorage.ts
│ │ ├── dom.ts
│ │ └── ...
│ ├── views # Components dedicated to specific routes / pages. These map directly to routes defined in the router.
│ │ ├── Dashboard.vue
│ │ ├── Manage.vue
│ │ ├── Activity.vue
│ │ └── ...
│ ├── app.ts # Main entry point of the application, will import App.vue
│ ├── App.vue # Main application Vue component
│ ├── router.ts # Routes and routing related code
│ ├── shims-vue.d.ts # Definition file to help with TypeScript typings for modules
│ └── ...
├── server # Miragejs mock server for albus-module-cypress e2e testing
│ ├── index.ts # Contains createMockServer, which specifies mock server routes
│ ├── mocks # Scaffolding and service response mock data
│ │ ├── entities # Mock data entities for API responses
│ │ │ ├── accounts.ts # Name appropriately based on the entities it will contains
│ │ │ └── ...
│ │ ├── accountScenario.ts # File is named the same as the E2E scenario. See "tests/e2e/specs".
│ │ ├── errorScenario.ts
│ │ ├── index.ts # Should export its relatives for easy importing
│ │ └── ...
│ └── ...
├── tests # Jest setup files and utility scripts
│ ├── globalSetup.js # Optional
│ ├── e2e
│ │ ├── modules # End-to-End Test Specs
│ │ │ ├── accountInputTests.js # File is named the same as its respective scenario with "Test" as the suffix
│ │ │ ├── errorTests.js
│ │ │ └── ...
│ │ ├── plugins # Cypress Plugins
│ │ │ └── index.js # Contains the file and folder configuration referenced by "cypress.json"
│ │ ├── specs # Test Scenarios for Cypress E2E
│ │ │ ├── accountInputScenario.js # Each scenario lives separately from its tests for maintainability
│ │ │ ├── errorScenario.js
│ │ │ └── ...
│ │ ├── support # Supporting utilities for E2E testing
│ │ │ ├── commands.js # Extra commands for Cypress
│ │ │ ├── index.js
│ │ │ └── ...
│ │ └── ...
│ ├── mocks # Data mocks for various tests
│ │ ├── payees.ts
│ │ ├── accounts.ts
│ │ └── ...
│ ├── unit # Test folders for various categories of tests
│ │ ├── components # Vue component testing
│ │ │ ├── TextInput.spec.ts # File is named the same as the component with ".spec" as the suffix
│ │ │ ├── AccountDropdown.spec.ts
│ │ │ └── ...
│ │ ├── utils # Various tests for utility functions
│ │ │ ├── translation.spec.ts # File is named the same as the source file with ".spec" as the suffix
│ │ │ ├── localStorage.spec.ts
│ │ │ └── ...
│ │ └── ...
│ └── ...
├── .browserslistrc # Listing of browsers we support to be used in SCSS compilation
├── .npmrc # Helper file that defines the Alkami npm feed to use for internal dependencies
├── albus.config.js # Albus configuration for the project. See albus-preset-vue for specific documentation
├── cypress.json # E2E configuration file. See albus-module-cypress for specific documentation
├── jest.config.js # Optional if needing to override certain options in Albus
├── package.json # See albus-preset-vue for dependencies required for a Vue project
├── postcss.config.js # CSS config for SCSS compilation
├── tsconfig.json # TypeScript configuration file
└── ...
```

#### The Breakdown

This is a brief description of the various folders in the overall project diagram above. Each major section has its own dedicated documentation that goes into more detail and walks through the implementations of each.

##### API

This is where all of the API requests exist that the application will leverage. Every request is exported and available to be imported one at a time or all at once.

##### Components

All components of the application live here. These can be broken up or grouped by folder in whatever way makes the most sense for the codebase.

##### Directives

Custom Vue directives to be imported globally or at a component level.

##### Interfaces

All TypeScript interfaces for all data that the application will leverage. Every file constitutes a single interface that is exported and can be consumed by a component.

##### Router

The Vue router definition.

##### Store

The VueX store definition. For smaller projects this will be a single file with all properties listed and separated into modules for larger projects consisting of more complex stores.

##### Styles

Global stylesheets that need to be shared across multiple components. These should ONLY be variable files or styles for third party libraries.

##### Server

JavaScript Service mocks using MirageJS for End-to-End testing scenarios. (albus-module-cypress)

##### Tests

JavaScript unit testing files to be executed with Jest.

##### Utils

Basic utility functions that various methods will utilize (e.g. local storage manager).

##### Views

The main views of the application. These should map 1:1 to route definitions in the Vue router definition.

##### Main.ts

The main application file and the entry point for Webpack to begin analyzing the codebase. This is the file that will ultimately be referenced in your index.cshtml file.

##### App.vue

The main Vue component that the Vue instance will mount in the main.ts file.
