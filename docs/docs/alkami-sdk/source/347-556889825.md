## Overview

StandardSSO Admin allows for the viewing, editing, creation, and testing of StandardSSO configurations from an FI's admin site. Previously, this was only available by interacting directly through the DB or with a SuiteTI tool (for Alkami employees). StandardSSO admin empowers the FI themselves to handle things in a more self-serve manner, with the end goal being the ability to set up a new StandardSSO integration end to end without Alkami involvement.

### Access

Access to StandardSSO Admin is controlled by a feature flag at the FI level and a role permission at the user level.

##### Feature Flag

EnableStandardSSOAdmin under Internal.StandardSSOAdmin must be enabled for the FI or the activity will not be available for any users.

This would typically be done via scripts/DST, but can be manually performed via SuiteTI in environments higher than DEV (if you need to update/add the flag to a DEV1 DB, the table to update is Feature.Flag):

##### Permission

User role must have "StandardSSO Admin" permission (in Setup section)

## Functionality
### View/Search Existing Integrations

The landing page shows all existing StandardSSO configurations, the corresponding widget name, and the date of the last modification (or creation, if new). They can be sorted by the name, widget, or modification date by clicking the column headers. Additionally, you can search by name using the search bar.

### View/Edit Configuration

The edit page allows users to view and edit the selected StandardSSO configuration. It can be accessed by clicking "Edit" button on the landing page.

See View/Edit Configurations (/spaces/SDKC/pages/556889871/View+Edit+Configurations) for more in-depth information.

### StandardSSO Creation

The create page allows users to create new StandardSSOs using a pre-made template for known integrations or an empty template otherwise. It also creates the associated widget.

See SSO Creation (/spaces/SDKC/pages/556889855/SSO+Creation) for more in-depth information.

### Try Now

The Try Now page allows admins to test a configuration with a specific user directly within admin without needing to VAU or make navigation/package changes to give widget access.

See Try Now (/spaces/SDKC/pages/556889862/Try+Now) for more in-depth information.

### Configuration History

The history page shows all changes made to a configuration since its creation, including changes made outside of StandardSSO admin (i.e. DSTs or manual database changes). The line that says "INSERTED" indicates the creation of the config.

Clicking "View Changes" will show the configuration before and after the changes side by side.

It can be accessed by clicking the "History" button from the landing page or configuration edit page.

### Templates

StandardSSO templates are the driving force of interacting with a given config via StandardSSO Admin. The template defines how a config should be configurable and appear within Admin.
See the following for existing templates and where they live: https://gitlab.mgmt.alkami.net/WIDD/alkami.microservices.standardsso/-/tree/develop/Alkami.MicroServices.StandardSSO.Migrations/Migrations/Templates (https://gitlab.mgmt.alkami.net/WIDD/alkami.microservices.standardsso/-/tree/develop/Alkami.MicroServices.StandardSSO.Migrations/Migrations/Templates)

The following tool was created to automate the intricate process of converting a raw StandardSSO config into a template to then be used in Admin.
See the following which contains a README for more information: https://gitlab.mgmt.alkami.net/WIDD/standardssotemplater (https://gitlab.mgmt.alkami.net/WIDD/standardssotemplater)
