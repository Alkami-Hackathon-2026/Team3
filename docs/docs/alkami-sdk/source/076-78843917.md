A nuspec file is a specification file that is used to create a Nuget as well as a Chocolatey package. Most of the file contents depend on the component that is being packaged but some of it is common for all Alkami packages. To provide a standard experience across all packages, we have standardized the values of many of the metadata properties to the following:

### Metadata Standards

The build script should replace the $version$ with the appropriate version number for the package at build time. You must change the other values to the appropriate values for the package. The projectUrl property references a page on the Alkami Confluence Wiki. After creating your component, create a new page under the appropriate section on the wiki using the Package ID as the header on the page which defines the URL.

Any .nuspec file

```
<<?xml version="1.0"?>
<package>
<metadata>
<id>{Replace with Package ID}</id> (unique identifier, the namespace of the C# startup project)
<version>$version$</version>
<title>{Put a meaningful title here}</title> (human readable named title of the package)

<authors>Alkami Technology, Inc</authors> (or Financial Institution name)
<owners>Alkami Technology, Inc</owners> (or Financial Institution name)
<projectUrl>https://confluence.alkami.com/sdk</projectUrl> (or any relevant Financial Institution location)
<iconUrl>https://www.alkami.com/files/alkamilogo75x75.png</iconUrl> (or Financial Institution logo)
<licenseUrl>http://alkami.com/files/orblicense.html</licenseUrl> (or Financial Institution license url, otherwise use Alkami)
<requireLicenseAcceptance>false</requireLicenseAcceptance>
<description>{Put a meaningful description here, another developer or product owner should read this and know the purpose of this component}</description>
<releaseNotes>The initial re</releaseNotes>
<tags>ConfigurableMicroservice</tags>
<copyright>Copyright (c) {YearCreated} Alkami Technology, Inc</copyright> (or Financial Institution name)
</metadata>
<files>
<!-- The following defines where to find the files for packaging and what to exclude-->
<file src="tools\chocolateyInstall.ps1" target="tools" />
<file src="tools\chocolateyUninstall.ps1" target="tools" />
<file src="AlkamiManifest.xml" target="AlkamiManifest.xml" />
<file src="**\*.*" target="src" exclude="**\obj\**\*.*;**\.vs\**\*.*;**\bin\**\*.*;**\packages\**\*.*;**\.nuget\**\*.*;**\.git\**\*.*;**\.gitignore;**\node_modules\**\*.*;**\.suo;**\.user;**\Tests\**\*.*;**\Test\**\*.*;**\UnitTest\**\*.*;**\UnitTests\**\*.*;**\tools\**\chocolatey*.ps1" />

<!-- bin files | define the libraries that should be a part of this package -->
<file src="bin\USBFI.Client.Widget.ToyFair.*" target="lib" exclude="**\*.config"/>

.....
</files>
</package>
```

### Files

When including files for a package, use the following governance to decide which files are included in the package.

- Library PackagesInclude pdb and xml files for every assembly included.
- Microservices PackagesSpecify the assembly name to include all necessary assemblies from your bin folder.
- Componentized Packages (such as Widgets and Providers)Include the assemblies produced by your componentized package.Include all microservice clients (and supporting assemblies such as contracts, data, and validations) that your component references.Do not include any assemblies that can be found in the Orb Shared folder, such as:Alkami.Ioc.dllAlkami.Services.Subscriptions.ParticipatingClient.dllAlkami.Services.Subscriptions.Resolver.dllAlkami.MicroServices.Settings.ProviderBasedClient.dll
