Bootstrapping Cypress is a relatively straightforward process. We just need to define a few files that Cypress will use to run and structure our tests:

- tests/e2e/plugins/index.js
- tests/e2e/support/commands.js
- tests/e2e/support/index.js
- cypress.json

To start, we need to define our configuration, and then install albus-module-cypress.

cypress.json

```
{
"pluginsFile": "tests/e2e/plugins/index.js",
"baseUrl": "http://localhost:8080"
}
```

- pluginsFile — This defines the location for Cypress plugins, which should always be under "tests/e2e/plugins".
- baseUrl — This is the URL to your MirageJS service mocks, which we'll get into in the Mocking Services with MirageJS section.

```
npm install --save-dev albus-module-cypress
```

### Cypress Plugin Configuration

Now that we've pointed Cypress to "tests/e2e/plugins/index.js", let's define it. This file will simply tell Cypress where to look for everything:

tests/e2e/plugins/index.js

```
module.exports = (on, config) => {
return Object.assign({}, config, {
fixturesFolder: 'tests/e2e/fixtures',
integrationFolder: 'tests/e2e/specs',
screenshotsFolder: 'tests/e2e/screenshots',
videosFolder: 'tests/e2e/videos',
supportFile: 'tests/e2e/support/index.js'
});
};
```

Really, the most important items here that we've specified is the integrationFolder and supportFile.

- fixturesFolderFixtures are used to load a fixed set of data located in a file. Since we're using a mock server, we probably won't use this much. But we want to define it so that Cypress knows where to look if we do end up defining some.
- integrationFolderThis is important because it is where we define our scenarios and reference our test cases.
- sceenshotsFolder, videosFolderThese are output directories for screenshots and videos that Cypress has the capability to output. Because this is an artifact output directory, it must be added to our project's .gitignore to prevent accidental commits of unnecessary media.
- supportFile This file provides mechanisms to be executed before any specs are executed, including Custom Commands.

As stated above, let's add an entry into our .gitignore file to make sure we've excluded directories containing media artifacts:

.gitignore

```
…

# Directory for Cypress test output
**/e2e/videos
**/e2e/screenshots

…
```

### Cypress Support Files and Custom Commands

Custom commands can be included in our Support File, which will execute before all tests are run.

First, we'll import our commands into our main Support File in order to enforce separation for readability and maintainability purposes.

tests/e2e/support/index.js

```
// This is run before any test files
// https://on.cypress.io/configuration

// Import custom test commands
import './commands';
```

Next, we can define our custom commands:

tests/e2e/support/commands.js

```
// https://on.cypress.io/custom-commands
Cypress.Commands.add(
'selectOption',
{ prevSubject: 'element' },
(subject, optionNumber = 0) => {
const dropdownComponent = Alkami.Iris.DropdownComponent.componentForElement(subject);

if (instance) {
dropdownComponent.value = dropdownComponent.options[0].value;
}
});
```
