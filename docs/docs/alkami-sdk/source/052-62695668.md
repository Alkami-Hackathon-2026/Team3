### Why has SiteText "Detected NULL key for sitetext with Default Value []"?

This is due to the database entry for the SiteText key being null. You can check this by running the below query, replacing the Namespace with your widget project, and investigating the "SiteTexts" column; fix any items that are formatted incorrectly.

```
SELECT SiteTexts FROM [AlkamiMaster].[sitetext].[Namespace] like 'Sample.Client.Widget.ChangeAddress'
```

### Why is my widget not displaying the latest widget setting values after they are update using the Widget Settings admin screen?

The values are stored in the database and have a 15 minute cache expiration. To see your updated settings in stage or production, do the following:

- Change the widget setting value in the admin portal
- Wait 15 minutes for the cache to expire
- Advise the member to logout and then log back in

You can quickly clear the Widget Setting cache when you are developing in your local environment by recycling the CoreService within the IIS Manager.

### How do I control my NuGet Package Sources

In Visual Studio pull down the Tools menu and selection Options.
Find NuGet Package Manager (about halfway down the top level list)
Select Package Sources
Check and uncheck the boxes as appropriate for the things you are going to work on.

For Alkami projects:

- Do not enable any public sources such as nuget.org, Microsoft Visual Studio Offline Packages, hack.com, etc.
- https://feeds.alkamitech.com/nuget/nuget.dev is generally used
- https://feeds.alkamitech.com/nuget/ThirdParty is generally used
- Oftentimes you will want a local directory such as c:\LocalPackageFeed for the nuget packages you create in your microservice projects so it is easy to load them into other Alkami projects.

For non-Alkami projects:

- Use whatever sources you want.
- https://api.nuget.org/v3/index.json is generally used
- C:\Program Files (x86)\Microsoft SDKs\NuGetPackages is generally used
- Usually you will want to turn off any Alkami sources

Note: you can have a separate nuget.config file in each project (or even in a group of projects under a common parent directory). Refer to https://docs.microsoft.com/en-us/nuget/reference/nuget-config-file (https://docs.microsoft.com/en-us/nuget/reference/nuget-config-file) for details on how to do this. You will probably want to make use of the packageSources section with a clear entry to override the machine-wide sources, then add in just the sources you want.

### Why am I getting the error "Make sure that the controller has a parameterless public constructor"?

This is due to the widget assembly not being loaded into the application resource pool. Most likely, there are additional libraries in the widget's Areas directory that were accidentally deployed during development in Visual Studio. The web client will attempt to load all the assemblies in the widget's Area/bin directory and will fail if a duplicate assembly is loaded causing the process to stop and not load the accompanying widget assembly. Make sure the "CopyLocal" reference properties for all library references are set to "False" within the Visual Studio properties dialog box.

### Does Alkami already have a widget named the same as my custom SDK widget? If so, what then?

The widget name and routing will always be prefixed with a unique identifier. The display names do not need to be unique and presents the possibility of duplicating a display name already created by Alkami. If the display name of a custom SDK widget must be the same name as one of Alkami's standard widgets, then we can assume the custom SDK widget is a direct replacement, at which time we can disable Alkami's standard widget and replace it with the custom SDK widget. If this isn't the case, and the custom widget and Alkami widget are both being used, then it is recommend the SDK widget's display name be updated to differentiate it from the existing standard widget.

### Why does my microservice crash when debugging in Visual Studio?

The two most common issues are when Visual Studio is not running with Administrator privileges or when the service is already running.

- Always make sure the "Alkami.Services.Subscription.Host" is running, unexpected behavior will happen if this is stopped.
- Always run microservice solutions as an Administrator in Visual Studio
- Always make sure the service you are trying to run from VS is not currently running. You can check this under the "Services" to see if the service has been registered and is in fact running. For example, if I wanted to work on the Settings Microservice, I'd have to stop it using the "Services" dialog before I could run it from source.
### How can I get a users email contact information?

```
using Alkami.Client.Services.Bank.Repository;
…
public virtual ICustomerRepository CustomerRepository { get; set; }
…
var user = CustomerRepository.Get();
var emailContact = user.GetUserContact(x => x.IsPrimary).FirstOrDefault() ?? user.GetUserContact().FirstOrDefault();
var emailAddress = emailContact.Email;
```

The first request will give you the value that they have marked as primary, and in the case that they don't have one marked as primary, the second will give a list of their email addresses.
We strive to ensure that everyone using online banking has at least one email due to registration and password concerns, so you may still want to check that value for null, as there is no absolute way to enforce that they have one.

### I was referencing a claims related class and now my widget is broken, what happened?

Do not fear! There is an easy solution.

The biggest source of issues will have to do with direct references to claims related classes or methods. In short, you should not be doing this. There is an existing layer of abstraction that provided by the Alkami.Client.Framework.Mvc.BaseController and Alkami.Security.Common.IClaimsUtility that you can reference to remove any rogue references you have to a claims signature class from your widget. The important part about these properties/methods is that they contain no claims types in their signature; value types only. This allows your widget to remain backwards compatible moving forward regardless of the changes made to the claims infrastructure.

### Can I add my own custom widget icons?

Yes!

To add an icon into the system, we would need a services ticket with the SVG icons attached, as well as the names those icons would be mapped to. ### Can I add my own custom fonts to a widget, even in the native mobile application?

### How does Alkami recommend we manage the workflow of updating widgets for breaking changes?

Alkami recommends starting with a thorough regression test against the latest SDK version relating to the components in question against. It may be easier to standup the VM as a dedicated test environment so this process is easily repeated. A broken widget will need to be updated, recompiled and assigned a new major version of the assembly and package.

For example,

The Awesome Widget v1.0.8 is found to be broken, once fixed it should then be Awesome Widget v2.0.0. The Awesome Widget is then submitted and goes through the standard code review process. Work with the Account Executive team to determine when the breaking version of ORB will be deployed. Once a date is decided, the client should coordinate with the SDK team to ensure the widget requires a special SLA relating to the dependent ORB release.

### Is there a procedure for hotfixes in the event that a widget needs to be updated after it has been modified for a breaking change, but before the breaking-change version can be deployed?

The best way is to manage through source control and versioning so that it is easy for the developer to revert to an older state in the event of a HotFix against an older version. If Awesome Widget v1.0.8 is in Production @ 2018.01, and Awesome Widget v2.0.0 is in Stage @2018.02, then a HotFix should be submitted as Awesome Widget v1.0.9 with special approval necessary to go directly to Production as a critical hot fix.

### How can I display my SiteText if it contains encoded html

If you want to include html within your SiteText values, you will need to encode the text so the html tags don't get confused with the xml tags. This means that a < character needs to be &lt; and > characters need to be &gt;

When you use Html.SiteText(..) to retrieve the text in your view the value will be proper decided for you. However, Razor will try to be helpful to you when it detects html tags and will encode the value again. To get around the problem use Html.Raw as shown below:

```
@Html.Raw(Html.SiteText("MyKey"))
```

### Do I need to create a microservice to implement a SingleSignOn?

It all depends what the "sso" is going to look like. For the following example, assume you will be SSOing to a Loan Application system.
#1 - If you are going to be using a traditional SIngleSignOn where confidential information is passed on a secured connection to the LoanApp system, then the LoanLoanApp system generates a session token, which the Alkami Widget will then use to open a pop-up or iFrame that uses the token: then Yes, you must use a microservice. The reason for this is that you can only make calls out to the Internet, or even to your data center from the app tier in the Alkami environment. Microservices run in the app tier and they can make that call. However, Widgets run in the web tier and are completely blocked by firewalls from directly accessing anything outside of the Alkami environment. In this scenario, trying to make the SSO work from the Widget will simply not work.

#2 - Alternatively, if all you are going to do is open a frame and can pass parameters such as the member's first name as a query string parameter for the frame src as a way to pre-populate a field in the LoanApp system, then you can certainly do the who thing in the Widget and a microservice is not needed.

If using approach #2, and you will be passing sensitive information such as SSN, then you will probably need something more secure than passing parameters in cleartext on the query string for the frame. Sometimes this is done by encrypting the confidential values, and then passing the encrypted value(s). A slightly better approach over the query string parameters is to load a form in the iFrame, and then use scripting to post the values to the LoanApp system. Doing this will usually leave less confidential data sitting in the browser cache. Whether you can do this for your project is going to be primarily a matter for your compliance people to determine.

For a project like an application system where a human will be validating information before the user has any access to get money out of the system, usually has lower security requirements. Or if the system you are SSOing into doesn't provide any way for a fraudster to get access to funds or PII, then #2 might be fine.

For a project like a billpay system where it is easy to get money from out of an account, #1 is the only acceptable approach. You much mild such a system such that even a developer with full access to the source code is unable to hack the system. Security a #1 approach is much easier.

### What are the possible values for the NativeDisplaySetting column in the core.FlavorWidget table?

This field is bit mask. Determine the value you need by a logical OR of the following values:

IosPhone = 0x01
IosTablet = 0x02
AndroidPhone = 0x04
AndroidTablet = 0x08

In most cases you would want to use 15 as the value, meaning that the Widget should be available for all 4 mobile device types.

If you wanted only IOS devices, then 3 is the proper value ( 0x01 || 0x02).

There is currently no way for you to directly control the value to be set in the Alkami stage and prod environments. You will need to work with your Alkami Client Success Analyst to arrange for professional services work to configure this setting.
