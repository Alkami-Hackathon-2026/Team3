Try Now allows admins to test StandardSSO configurations from within the admin site. It replicates the behavior of the SSO from the end users perspective without requiring you to VAU or ensure a test user has access to the proper widget. Using it, admins are able to iterate and troubleshoot much quicker.

## Access

Admin role must have Login As User (Full Access) permission (view only will not work)

The activity can be reached by opening a configuration and clicking the "Try Now" button:

The button will be disabled if user does not have Login As User (Full Access) permission:

## Usage
### User Selection

The first step is selecting a user to use for the SSO. Users can be searched for by:

- Name
- Username

Partial matching is supported without the need to add any wildcards to queries.

For example, for a user named "Doris Bowman" with the username "checkimage4", the search terms "bow" and "check" will both return the user.

Click the "Select User" button to choose the desired user.

#### User Selection Errors

After selecting a user, an error can be shown if the user does not meet the requirements for the SSO based on the configuration. These will be shown in a yellow toast message.

##### Possible errors:
- "User has no accounts eligible for this SSO"/"User has no cards eligible for this SSO" - Based on the configuration and filtering of accounts/cards, user doesn't have any accounts that can be used
- "User is missing email" - The configuration uses the email expression, but user does not have an email on file
- "User has insufficient permissions to access this SSO" - Business user is a sub-user and sub-users are not allowed OR missing role permissions
- "User is missing a user level extended property required for this SSO" - Missing user level extended property specified under UserConfiguration section
### Account/Card Selection (if applicable)

After user selection, the next step is to select an account or card to use for the SSO. This will only be required if the configuration being tested uses values that come from an account or card (as opposed to just user level values), such as the AccountNumber or CardNumber expressions. Otherwise, this step will be skipped.

The information shown in the dropdown matches exactly what the end user would see and is based on SelectionConfiguration section of the configuration (see Account Dropdown Customization (/spaces/SDKC/pages/556889803/Account+Dropdown+Customization))

### SSO Initiation

The DisplayMethod in the SSO configuration will control where the SSO is opened. Inline and NewWindow will work as expected. SameWindow will also be opened in a new window so as to not take the user out of admin.

### Other Errors

If you receieve the red error message, this indicates an issue either with your configuration or in the StandardSSO service.

#### Common Possible Causes
- Invalid configurationEnsure the json is valid
- Null values passed to operation expressionsFor example, if AddressLine2 is null here {{ Left(AddressLine2, 4) }}, an error will occurUse the Coalesce expression to handle this
- HTTP service in unsuccessfulIf an HTTP service returns a non-success code (e.g. 300 or above status code), an error will occur
