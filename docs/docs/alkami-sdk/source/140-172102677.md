## Obtain the OpenSSL tool

To follow the instructions on this page, you need the OpenSSL tool installed in your system. Some operating systems have it installed by default. For Windows, you must download and install it.

You can obtain a copy for Windows from https://slproweb.com/products/Win32OpenSSL.html (https://slproweb.com/products/Win32OpenSSL.html)

For our testing and this documentation, we used version 3.0.0.0 and installed the MSI. You can put the executables in the Windows directory or into a directory separate from Windows. The advantage of installing into the Windows directory is that they will be available all the time because the default path includes that directory. We chose to keep them separate to avoid putting extra files into the Windows directory.

See https://www.openssl.org/ (https://www.openssl.org/) for information about OpenSSL,

### Generate a certificate

When you installed OpenSSL, a program group will have been added to the Windows Start Menu. Locate the program group and launch the Win64 OpenSSL Command Prompt. This will open a command prompt and set the path to include the directory containing the OpenSSL executables.

Because Alkami will be acting as the IDp (Identity Provider), you need a full certificate that contains the private key (and the public key). This will be a two-step process

- Generate the keys. In our example we will set the certificate expiration to two years (730 days). Modify the parameters for the key type and size, and expiration to meet your needs and run the following command.
Run in your command prompt with a path to the OpenSSL tools

```
openssl req -new -newkey rsa:4096 -nodes -sha256 -keyout "C:\SSO\Alkami_SampleSso_signing_private_key.crt" -x509 -days 730 -out "C:\SSO\Alkami_SampleSso_signing_public_key.crt"
```

You will be prompted for various certificate properties. Here are the values we used in our sample. Alter them to meet your needs:

Country Name: US

State or Providence Name: TX

Locality Name: Plano

Organization Name: Alkami Technology

Organization Name: (left blank)

Common Name: developer.dev.alkamitech.com (http://developer.dev.alkamitech.com)

Email Address: (left blank)

This step will generate two files. One will contain the private key, and one will contain the public key as identified in the filename parameters on the command line.

You will provide the public key file to the SP (Service Provider) that is the destination of the SSO. The public key is used to validate the signature in the SAML assertion.

If this was a production certificate, you would want to carefully protect the private key file as anyone obtaining the private key could impersonate the IDp (Alkami in this care) and execute an SSO into your system.

2. Combine the key files into a certificate file. To install the certificate into Windows you need to combine these two key files into a full certificate file.

Run in your command prompt with a path to the OpenSSL tools

```
openssl pkcs12 -export -in C:\SSO\Alkami_SampleSso_signing_public_key.crt -inkey C:\SSO\Alkami_SampleSso_signing_private_key.crt -out C:\SSO\Alkami_SampleSso_Full_Certificate.pfx
```

To guard the private key that will be in this file you will be prompted to set a password for the file. Make up whatever password you wish to use and don't forget it. You will be required to enter the password twice.

## Install the certificate
- Open the Microsoft Management Console (MMC) which you can do by simply typing "mmc" into the Windows search bar.
- Pull down the File menu and select "Add/Remove Snap-in"
- Select "Certificates" and click the Add button in the middle of the screen, select the "Computer account" and click Next, then leave the default radio button selected for the "Local computer" and click Finish
- Click "OK" to complete the process of adding the Snap-in
- Expand the Certificates tree in the left panel, expand Personal, and then click on Certificates.
- Right-click on the Certificates folder and under All Tasks you will find Import. Click on Import.
- You will be installing into the Local Machine so click on Next.
- Enter the name of your full key file, or click on Browse to find it. If you browse you will need to change the file type selection to *.pfx, or to All Files, Click Next.
- Enter the password for the file. (this is the password you entered when combing the key files above).
- You may mark the key as exportable. This will make it possible to export the certificate from this machine and include the private key. This is optional but you should NOT do this when handling production keys on a machine unless the the machine is secured from access by users who should not have access to this private key.
- Allow the default location to place the certificate into the Personal store.
- Click on Finish.

Now that the certificate is in the certificate store it would be ready to use if it had been issued by a trusted Certificate Authority (CA). But because it is self-signed, we need to tell the computer that it can be trusted.

- Locate the certificate in the personal certificates folder.
- Right click on the certificate and copy it.
- In the left hand panel you will see a folder named "Trusted Root Certification Authorities". Right-click on that folder and paste the certificate.

There is one final step. The Alkami Standard SSO code will need to access the private key in this certificate.

- Locate the certificate in the personal certificates folder.
- Right click on the certificate and under All Tasks, select Manage Private Keys
- Add the "Users" group from the local computer into the list that has access to the key. (If this computer is on a domain, you will need to change the location to the computer rather than the domain when searching the the group named "Users."

## What about the "other" certificate

In many cases (most SAML implementations, for example), you will also need to install a second certificate. In the example above we installed the certificate such that the private key can be used in your SDK, typically for the purpose of signing a request being sent to a service provider. The other certificate is usually for the purpose of encrypting something that is in the request and in that case your requesting code will use the public key to encrypt, and the receiving side will use their private key to decrypt it. Because the private key is the sensitive value, the other party (the one who is receiving the SSO request is the one to create the keys and they will provide you with a certificate file that only contains a public key. In this case you simply import the certificate file as follows:

- Open the Microsoft Management Console (MMC) which you can do by simply typing "mmc" into the Windows search bar.
- Pull down the File menu and select "Add/Remove Snap-in"
- Select "Certificates" and click the Add button in the middle of the screen, select the "Computer account" and click Next, then leave the default radio button selected for the "Local computer" and click Finish
- Click "OK" to complete the process of adding the Snap-in
- Expand the Certificates tree in the left panel, expand Personal, and then click on Certificates.
- Right-click on the Certificates folder and under All Tasks you will find Import. Click on Import.
- You will be installing into the Local Machine so click on Next.
- Enter the name of the certificate file, or click on Browse to find it. If you browse you will typically be looking for a *.crt file. Click Next.
- Note: there should not be a password for the file because there is nothing sensitive in the file..
- Allow the default location to place the certificate into the Personal store.
- Click on Finish.

Now that the certificate is in the certificate store it would be ready to use if it had been issued by a trusted Certificate Authority (CA). But because it is self-signed, we need to tell the computer that it can be trusted.

- Locate the certificate in the personal certificates folder.
- Right click on the certificate and copy it.
- In the left hand panel you will see a folder named "Trusted People". Right-click on that folder and pasted the certificate.

Note: nothing needs to be done regarding permissions for this certificate.

## How do I use the certificate

Usually, the way you will identify the certificate your SSO code will use if by the "thumbprint" of the certificate. That is the way the Alkami Standard SSO system works. (Although it is also possible to identify a certificate by its issuer, friendly name, other various other properties on the certificate.)

To find the thumbprint simple use the certificate manager in MMC and browse to the certificate in the Personal or Trusted People folder and right-click on the certificate. Click on the Details tab and scroll down through the list of properties on the certificate and you will find a field named Thumbprint. Click on the Thumbprint field and you can copy the value from the textbox beneath the list of fields.
