Throughout this documentation there are a few terms that are unique to the Albus ecosystem.

#### Albus-CLI

The albus-cli is the interface that is exposed to interact with Albus through the command line. It has a plethora of options and modifiers that can be applied in addition to the core set of commands (e.g., init, build, deploy, watch, test). This is a requirement in virtually every project that leverages Albus.

To see the available commands and options, check out the CLI reference (/spaces/SDKC/pages/303531404/Albus+CLI+Commands) page.

#### Plugins

In the Albus ecosystem, plugins are encapsulated pieces of functionality that perform a specific action. For instance, there is a sass plugin that the albus-preset-sass uses that takes care of the actual compilation of SCSS files.

#### Presets

Akin to plugins, presets are groups of functionality that are tailored to a specific use case. Each preset comes with exposed methods that are able to be invoked by the Albus CLI and executes one or more tasks. A primary example of this is the albus-preset-legacy that transpiles TypeScript, compiles SCSS files, and minifies JavaScript and CSS.

To see all available presets, head over to the presets (/spaces/SDKC/pages/303531412/Presets) page.
