### Generic Proxy Microservice

The Generic Proxy Microservice is an Alkami developed and supported service that allows working with a secure web service or web page when you don't want or need a create a new microservice.

Documentation on working with the Generic Proxy service is located here (https://confluence.alkami.com/display/SDKC/Working+with+the+Generic+Proxy+Microservice?src=contextnavpagetreemode).

### Slim Microservice

This "Slim" microservice has the minimum components necessary to create a self contained service and client proxy.

### Provider Microservice

Provider based services allow developers to define configurable settings for use within the service implementation. The settings can be managed from Alkami's Admin Portal under the "Setup" menu's "Integration Settings->Providers." These settings need to be defined within the service using C# code. The developers are responsible for equipping the service with these configurable settings. When the settings are implemented within the service, then admin users can manage those settings without requiring code changes.

Documentation on setting up your first provider service is located here (https://confluence.alkami.com/display/SDKC/My+First+Provider+Service?src=contextnavpagetreemode).

### Logic Microservice

This project enables developers to create and setup a new service which can be used on the Alkami platform for easier maintenance and delivery. The logic type microservice specifically does not use persistent data storage. Settings can be added during development (however if you are going to add settings you should probably use the Provider Microservice template for your project).

### SSO Microservice

This Generic SSO Host project has all the method implementations necessary to stand up a custom SSO service using Alkami's standard contracts and data objects.

Documentation on setting up your first SSO service is located here (https://confluence.alkami.com/display/SDKC/My+First+SSO+Provider).

### Quick Apply

The Quick Apply widget is a single source for all product acquisition interfaces in Alkami's platform. The widget can communicate with a microservice built by using the Quick Apply microservice template to get lists of available products and product options.

Documentation on working with Quick Apply is located here (https://confluence.alkami.com/display/SDKC/Working+with+Quick+Apply?src=contextnavpagetreemode).

### Card Management

This project enables developers to create the Card Management Provider Microservice implementing the interface ICardManagementProviderContract, which provides methods for managing a specific FI's user's cards.

### Check Imaging

A Check Image is the digital picture of the front side and backside of a paper check. An image is captured when a check is deposited and can be viewed as part of the details related to the transaction. These images are hosted outside of Alkami's systems and need to be linked to or downloaded and then rendered in the browser for the member to view. Alkami's SDK offers the ability to create a custom check imaging microservice to manage the retrieval of those images from an external data source.

Documentation on working with Check Imaging is located here (https://confluence.alkami.com/display/SDKC/Working+with+Check+Imaging?src=contextnavpagetreemode).

### Facts

This microservice project template will make it possible for you to add new "facts" that ca be used to drive package assignment rules, and in other places that may use the Alkami rules engine. A microservice you create using this template will contracts and data objects that are defined by Alkami.
