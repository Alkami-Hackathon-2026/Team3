The Alkami native apps rely on oAuth for session authentication and authorization. The permissions that the session will have is a combination of what the device type is permitted to access, and what the end user has permissions to access.

Note: At the current time, the native apps cannot be used to connect to a "stage-match" site. You will need to connect to the developer.dev.alkamitech.com (http://developer.dev.alkamitech.com) site. The good news is that you will not need to do anything with the RegisteredApplications in the database. It is probably best to use the app from https://dl.alkami.com/dev (https://dl.alkami.com/dev) and use these values in the app for the connection

### Step 1 - Make your plan

This may sound obvious, but it is a step you cannot skip. You need to know what system you want to connect to, and how you are going to make the network connectivity work. For this page of instructions, we are going to focus on connecting to your local SDK development environment.

### Step 2 - Obtain your device

Because you will be connecting to a development environment and that environment is most likely going to be connected to your financial institutions's internal network, you should not be using a personal mobile device that you use in the outside world. If your organization does allow BYOD (bring your own device), then you should still make sure you have explicit permissions from your organization to use it for this testing. The best practice will be to use a device that is dedicated for this type of testing and does not have additional software installed on it besides the minimum needed to do this testing.

### Step 3 - Get the app

Make sure you know which native app you want to use. The production version of the apps can be downloaded from https://dl.alkami.com/release (https://dl.alkami.com/release), however the production apps will only connect to the production Alkami system. For some testing, that might be exactly what you need. But if you want to connect to your SDK it is not going to work because the url is burned into the app.

A "development" version or the apps can be downloaded from https://dl.alkami.com/dev (https://dl.alkami.com/dev) and these apps will allow you to enter the url you are going to connect to. (You can select the DevSdk copy of the app for testing to the basic SDK site.)

### Step 4 - Resolve connectivity issues

For these instructions we are going to assume you're connecting to an SDK environment that is within your organization's internal network. Does your organization have a Wi-Fi that you can connect to and that is able to reach your SDK machine? If you do not have that, then you will need to either hardwire the device to your network (use a usb-to-ethernet adapter), or use some sort of proxy solution (such as Charles Proxy).

Figure out what the default webpage is in your SDK. Most likely you will use a browser on your SDK and go to http://127.0.0.1 (http://127.0.0.1) and will see one of these:

Note that at this point we are using http (not https) and that is because the certificate name will not match 127.0.0.1 and we will get a certificate error if we try to use https. If neither of these pages does come up, you need to figure out why and resolve it. Perhaps you have deleted the http binding from the default website?

Now, figure out what the IP address is for your SDK machine (you can use the "ipconfig" command from a cmd prompt). Try the same test to reach the default web page. If your ip address is 192.168.1.100, then simple use http://192.168.1.100 (http://192.168.1.100) and make sure you get a webpage displayed.

Now, try the same url from your mobile device. In our example that means going to http://192.168.1.100 (http://192.168.1.100) If you get the expected default webpage like you got with the desktop browser then you need to figure out why and resolve it. (most likely your Wi-Fi connection does not have network connectivity to your SDK.)

### Step 4 - Resolve name resolution issues

(Step 3 was only used to make sure you have basic connectivity before things start to get trickier.)

Determine the url you use to connect to your SDK WebClient site. For the basic SDK, that is https://developer.dev.alkamitech.com (https://developer.dev.alkamitech.com) If you have a stage-match site then you will have a different url. For example, it might be something like https://usbfi.dev.alkamitech.com (https://usbfi.dev.alkamitech.com)

There are several ways to accomplish the name resolution task. Pick one of the following that will work for you, or come up with a strategy that will work for you based on your experience, and access to network configuration settings. It is recommended that we first start with the basic SDK site https://developer.dev.alkamitech.com (https://developer.dev.alkamitech.com) , but you will end up doing the same things in the remaining steps for your stage-match site.

- Have your networking department add a DNS entry in your internal network DNS server pointing the url to the IP address you determined in step 3

### Step 6- Adding the "Registered Application"

If you are using the DevSdk app and connecting to the developer.dev.alkamitech site, then you can skip this step as there is already a registered application in the database for this purpose.

To use a FI native app to test hitting your SDK, you need to add a row to the dbo.RegisteredApplications table using the proper client key and secret.

Open an SDK Support incident and request your "Client Key" and "Secret" for your native apps.

(Note: for Alkamists: we can lookup the values in https://bitbucket.corp.alkami.net/projects/IOSDEV/repos/fastlane/browse (https://bitbucket.corp.alkami.net/projects/IOSDEV/repos/fastlane/browse) )

On your SDK machine, use the browser to login to the admin site. Under the Setup menu you will find "Registered Applications."

You will see this screen. Add a new application and setup it up with the same permissions as the IOS_ORB application, except use your Client Key and Secret. Don't forget to select the Application scopes (you can just select all of them).

The following script may also be useful in adding the values.

```
Declare @Your_CLIENT_KEY as uniqueidentifier
Declare @Your_CLIENT_SECRET as uniqueidentifier
Set @Your_CLIENT_KEY='00000000-0000-0000-0000-YourClientKey'
Set @Your_CLIENT_SECRET='00000000-0000-0000-0000-YourClientSecret'

---- Make no changes below this point

Declare @DevSdk_CLIENT_KEY as uniqueidentifier
Declare @DevSdk_CLIENT_SECRET as uniqueidentifier
Set @DevSdk_CLIENT_KEY='CBA61EA9-DFA1-495E-AE8A-3191A8E28B03'
Set @DevSdk_CLIENT_SECRET='0C8730BB-3F3E-4261-B4E2-1452A844CDE3'

if (@Your_CLIENT_KEY = @DevSdk_CLIENT_KEY or @Your_CLIENT_SECRET = @DevSdk_CLIENT_SECRET)
Begin
print 'Your client key and secret must be unique. They cannot match the DevSdk values.'
print 'Update was NOT successful'
return
end

if EXISTS (Select * from [RegisteredApplications] where ClientKey = @Your_CLIENT_KEY and ClientSecret = @Your_CLIENT_SECRET)
Begin
print 'Your client key and secret are already in the RegisteredApplications table.'
print 'Update was NOT successful'
return
end

if NOT EXISTS (Select * from [RegisteredApplications] where ClientKey = @DevSdk_CLIENT_KEY and ClientSecret = @DevSdk_CLIENT_SECRET)
Begin
print 'The devSdk record is missing from the RegisteredApplications table.'
print 'Update was NOT successful'
return
end

insert into RegisteredApplications
SELECT TOP (1)
@Your_CLIENT_KEY as [ClientKey]
,@Your_CLIENT_SECRET as [ClientSecret]
,[Name] ,[Description] ,[FirstUseUtc] ,[IsFullyTrusted] ,[IsEnabled]
,[LogoBytes] ,[TokenLifespan] ,[RefreshEnabled] ,[IsAbsoluteTime]
,[RedirectUris] ,[CreateDate] ,[LogoImageId] ,[RefreshTokenDays]
,[LastUpdate] ,[Settings] ,[ServiceAdminUserID]
FROM [RegisteredApplications]
where [ClientKey] = @DevSdk_CLIENT_KEY and [ClientSecret] = @DevSdk_CLIENT_SECRET

print 'Script finished'
```

### Step 8- Instruct the app to connect to the correct url

Do a fresh launch of the native app. (if it is already running, you must close the app and then open it again.

Touch (or click) on the splash screen in the native app 5 times and you will be presented with a screen where you can enter the url, and key and secret to use.

After properly filling out the screen, you can continue and you should be presented with a login screen. Simply login and you are all ready to complete your testing.
