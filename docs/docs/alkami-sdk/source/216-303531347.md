This component is not where we want it to be in terms of quality and ease of use to work with it. We have some exciting things coming soon that will resolve a number of the challenges in working with it!

The mobile titlebar is the component at the top of each page in our application that allows a user to interact with certain global and widget specific actions (e.g., opening the navigation drawer, updating a transfer). This is one of the most challenging components in our system since it has to be able to be displayed in web as well as native, but the configuration from JavaScript has to remain the same. To get started, let's look at an overview of this component on each of the platforms.

### Titlebar Overview

When viewing a web-based mobile widget in a web browser, the titlebar that is shown is built from HTML which is specified in the CSHTML file that is rendered (see below section for more details). When that same widget is displayed in the native application, the HTML titlebar is hidden and the native titlebar is shown. Because of this difference in implementation, there will be some visual differences between the platforms.

Figure 1: Widget displayed on web and native

As you can see from the image above, while the widget itself displays identically, the titlebar has some platform specific differences. Let's walk through each platform in depth to understand how to work with the titlebar and how to normalize these differences as much as possible.

### HTML Titlebar

While the native titlebar is automatically added by default in the native application, a widget needs to manually specifiy the titlebar for a web view. This is done by using a custom section named Header and is what gets rendered when the widget is displayed in a non-native environment. Here is an example of an HTML titlebar code:

index.cshtml

```
@section Header {
<div class="titlebar">
<!-- Left side buttons -->
<a class="titlebar-button left" href="#">Nav</a>
<a class="titlebar-button left icon back hidden" href="#"></a>
<a class="titlebar-button left hidden" href="#">Cancel</a>

<!-- Title -->
<h1 id="page_title" class="truncate">ACH</h1>

<!-- Right side buttons -->
<a class="titlebar-button right hidden" href="#">Done</a>
</div>
}
```

To reiterate, this section is only rendered in a widget displayed in a non-native environment. Additonally, the toggling of the hidden classes to show or hide the buttons must be handled by the widget itself and managed throughout the experience.

##### Important Notes:
- Buttons to be used in the titlebar must be present on page load or added programatically via JS
- The titlebar button must always have a class of titlebar-button
- The button shown is driven by the element's class with a number of customizations available:Alignment - choose to display the button on the left or rightIcon - if an icon is desired, add the icon class and choose one of the supported icons (back, home, nav)If no icon is specified, the navigation (hamburger) icon will be used as defaultText - if the icon class is not added, the text inside of the button will be used instead
- The titlebar must be placed inside of an h1 tagA class of truncate is recommended in case the title overflows on smaller screen devices

#### Titlebar Height

Another important item to call out is the way that the global application's CSS is built in order to handle the variation in titlebar. To understand this nuance more clearly, let's look at the actual web area in a widget, when displayed in a browser vs a native device:

Figure 2: Web content in a browser vs native device (web areas are outlined in red)

Because the beginning of the widget content can start at the top of the viewport (e.g., in a web browser) or from the bottom of the titlebar (e.g., in the native application), the application's global CSS needs to account for this. The way we handle this is to add a body class .native-menu when the view is displaying inside of a native app and can change the page margin accordingly. Since the web titlebar is 45px tall and we always want a 20px margin between the titlebar and widget content, we add a 65px margin on web based content and 20px on native content. Here are the CSS rules that control this:

```
#wrapper div#content {
margin-top: 65px !important;

.flush-with-titlebar {
margin-top: -20px;
}
}

&.native-menu {
#wrapper div#content {
margin-top: 20px !important;

.flush-with-titlebar {
margin-top: -20px;
}
}
}
```

Another item of note is the .flush-with-titlebar class which removes that margin and makes it so that the widget content is flush with the bottom of the titlebar. Use this to negate that extra margin on a widget view.

### Native Titlebar

Now that we've gone through the HTML version of the titlebar, let's dive into the native portion. Since the titlebar in our application is controlled by platform specific code, we leverage a JavaScript bridge to serialize a config object and pass it to a native function that updates the titlebar for us. To make using this functionality easier, we have created an adapter library that takes care of passing these values to the native device. It is stored under the window.nativeHook object that is globally accessible to any JavaScript running in our application.

In order to ensure the titlebar is set correctly on page load, the setNavBar method needs to be invoked on page load. This can either be accomplished in the widget JS file, or added as an inline script in the mobile view.

Inline Script (index.cshtml)

```
@section BodyScripts {
<script>
window.nativeHook.setNavBar({
text: 'Disclosure',
left: { button: 'back', callback: 'window.location.href = "\Mobile\Disclosures"' },
right: { button: 'custom', text: 'Agree', callback: '$("form#mobile_disclosure").submit()' }
});
</script>
}
```

widget.js

```
// ...
window.nativeHook.setNavBar({
text: 'Disclosure',
left: { button: 'back', callback: 'window.location.href = "\Mobile\Disclosures"' },
right: { button: 'custom', text: 'Agree', callback: '$("form#mobile_disclosure").submit()' }
});
// ...
```

After the titlebar has been set the first time, use the updateNavBar method for all subsequent updates.

```
window.nativeHook.updateNavBar({
text: 'Widget Title',
left: { button: 'drawer' }
});
```

The same options that were available in the HTML titlebar are also available in the native adapter library (e.g., using icons or text for buttons). Here is the interface for the options object to pass into this method:

Titlebar Options (ITitlebarOptions)

```
interface ITitlebarOptions {
left?: ITitlebarButton; // button that will be on the left of the native titlebar (usually drawer or back)
right?: ITitlebarButton; // button that will be on the right of the native titlebar
text: string; // title that will be shown in the native titlebar
}

interface ITitlebarButton {
button: string; // 'back' | 'custom' | 'drawer' | 'home'
text?: string; // If 'custom' button specified, use this text instead of an icon
callback?: string; // String containing JS that will be invoked with eval()
}
```

#### Native Titlebar API

In addition to methods to set and update the native titlebar, there are additional methods to provided to get context on the device a widget's JS is being execute in. Each of these methods are available on the window.nativeHook global JavaScript namespace.

#### isAndroid()

Tests the user agent of the callng client to see if it is an Android Device.

Returns

- (Boolean): Returns a boolean indicating if the calling client is an Android device.

Example

```
if (window.nativeHook.isAndroid()) {
version = parseFloat(userAgent.match(/Android (\d+\.\d+)/i)[1]);
isMobileUnsupported = version < 5.0;
}
```

#### isNativeApp()

Tests the user agent of the callng client to see if it has the nativeapp custom suffix.

Returns

- (Boolean): Returns a boolean indicating if the calling client is the native application.

Example

```
if (window.nativeHook.isNativeApp()) {
window.open(data.SsoUri, "_self");
} else {
window.open(data.SsoUri, "_blank");
}
```

#### isNativeAppWithNativeMenu()

Tests the user agent of the callng client to see if it has the nativemenu custom suffix.

NOTE: This will always be the same as isNativeApp()

Returns

- (Boolean): Returns a boolean indicating if the calling client is the native application with the native menu active.

Example

```
if (window.nativeHook.isNativeAppWithNativeMenu()) {
const titlebarMethod = this.firstUpdate ?
window.nativeHook.setNavBar :
window.nativeHook.updateNavBar;

titlebarMethod(this.titlebarConfig);
}
```

#### getNavBar()

Method that returns the internally stored copy of the titlebar configuration.

Returns

- (Object): navBarJson object (ITitlebarOptions)

Example

```
const titlebarConfigObject = window.nativeHook.getNavBar();
```

#### getNavBarString()

Method that returns the internally stored copy of the titlebar configuration in string format.

Returns

- (String): navBarJson object stringified

Example

```
const currentTitlebarConfiguration = window.nativeHook.getNavBarString();
const titlebarConfigObject = JSON.parse(currentTitlebarConfiguration);
```

#### setNavBar(navBarJson)

Method used to set the initial configuration of the titlebar.

Arguments

- navBarJson (ITitlebarOptions object)

Returns

- (void): Returns void

Example

```
window.nativeHook.setNavBar({
text: 'Widget Title',
left: { button: 'drawer' }
});
```

#### updateNavBar(navBarJson)

Arguments

- navBarJson (ITitlebarOptions object)

Returns

- (void): Returns void

Example

```
window.nativeHook.updateNavBar({
text: 'Widget Title',
left: { button: 'custom', text: 'Save' }
});
```
