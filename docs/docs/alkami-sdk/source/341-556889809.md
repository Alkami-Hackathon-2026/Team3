### Overview

Account Looping lets a Standard SSO configuration build per-account key/value outputs at runtime, then reuse those outputs in requests (HTTP or SAML) or concatenate them into a single string.

This is most useful when a provider needs:

- One field per account (for example account_0, account_1, account_2).
- A single joined string of all account values (for example ACC1,ACC2,ACC3).
### What Is Supported
| Capability | Supported | Notes |
| AccountLoop to HTTP query params | Yes | Loop results are appended to configured query parameter names. |
| AccountLoop to HTTP form fields | Yes | Loop results are appended to configured form field names. |
| AccountLoop to SAML attributes | Yes | Loop results are appended as unique attributes. |
| AccountLoop expression with delimiter | Yes | Supports AccountLoop(key, delimiter) and joins values with the delimiter. |
| AccountLoop key lookup behavior | Yes | Key matching is case-insensitive; null-valued items are skipped. |
### Runtime Behavior (How It Works)
- Engine loads and validates configuration.
- During account-selection processing, if AccountLoop entries exist, each loop runs across available accountsMeaning you will not see an account selection
- For each account:OptionIdentifier is set to that account.ValueTemplate expressions are generated and evaluated.Key and value are materialized, with <<index>> replacement.
- Results are stored in EvaluationContext.AccountLoopValues keyed by AccountLoop.Key.
- Later request-population logic consumes those values in any configured target.
### Configuration Model
#### AccountLoop object
- Key: Loop name used by consumers (for example SamlAccountLoop).
- KeyTemplate: Per-item key template. Usually includes <<index>>.
- ValueTemplate: Expression to evaluate per account.
#### Consumer fields
- HttpRequest.AccountLoopQueryParameters
- HttpRequest.AccountLoopFormFields
- SamlRequest.AccountLoop
- AccountLoop(loopKey, optionalDelimiter) expression anywhere expression syntax is allowed
### Walkthrough: Configure Account Looping
- Add AccountLoop array to configuration.
- Add one or more loop definitions.
- Pick at least one consumer path:Query paramsForm fieldsSAML attributesAccountLoop expression concatenation
- Validate with a user who has 2+ eligible accounts.
- Confirm generated payload includes expected keys/values.
### Example A: Per-account payload as HTTP form fields

This is your first pattern: generate XML fragments per account and append as form fields via AccountLoopFormFields.

AccountLoopExample

```
{
"BankIdentifier": "f08d74db-4a36-4e32-b0bc-ca40eee09520",
"ProviderName": "AccountLoopTest",
"Description": "AccountLoopTest",
"AccountLoop": [
{
"Key": "SamlAccountLoop",
"KeyTemplate": "account_<<index>>",
"ValueTemplate": "{{ Append('<Account><ACCOUNT_NAME>', AccountDisplayName, '</ACCOUNT_NAME>', '<ACCOUNT_ID>', AccountNumber, '</ACCOUNT_ID>', '<SHARE_ID> TODO </SHARE_ID>', '<ACCOUNT_TYPE>', CoreName, '</ACCOUNT_TYPE>', '<ACCOUNT_RELATIONSHIP>', Relationship, '</ACCOUNT_RELATIONSHIP></Account>') }}"
}
],
"HttpRequest": {
"DisplayLocation": "NewWindow",
"Uri": "https://www.Alkami.com",
"Method": "Post",
"ContentType": "application/x-www-form-urlencoded",
"FormFields": {
"Account": "{{ AccountHolder }}"
},
"AccountLoopFormFields": "SamlAccountLoop"
}
}
```

Expected shape:

- Existing FormFields remain.
- Additional fields are appended, such as account_0, account_1, account_2.

### Important Caveats
- AccountLoop generation is tied to account-selection flow and is intended for account-based scenarios.
- If a configured consumer key does not exist in AccountLoopValues, append is skipped silently for query/form/SAML-attribute attachment.
- AccountLoop expression lookup failure can cause runtime evaluation failure (reported as a GeneralError).
- Duplicate loop keys overwrite earlier loop outputs in the in-memory dictionary.
### Practical Recommendations
- Keep Key values unique across AccountLoop entries.
- Always include <<index>> in KeyTemplate when appending as key/value fields.
- Use AccountConfiguration filters to keep loop output deterministic and limited.
- Use a delimiter in AccountLoop expression when target expects a list-like string.
- Validate with at least 2 eligible accounts in lower environments before promoting.
