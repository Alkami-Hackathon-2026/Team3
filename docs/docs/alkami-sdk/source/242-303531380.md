When it comes to the mock data in the "tests" folder, it follows the same pattern as the interfaces folder (one file per export). Each file is named based on its contents and exports a single mock data object that can be imported easily into tests.

What data to include?

The best pattern I have found when mocking data that come from API responses is to include the entire response instead of just the data you care about. This makes it easy to test both the API layer as well as a component that uses a subset of the data if you have the entire response stored.

import { shallowMount } from '@vue/test-utils';
import RepositoryRecord from '@/components/project/RepositoryRecord.vue';

// Import the mock files here
import { projectRefs } from '../../data/projectRefs';
import { executions } from '../../data/executions';

// And reference them in your test file where needed
const repositoryInfo = projectRefs.projects[0];
const storeMock = {

'31DAE330A77807FA058B7867E3BD02307539FF2E': [executions.executions[0]],
},
},
},
};

// Then execute your tests as normal
describe('RepositoryRecord.vue', () => {

const wrapper = shallowMount(RepositoryRecord, {

},

});
});
